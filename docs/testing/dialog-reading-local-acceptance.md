# 对话阅读布局本地验收

在包含至少三个 Skill 角色的测试会话中发送一个会产生长回复的问题。仅观察和记录，不修改数据或代码。

1. 检查顶部角色卡保持原样；收缩后正文空间增加，重新展开及重启 APP 后状态保持。关闭联网后，输入区不出现独立的搜索状态行；工具面板仍可开启联网。
2. 检查同一用户问题只出现一个回答区域。左右滑动、左右按钮均能切换角色；姓名、页码和其他角色新回复提示清晰，角色回复的先后完成不改变页面顺序。
3. 检查短回复完整显示。长回复预览可展开，正文使用较宽区域；展开角色甲后切换角色乙再返回，角色甲仍保持展开。
4. 将角色甲长回复滑到中段，切到短回复再返回，核对阅读位置。收起长回复后确认仍停留在该回答附近，未跳到下一条问题。
5. 离开会话、重启 APP 后，核对当前角色页、展开状态和会话阅读位置；新增或移除会话角色后，旧问题的回答顺序不改变。
6. 生成中切换角色，停止或重试单个失败回复，确认已完成的其他回答仍可读，页面不自行切换或强制滚到底部。
7. 显式发起交叉讨论，确认回复按发言时间顺序展示。再测试定向回复，确认分页阅读不会改变下一条消息的回复对象。
8. 检查 Markdown、代码块、表格、链接、复制、保存成果和文本选择；再在大字体、窄窗口及键盘弹出时核对可读性。

记录每项的 PASS、FAIL 或 BLOCKED，并附设备型号、Android 版本、APP 构建版本及可复现步骤。历史会话没有明确提问关联的回复应保持原有时序，不应被误合并。
