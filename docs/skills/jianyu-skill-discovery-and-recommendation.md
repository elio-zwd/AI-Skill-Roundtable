# 见域 Skill 发现与推荐模型

> 状态：PR08-C 规格草案。本文定义目标产品的发现与推荐规则，不代表当前 Android App 已实现推荐引擎、收藏、最近使用或多维筛选。
>
> 关联文档：[Skill 分类模型](./jianyu-skill-taxonomy.md)；[官方候选映射](./jianyu-skill-catalog-mapping.md)。

## 1. 结论

见域采用“**问题优先、候选可解释、用户确认、阵容去重、观点多样**”的推荐模型：

```text
用户表达问题
→ 识别目标、约束、风险、时效、资料和输出
→ 生成单 Skill / 多 Skill 候选
→ 过滤不可用、许可未通过或能力边界不匹配项
→ 检查能力重复与观点多样性
→ 展示推荐理由、所需资料和风险
→ 用户增删、替换或确认
→ 才开始单 Skill 或多 Skill 协作
```

系统不得自动邀请 Skill、自动开始圆桌、自动上传材料或把人物名气当作可靠性评分。

## 2. 发现入口

### 2.1 问题推荐

首页先允许用户直接描述问题。系统根据问题推荐候选，但不要求用户先理解 Skill 类型或选择分类。

推荐前至少识别：

- 用户要解决什么；
- 希望思维拓展、现实支持或两者兼有；
- 是一次任务还是持续议题；
- 需要何种输入与输出；
- 是否依赖当前信息或联网；
- 是否涉及隐私、法律、医疗、金融、心理危机或其他高风险；
- 单 Skill 是否足够；
- 是否需要反方、核查或工作流能力。

识别结果只是候选生成依据，不自动保存为长期个人背景。

### 2.2 分类浏览

分类浏览先展示四类主类型，再允许按领域和场景继续缩小范围。界面不得把 44 个候选平铺成一个无层次名人列表。

每张卡至少显示：

- 名称和主类型；
- 一句话能力说明；
- 现实支持/思维拓展；
- 适合单 Skill、多 Skill或两者皆可；
- 联网和资料要求；
- 风险或能力限制；
- 当前接入、候选或暂缓状态。

### 2.3 搜索

搜索应覆盖：

- 正式名称；
- 常见别名和中英文名；
- 能力描述；
- 领域、场景、输入和输出标签；
- 用户自然语言，例如“帮我拆老板任务”“检查合同遗漏”“找反方意见”。

搜索排序不能只依赖人物姓名热度。名称精确匹配只提高可发现性，不提高专业可靠性。

### 2.4 筛选

V1 目标筛选项：

- 主类型；
- 现实支持/思维拓展；
- 领域；
- 场景；
- 单 Skill/多 Skill；
- 是否需要联网；
- 是否需要资料；
- 风险等级；
- 当前可用/候选/暂缓。

筛选用于缩小候选，不改变 Skill 本身的风险和能力边界。

### 2.5 最近使用和收藏

- 最近使用按用户真实启动记录产生，不因系统推荐自动增加。
- 收藏由用户主动操作，可取消。
- 收藏和最近使用提高个人可访问性，不提高全局可靠性评分。
- 高风险、许可证未核验或暂缓项不能因为被收藏而绕过接入门禁。
- V1 本地保存，不暗示账号同步。

## 3. 推荐阶段

### 3.1 硬性门禁

出现以下任一情况时，候选不得进入“可直接开始”集合：

- `license_pending` 且需要复制或发布第三方内容；
- `excluded`；
- 需要 Android 当前不具备的桌面执行能力；
- 与问题风险等级不匹配；
- 必要资料缺失且无法通过澄清补足；
- 必须联网但当前无法核验；
- 真实人物模拟缺少非本人声明；
- 高风险能力缺少来源、时效、边界或人工复核提示。

暂缓候选可以在研究或详情中显示，但必须清楚标记“当前不可开始”和原因。

### 3.2 候选匹配维度

推荐可以综合以下维度，但 PR08-C 不冻结具体权重或算法：

| 维度 | 判断问题 |
|---|---|
| 目标匹配 | 是否直接帮助当前问题和阶段目标 |
| 类型匹配 | 人物视角、顾问、助手或工作流是否合适 |
| 输入匹配 | 用户已有材料是否满足最低输入 |
| 输出匹配 | 能否产生用户需要的结果形式 |
| 时效匹配 | 是否需要当前信息，能否核验 |
| 风险匹配 | 是否具备相应边界和复核机制 |
| 模式匹配 | 单 Skill 是否足够，是否需要多 Skill |
| 协作增益 | 加入后是否提供新的领域、立场或步骤 |
| 重复惩罚 | 是否与已选 Skill 能力高度重复 |
| 可用性 | 是否已接入、许可通过且移动端可用 |

不得把点击量、知名度、财富、职位或模型对人物的熟悉程度当作专业可靠性。

### 3.3 推荐理由契约

每个候选必须提供可读理由，至少回答：

1. **为什么适合**：与用户问题的具体匹配点。
2. **负责什么**：在本议题或阵容中的明确职责。
3. **需要什么**：需要用户补充的资料、日期或约束。
4. **产生什么**：预期输出。
5. **有什么限制**：风险、时效、联网和非本人声明。
6. **为什么不是其他候选**：存在明显重叠时说明取舍。

禁止使用“最强”“最权威”“一定适合”等无法核验的营销语言。

## 4. 单 Skill 推荐

优先推荐单 Skill 的情况：

- 目标和交付物清楚；
- 风险可由一个受控能力覆盖；
- 不需要明显的跨领域判断；
- 用户希望快速完成一次任务；
- 多 Skill 只会增加重复和成本。

单 Skill 推荐仍可提示可选补充能力，例如：

- 加入核查能力；
- 加入反方视角；
- 加入成果整理工作流。

补充能力只有用户确认后才加入。

## 5. 多 Skill 推荐

多 Skill 适用于：

- 复杂决策或长期议题；
- 同时需要现实支持和思维拓展；
- 需要不同领域、立场或证据来源；
- 需要“分析—核查—成果”多个步骤；
- 高风险问题需要专业边界与现实复核；
- 用户明确希望圆桌协作。

推荐阵容应尽量覆盖不同职责，而不是堆叠相似人物。

建议的职责结构：

```text
主负责：直接解决核心问题
补充者：提供不同领域或执行步骤
挑战者：反方、失败条件或关键假设
核查者：来源、事实与时效
整合者：共识、分歧、条件、建议和下一步
```

一个 Skill 可以承担多个职责，但系统必须说明。多 Skill 默认分别独立回应；交叉讨论仍需用户显式触发。

## 6. 阵容重复检查

### 6.1 能力重复

以下组合容易高度重叠，应触发提醒而不是禁止：

- 创业与产品人物：埃隆·马斯克、史蒂夫·乔布斯、张一鸣、保罗·格雷厄姆、蒂姆·库克、段永平；
- 投资与风险人物：查理·芒格、纳西姆·塔勒布、纳瓦尔、孙宇晨、赵长鹏；
- 内容与增长：MrBeast、X 增长导师、峰哥亡命天涯、内容策划与文案助手；
- 教育与职业：张雪峰、职业发展顾问、简历与面试教练、考公备考教练、学习规划师；
- 办公写作：公文与材料教练、汇报与方案写作助手、会议纪要与行动项助手、人事文档助手；
- 研究和产品：调研与事实核查助手、产品与竞品分析助手、保罗·格雷厄姆、张一鸣。

提醒内容应说明重复点，并提供三种选择：

- 保留一个主负责；
- 改选互补能力；
- 仍然保留，但为每个 Skill 指定不同问题。

### 6.2 观点多样性

观点多样性至少检查：

- **领域**：是否只有同一行业或职业背景；
- **立场**：是否缺少反方或失败条件；
- **方法**：直觉、数据、风险、执行、用户体验是否单一；
- **时间**：历史人物框架与当前事实是否混淆；
- **证据**：人物观点是否缺少核查能力；
- **后果承担**：建议者是否忽略用户现实约束和风险。

多样性不是为了凑人数，也不要求每次都加入反方。系统应说明“加入该 Skill 将增加什么新信息”。

## 7. 用户确认

推荐确认页应允许用户：

- 查看推荐理由；
- 查看详情、来源、风险和能力限制；
- 增加、删除或替换 Skill；
- 调整单 Skill/多 Skill；
- 选择是否使用联网；
- 选择要带入的资料和个人背景；
- 修改预期输出；
- 取消并返回问题编辑。

只有用户最终确认后才：

- 创建或继续议题；
- 加入 Skill；
- 将用户选择的资料带入；
- 开始模型调用。

打开详情、搜索、收藏或返回均不得自动开始。

## 8. 高风险推荐

### 8.1 医疗、法律、金融

- 优先推荐一般信息、整理、核查和问题清单能力。
- 清楚说明不是诊断、法律意见或投资保证。
- 当前政策、价格、资格、法规或产品必须标注地区和日期。
- 重大决定前提示持牌专业人员或正式渠道复核。
- 人物视角不能作为唯一主负责。

### 8.2 心理危机和紧急危险

- 优先现实安全和人工帮助。
- 不以普通阵容推荐延迟紧急行动。
- 不推荐娱乐、人物模仿或长流程工作流处理紧急情形。

### 8.3 真人人物

- 展示非本人声明。
- 涉及当前政治、企业、监管、产品或个人现状时要求时效核验。
- 不推荐其处理需要专业执照的任务，除非仅作为补充视角。

## 9. 特殊候选推荐规则

### 9.1 Windows 文档生产力助手

只有用户目标属于内容组织、模板设计、质量检查、步骤说明或生成可复制内容时，才可作为“移动端受限候选”展示。

当用户要求真实执行 Word、Excel、PowerPoint、VBA、宏、COM、PowerShell 或 Windows 文件操作时：

- 不得显示为可直接执行；
- 明确 Android 端不能完成；
- 可改为提供步骤、模板、检查清单或交由后续桌面环境执行；
- 当前保持暂缓，不进入正式可开始集合。

### 9.2 原创表达与写作自然化助手

仅在用户希望改善真实内容的结构、语气、可读性和自然度时推荐。

以下意图触发拒绝或转向合规帮助：

- “绕过 AIGC 检测”；
- “伪装成人工原创”；
- “编造经历、数据或引用”；
- “保证查不出来”；
- “规避学校、招聘或平台审查”。

可转向：

- 澄清用户真实观点；
- 标记 AI 辅助范围；
- 事实和引用核查；
- 原创结构重写；
- 遵守提交方规则的编辑建议。

## 10. 失败、缺口和降级

- 无合适候选时，系统应说明缺口，不强行推荐名人。
- 联网不可用时，标记未核验并降级为稳定框架或要求用户提供来源。
- 许可或移动端状态不明时，只显示研究状态，不可开始。
- 推荐理由生成失败时，不能只展示无解释名单。
- 多 Skill 阵容重复过高时，提醒用户调整，不擅自删除。
- 用户拒绝全部推荐时，仍可返回问题继续编辑或选择搜索。

## 11. 推荐记录

为支持后续审查，每次正式开始前应保留目标层面的可解释记录：

- 用户确认的问题和阶段目标；
- 被推荐、被排除和最终选择的 Skill；
- 推荐理由与主要限制；
- 用户主动选择的资料、联网和个人背景；
- 高风险提示是否展示；
- 用户的替换、删除和确认动作。

记录用于本地议题回顾和产品审查，不用于暗中建立人物画像。具体存储和隐私实现由 PR08-E、PR08-F 和 PR09 评估。

## 12. V1 边界

V1 不提供：

- 用户创建 Skill；
- 第三方 Skill 导入；
- 公开市场、评分榜或付费排名；
- 自动安装脚本、依赖或桌面工具；
- 以热度决定可靠性的排行榜；
- 未经确认的自动邀请；
- 未经确认的自动交叉讨论；
- 许可证未通过候选的正式接入。

## 13. 验收条件

- 用户可从问题、分类、搜索、筛选、最近使用和收藏发现 Skill。
- 每个推荐都有具体理由、职责、输入、输出和限制。
- 用户确认前不加入、不开始、不上传材料。
- 单 Skill 与多 Skill并列，不把多 Skill视为默认更高级。
- 阵容能识别能力重复并检查观点多样性。
- 人物名气不进入专业可靠性判断。
- 高风险、Windows 文档和写作自然化边界清楚可执行。
- 暂缓与许可待核验候选不能伪装成当前可用。
