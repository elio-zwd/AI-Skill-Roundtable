# 见域 Skill 发现与推荐模型

> 状态：PR08-C 收尾规格。本文定义目标产品的发现与推荐规则，不代表当前 Android App 已实现推荐引擎、收藏、最近使用、多维筛选或完整治理字段。
>
> 关联文档：[Skill 分类模型](./jianyu-skill-taxonomy.md)；[官方候选目录映射](./jianyu-skill-catalog-mapping.md)。

## 1. 冻结结论

见域采用“**问题优先、全量可发现、候选可解释、风险可见、用户确认、阵容去重、观点多样**”的推荐模型：

```text
用户表达问题
→ 识别目标、约束、风险、时效、资料和输出
→ 从已通过当前产品版本发布门禁的候选中生成单 Skill / 多 Skill 建议
→ 检查能力重复、观点多样性和现实风险
→ 展示问题匹配、职责、风险标签、时效和人物模拟状态
→ 用户增删、替换、选择材料或确认
→ 才开始单 Skill 或多 Skill 协作
```

冻结规则：

1. 44 项均属于 V1 阶段目标，允许按 V1.0、V1.1 等批次达到发布条件；不要求 V1.0 首次发布时同时上线全部 44 项。
2. 现有 20 项历史阵容资产全部可搜索、浏览，并在所有场景中正常参与自动推荐。
3. 高风险或敏感场景可以增加免责声明、时效核验、输出边界和专业转介，但不得仅因人物争议或风险标签降低人物 Skill 排名、全局隐藏人物，或把人物改成只能手动邀请。
4. 人物知名度、财富、职位、粉丝量和点击量只影响名称可发现性，不得作为专业可靠性依据。
5. 用户确认前不自动加入 Skill、不开始圆桌、不带入个人材料，也不把其他 Skill 的输出交给表达类 Skill。

“有资格参与推荐”不等于“当前构建已获准发布”。如果某候选仍处于阻断重构、原创性或许可待核验状态，它可以在规格、目录或研究状态中显示，但正式产品版本不得把它伪装成已通过门禁的可执行能力。

## 2. 发现入口

### 2.1 问题推荐

首页先允许用户直接描述问题。推荐前至少识别：

- 用户要解决什么；
- 希望思维拓展、现实支持或两者兼有；
- 是一次任务还是持续议题；
- 需要何种输入与输出；
- 是否依赖当前信息或联网；
- 是否涉及隐私、法律、医疗、金融、心理危机、政治或加密合规；
- 单 Skill 是否足够；
- 是否需要反方、核查或工作流能力。

识别结果只用于当前推荐，不自动保存为长期个人背景。

### 2.2 分类浏览

分类浏览先展示四类主类型，再允许按领域和场景缩小范围。界面不得把 44 项平铺成无层次名人列表。

每张卡至少显示：

- 名称、主类型和一句话能力说明；
- 现实支持、思维拓展或两者皆可；
- 适合单 Skill、多 Skill 或两者皆可；
- 联网和资料要求；
- 风险标签和能力限制；
- 时效状态；
- 是否为人物模拟；
- 当前接入、开发中、门禁待完成或可发布状态。

### 2.3 搜索

搜索覆盖：

- 正式名称、常见别名和中英文名；
- 能力描述；
- 领域、场景、输入和输出标签；
- 用户自然语言，例如“帮我拆老板任务”“写一封催办信息”“整理 PPT 大纲”“找反方意见”。

现有 20 项全部进入搜索索引。风险标签不得把它们从搜索中移除。

### 2.4 筛选

V1 目标筛选项：

- 主类型；
- 现实支持或思维拓展；
- 领域和场景；
- 单 Skill 或多 Skill；
- 是否需要联网；
- 是否需要资料；
- 风险等级和治理标签；
- 当前状态。

筛选用于缩小候选，不改变 Skill 本身的风险、来源和能力边界。

### 2.5 最近使用和收藏

- 最近使用按用户真实启动记录产生。
- 收藏由用户主动操作，可取消。
- 收藏和最近使用提高个人可访问性，不提高全局可靠性评分。
- 收藏不能绕过发布门禁。
- V1 本地保存，不暗示账号同步。

## 3. 推荐资格与排序

### 3.1 发布门禁和推荐资格分开

推荐系统分别处理：

| 判断 | 回答的问题 |
|---|---|
| 产品范围 | 是否属于 44 项 V1 阶段目标 |
| 发现资格 | 是否可搜索和浏览 |
| 自动推荐资格 | 是否可根据问题进入候选排序 |
| 当前执行资格 | 当前产品版本是否已经完成重构、来源、许可、安全、质量和能力验收 |

现有 20 项前三项均为“是”。当前执行资格必须以实际发布门禁为准，不能用“已经存在于 assets”替代。

发布状态优先级：

```text
阻断重构
> 原创性或许可待核验
> 补 Notice 与声明
> 可发布
```

### 3.2 候选匹配维度

| 维度 | 判断问题 |
|---|---|
| 目标匹配 | 是否直接帮助当前问题和阶段目标 |
| 类型匹配 | 人物视角、顾问、助手或工作流是否合适 |
| 输入匹配 | 用户已有材料是否满足最低输入 |
| 输出匹配 | 能否产生用户需要的结果形式 |
| 时效匹配 | 是否需要当前信息，能否核验 |
| 治理准备 | 是否具备相应边界、提示和复核机制；该项用于响应治理，不作为人物风险降权分 |
| 模式匹配 | 单 Skill 是否足够，是否需要多 Skill |
| 协作增益 | 加入后是否提供新的领域、立场或步骤 |
| 重复惩罚 | 是否与已选 Skill 能力高度重复 |
| 当前执行资格 | 是否已通过当前版本发布门禁 |

不得使用点击量、知名度、财富、职位、粉丝数或模型熟悉程度评估专业可靠性。人物 Skill 可以基于问题目标、能力匹配、阵容互补和重复程度正常排序，但人物争议和风险标签本身不得形成系统性降权。

### 3.3 高风险治理规则

医疗、法律、金融、心理、政治、加密资产、重大职业或不可逆决定等场景中：

- 人物 Skill 按正常候选匹配规则参与排序，不因人物争议或风险标签降低排名；
- 可以要求补充核查者、专业顾问或现实专业人员；
- 可以增加地区、日期、来源、不确定性和免责声明；
- 可以在推荐理由中解释人物 Skill 的职责、适用边界和需要补充的现实复核；
- 不得全局隐藏相关人物；
- 不得把人物设为只能手动邀请；
- 不得删除目录中的争议人物。

紧急健康、安全、自伤他伤等现实危险不适用普通阵容推荐，应优先现实安全和人工帮助。这属于紧急响应流程切换，不是对某个人物 Skill 的推荐降权。

## 4. 推荐理由契约

每个候选必须提供可读理由，至少展示：

1. **匹配的问题**：它具体解决用户问题的哪一部分。
2. **负责的职责**：主负责、补充、挑战、核查、工作流或成果构建。
3. **需要的材料**：用户需补充的事实、日期、文本、表格或约束。
4. **预期输出**：分析、清单、计划、沟通稿、文档结构或其他成果。
5. **风险标签**：例如金融风险、政治敏感、心理健康或来源待核验。
6. **时效状态**：资料日期、是否需要联网、当前是否已经核验。
7. **人物模拟状态**：人物或历史阵容资产明确显示 AI 模拟和非本人声明。
8. **明显取舍**：与其他候选重叠时说明为什么选择、替换或分工。

人物模拟统一显示：

> 这是基于公开资料生成的 AI 模拟视角，不代表本人，也不保证复现其当前或完整观点。

禁止使用“最强”“最权威”“本人推荐”“一定适合”等无法核验或会造成冒充的语言。

## 5. 单 Skill 与多 Skill 推荐

### 5.1 单 Skill

优先推荐单 Skill 的情况：

- 目标和交付物清楚；
- 风险可由一个受控能力覆盖；
- 不需要明显的跨领域判断；
- 用户希望快速完成一次任务；
- 多 Skill 只会增加重复和成本。

可提示核查、反方或成果整理能力，但只有用户确认后才加入。

### 5.2 多 Skill

多 Skill 适用于：

- 复杂决策或长期议题；
- 同时需要现实支持和思维拓展；
- 需要不同领域、立场或证据来源；
- 需要“分析—核查—成果”多个步骤；
- 高风险问题需要专业边界与现实复核；
- 用户明确希望圆桌协作。

建议职责：

```text
主负责：直接处理核心问题
补充者：提供不同领域或执行步骤
挑战者：检查反方、失败条件或关键假设
核查者：验证来源、事实与时效
整合者：保留共识、分歧、条件和下一步
成果构建者：在用户确认后形成可编辑交付物
```

多 Skill 默认分别独立回应。交叉讨论仍需用户显式触发；表达类 Skill 不因被加入就自动取得其他成员全部输出。

## 6. 阵容重复与观点多样性

容易重叠的能力组：

| 能力组 | 相关候选 | 推荐处理 |
|---|---|---|
| 教育与职业 | 张雪峰、职业发展顾问、考公备考教练、学习规划师、简历与面试教练 | 区分人物视角、通用职业、考试、学习和求职交付 |
| 创业、产品与经营 | 马斯克、乔布斯、张一鸣、保罗·格雷厄姆、蒂姆·库克、段永平、产品与竞品分析助手 | 分配创新、产品、组织、创业、运营、经营或研究职责 |
| 投资与风险 | 芒格、塔勒布、纳瓦尔、孙宇晨、赵长鹏、预算与消费决策助手 | 人物提供不同视角，预算助手处理一般消费和风险教育 |
| 内容与增长 | MrBeast、峰哥、X 增长导师、内容策划与文案助手、`original-expression-naturalizer` | 区分人物视角、增长、内容生产和现实沟通文案 |
| 办公写作 | 公文教练、汇报方案助手、会议行动助手、人事文档助手、团队交接助手、办公文档助手 | 区分文体、会议转行动、人事、交接和文档结构 |
| 研究与证据 | 费曼、卡帕斯、调研与事实核查助手、产品与竞品分析助手 | 人物负责解释或技术角度，核查助手负责证据和时效 |

遇到重叠时提供三种选择：

- 保留一个主负责；
- 改选互补能力；
- 仍然保留，但给每个 Skill 指定不同问题。

观点多样性检查领域、立场、方法、时间、证据和后果承担，不为凑人数而强制加入反方。

## 7. 用户确认与材料带入

推荐确认页允许用户：

- 查看推荐理由、详情、来源、风险和时效；
- 增加、删除或替换 Skill；
- 调整单 Skill 或多 Skill；
- 选择是否联网；
- 选择要带入的资料和个人背景；
- 选择是否将其他 Skill 的行动建议或材料交给成果构建者；
- 修改预期输出；
- 取消并返回问题编辑。

只有最终确认后才：

- 创建或继续议题；
- 加入 Skill；
- 带入用户选定的资料；
- 将用户确认的行动材料交给办公文档或现实沟通文案类 Skill；
- 开始模型调用。

打开详情、搜索、收藏或返回均不得自动开始。

## 8. 特殊候选推荐规则

### 8.1 `office-document-productivity`：办公文档助手

适合推荐的目标：

- 组织 Word 正文、大纲和结构；
- 形成 PPT 逐页大纲和演讲要点；
- 设计 Excel 字段、公式思路和数据整理逻辑；
- 生成会议纪要、周报、月报、项目计划；
- 形成通知、申请、汇报材料、模板和检查清单；
- 输出可复制文本、Markdown、表格或 CSV。

当用户要求控制 Windows Office、执行 COM/VBA/宏/PowerShell、操作桌面文件或自动修改电脑中的 Word/PPT/Excel 时：

- 不得展示为可执行这些动作；
- 明确 Android V1 不具备对应能力；
- 可以转为内容结构、步骤、模板或检查清单；
- 不承诺复杂格式完全保真。

当前状态：

```text
能力方向纳入 V1
正式实现尚未完成
通过重构与验收前不可发布
```

### 8.2 `original-expression-naturalizer`：去AI化助手

目录卡片或就近说明、详情页、推荐确认、首次调用确认和成果导出说明必须同时显示：“让真实内容更像你本人表达，不用于规避检测或伪造事实。”

仅在用户需要把真实事实和行动目标转化为可直接发送、提交或使用的现实文本时推荐，例如：

- 发给领导、同事、客户、老师、家人或朋友的信息；
- 请假、申请、说明、道歉、拒绝、协商、催办；
- 求职邮件、自我介绍、申请理由、工作汇报。

输入必须来自：

- 用户提供的真实事实；
- 用户说明的关系背景、身份和行动目标；
- 用户明确确认带入的其他 Skill 行动建议或材料。

它可以调整正式、口语、礼貌、直接或委婉程度，减少机械和模板感，但不得：

- 擅自读取或带入其他 Skill 的输出；
- 整理多个 Skill 的讨论意见；
- 统一、替换或美化圆桌结论；
- 改写其他 Skill 的分析判断；
- 掩盖成员分歧；
- 以检测对抗为目标；
- 伪造事实、经历、数据、引用或身份；
- 删除必须保留的诚信、来源或 AI 使用声明。

遇到用户要求隐瞒禁止使用 AI、伪造原创过程或保证无法被识别时，应拒绝该目标，并转向真实事实梳理、合规披露和原创沟通支持。

当前状态：

```text
能力方向纳入 V1
正式实现尚未完成
阻断重构并完成原创性、诚信与质量验收前不可发布
```

## 9. 失败与降级

- 无合适候选时说明能力缺口，不强行推荐名人。
- 联网不可用时标记未核验，并降级为稳定框架或要求用户提供来源。
- 候选未通过当前执行门禁时，可显示研究或开发状态，但不能伪装为可开始。
- 推荐理由生成失败时，不能只展示无解释名单。
- 多 Skill 重复过高时提醒用户，不擅自删除。
- 用户拒绝全部推荐时，返回问题编辑或搜索。

## 10. 推荐记录

正式开始前保留目标层面的可解释记录：

- 用户确认的问题和阶段目标；
- 被推荐、被排除和最终选择的 Skill；
- 推荐理由、风险标签、时效和人物模拟状态；
- 用户主动选择的资料、联网和个人背景；
- 用户是否确认把行动材料交给成果构建者；
- 高风险提示是否展示；
- 用户的替换、删除和确认动作。

记录用于本地议题回顾和产品审查，不用于暗中建立人物画像。

## 11. V1 边界与验收

V1 不提供：

- 用户创建 Skill；
- 第三方 Skill 导入；
- 公开市场、评分榜或付费排名；
- 自动安装脚本、依赖或桌面工具；
- 以热度决定可靠性的排行榜；
- 未经确认的自动邀请、材料带入或交叉讨论。

验收条件：

- 44 项均保留为 V1 阶段目标，允许按 V1.0、V1.1 等批次达到发布条件。
- 现有 20 项均可搜索、浏览并在所有场景中正常参与自动推荐。
- 高风险或敏感标签只影响推荐理由、披露、输出边界和专业转介，不得作为降低人物 Skill 排名、全局隐藏或改成只能手动邀请的依据。
- 每个推荐展示问题匹配、风险标签、时效和人物模拟状态。
- 用户确认前不加入、不调用、不带入材料。
- 办公文档助手只推荐 Android 可真实提供的内容能力。
- `original-expression-naturalizer` 的用户侧名称为“去AI化助手”；只生成真实现实沟通文案，不整理或掩盖圆桌观点，也不承诺检测结果。
- 暂未通过发布门禁的候选不能伪装成当前可用。
