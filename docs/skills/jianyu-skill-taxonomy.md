# 见域 Skill 分类模型

> 状态：PR08-C 收尾规格。本文描述目标产品模型，不代表当前 Android App 已完成相应字段、筛选、推荐、来源台账或治理能力。
>
> 启动基线：`main@d6db5e1b825bab60852b6365eef0ef6deb5bb970`
>
> 适用范围：V1 官方内置 Skill。V1 不支持用户创建、第三方导入或公开市场。
>
> 关联文档：[Skill 发现与推荐模型](./jianyu-skill-discovery-and-recommendation.md)；[官方候选目录映射](./jianyu-skill-catalog-mapping.md)。

## 1. 冻结结论

见域使用“**一个主类型 + 两类主价值 + 多维标签 + 使用模式 + 来源治理 + 发布状态**”描述 Skill：

```text
主类型：人物视角 / 专业顾问 / 任务助手 / 工作流能力
主价值：现实支持 / 思维拓展 / 两者皆可
多维标签：领域、场景、输入、输出、风险、联网、资料、协作
使用模式：单 Skill / 多 Skill / 两者皆可
来源治理：需求研究来源 / 正式实现来源 / 许可证 / 原创性
发布状态：阻断重构 / 原创性或许可待核验 / 补 Notice 与声明 / 可发布
```

同时冻结以下产品决定：

1. **44 项官方 Skill 全部属于 V1 阶段目标。** 允许按 V1.0、V1.1 等批次开发和验收；不要求 V1.0 首次发布时 44 项同时可用，但 V1 阶段最终完成时均应达到可用状态。
2. **V1 范围不等于当前可发布。** 未通过许可、安全、质量、能力和移动端门禁的项目不得伪装为已完成。
3. **现有 20 项历史阵容资产全部可被搜索、浏览，并在所有场景中正常参与自动推荐。** 风险标签只影响推荐理由、信息披露、输出边界、时效核验和专业转介，不得作为降低排名、全局隐藏或改成只能手动邀请的依据。
4. **第三方来源采用“许可明确优先复用，来源不明独立原创”。** 研究时看过某仓库不自动形成实现依赖；正式实现来源的许可证明确、适用且符合产品边界时优先复用并履行署名、Notice 和修改说明，来源不明、无许可证或无法拆分时独立原创。
5. **许可治理与产品风险治理相互独立。** 许可证允许，不代表人物、金融、法律、医疗、心理、隐私或平台风险已经解决；产品风险高，也不等于许可证不允许。

## 2. 四类主类型

| 主类型 | 定义 | 主要价值 | 必须披露 | 不得等同于 |
|---|---|---|---|---|
| 人物视角 | 基于公开、可追溯材料模拟某位人物常见的思考框架、判断偏好和表达特征 | 以思维拓展为主，也可支持现实问题 | 非本人声明、来源、时效、适用边界 | 本人真实意见、专业执照或事实权威 |
| 专业顾问 | 围绕一个专业领域提供解释、分析框架、问题清单和一般性建议 | 现实支持或两者皆可 | 专业边界、适用地区或版本、来源与人工复核条件 | 诊断、法律意见、投资保证、正式审批 |
| 任务助手 | 针对一次明确任务生成、修改、比较或检查可交付内容 | 以现实支持为主 | 所需输入、输出范围、事实与授权责任 | 自动替用户完成现实审批、签署或提交 |
| 工作流能力 | 按可复用步骤组织材料、检查节点、协作和成果，适合阶段推进 | 以现实支持为主，也可用于思维拓展 | 步骤、前置材料、中止条件、人工确认点 | 无确认的自动执行器或桌面脚本代理 |

类型判断规则：

1. 以用户实际获得的主要能力分类，不以名称中的“导师”“助手”机械判断。
2. 真实人物或明确人物模拟优先归入“人物视角”。
3. 需要连续步骤、检查点和成果交接的能力优先归入“工作流能力”。
4. 聚合方法论但不模拟具体人物的角色可归入“专业顾问”。
5. 类型不代表可靠性等级；人物知名度、财富、职位和粉丝量不得替代证据、来源和专业资质。

## 3. 两类主价值

### 3.1 现实支持

帮助用户处理生活、学习和工作中的具体事项，例如：

- 澄清任务与约束；
- 形成计划、清单、申请、说明或沟通稿；
- 整理资料、比较选项和核查事实；
- 生成可编辑成果；
- 明确下一步、阻碍和检查节点。

### 3.2 思维拓展

帮助用户重新理解问题和发现盲区，例如：

- 引入不同人物、领域和立场；
- 提供反方意见；
- 检查关键假设；
- 比较不同判断框架；
- 识别不确定性和遗漏视角。

### 3.3 标注规则

- 每个 Skill 标注 `现实支持`、`思维拓展` 或 `两者皆可`。
- 这是推荐和展示属性，不是用户议题的永久模式。
- 同一议题可以在两类价值之间反复切换。
- 主价值不能覆盖类型、风险、来源状态或使用模式。

## 4. 多维标签

标签采用稳定标识符与中文显示名分离。PR08-C 只冻结语义，不提前决定 Room Schema、Kotlin 枚举或 JSON 字段实现。

### 4.1 领域标签

| 标识符 | 中文名 | 典型范围 |
|---|---|---|
| `learning_exam` | 学习与考试 | 学习规划、考公、面试、知识解释 |
| `career_workplace` | 职业与职场 | 职业选择、求职、沟通、管理、协作 |
| `office_operations` | 办公与运营 | 会议、公文、汇报、合同、人事、交接 |
| `writing_research` | 写作与研究 | 调研、事实核查、结构、引用、表达 |
| `life_relationships` | 生活与关系 | 家庭、关系、礼仪、冲突与边界 |
| `personal_finance` | 财务与消费 | 预算、消费决策、金融风险教育 |
| `health_wellbeing` | 健康与自我管理 | 睡眠、习惯、压力、一般健康信息 |
| `culture_entertainment` | 文化与娱乐 | 传统文化、旅行、娱乐性陪伴 |
| `creator_business` | 内容与商业 | 内容策划、传播、创业、增长 |
| `technology_productivity` | 技术与生产力 | AI、工程、文档、表格、演示 |
| `industry_professional` | 行业专业支持 | 专利、软著、法律清单、合规 |
| `decision_risk` | 决策与风险 | 假设、概率、尾部风险、取舍 |

一个 Skill 可拥有多个领域标签；领域标签不等于专业资质。

### 4.2 场景、输入与输出标签

场景标签可组合使用：

`plan` 规划、`learn` 学习、`decide` 决策、`compare` 比较、`brainstorm` 发散、`challenge` 反方、`research` 调研、`verify` 核查、`write` 写作、`review` 审校、`communicate` 沟通、`practice` 演练、`summarize` 总结、`handover` 交接、`deliver` 成果交付。

输入标签包括：

`question`、`free_text`、`conversation_context`、`notes`、`document_text`、`links`、`structured_data`、`personal_context_optional`、`sensitive_material`。

输出标签包括：

`analysis`、`questions`、`comparison`、`plan`、`checklist`、`draft`、`script`、`summary`、`decision_record`、`knowledge_note`、`table`、`review_report`、`handover_package`、`audio_candidate`。

输入和输出标签描述目标产品可接受或可形成的内容，不代表当前 Android App 已具备文件读取、桌面控制或复杂格式保真能力。

### 4.3 风险标签

| 风险等级 | 适用情况 | 最低要求 |
|---|---|---|
| `general` | 普通创意、解释、低后果整理 | 说明关键假设，不编造事实 |
| `sensitive` | 隐私、职场、人际、声誉、版权、商业材料 | 用户授权确认、最小必要材料、避免冒充和操控 |
| `high_stakes` | 医疗、法律、金融、心理危机、重大职业或不可逆决定 | 来源、地区或版本、时效、不确定性、人工复核提示 |
| `urgent` | 紧急健康、安全、自伤他伤或重大现实危险 | 优先现实安全和人工帮助，不继续普通建议流程 |

高风险是响应方式和治理要求，不是降低排名或隐藏候选的理由。

### 4.4 联网、资料与协作标签

联网标签：

- `network_not_needed`：只根据用户材料和稳定方法完成。
- `network_optional`：联网可提高质量，但离线仍能提供稳定框架。
- `network_required`：正确完成必须核对当前政策、价格、职位、产品、法律或其他时效信息。
- `network_prohibited_for_material`：材料高度敏感，不应发送到外部检索或未授权服务。

资料标签：

- `material_none`
- `material_optional`
- `material_required`
- `material_user_authorized`
- `material_sensitive`
- `material_time_bound`

协作标签：

| 标签 | 在多 Skill 中的作用 |
|---|---|
| `independent_view` | 独立给出观点，避免互相抄写 |
| `complementary` | 补充不同领域或不同步骤 |
| `challenger` | 检查假设、反方和失败条件 |
| `verifier` | 核查事实、来源和时效 |
| `synthesizer` | 汇总共识、分歧、条件和下一步 |
| `workflow_owner` | 组织步骤、材料和检查节点 |
| `deliverable_builder` | 形成最终可编辑成果 |

协作标签用于检查阵容结构，不自动触发交叉讨论，也不授权表达类 Skill 改写其他 Skill 的观点。

## 5. 使用模式

| 模式 | 适用条件 |
|---|---|
| `single_only` | 能力只能在单独、受控流程中可靠工作 |
| `single_preferred` | 明确任务由单 Skill 完成更高效，但可被其他 Skill 引用 |
| `multi_preferred` | 主要价值来自与其他 Skill 的互补或反方关系 |
| `both` | 单 Skill 和多 Skill 均可 |

人物视角不得成为高风险问题的专业裁决者。它可以提供补充角度，但必须由专业顾问、核查能力或现实专业人员补足。

## 6. 来源与原创性治理

### 6.1 两类来源必须分开记录

| 来源类型 | 含义 | 能否据此复制实现 |
|---|---|---|
| 需求研究来源 | 用来发现用户需求、能力方向或常见工作流的第三方项目、文章或案例 | 不能；只记录研究关系 |
| 正式实现来源 | 实际进入见域提示词、工作流、示例、代码、脚本、模板或素材的具体来源 | 只有逐项核验后才可以 |

第三方项目只是需求研究来源时：

- 不自动构成正式实现依赖；
- 不因该研究来源无许可证就删除正常能力方向；
- 不因研究来源标注 MIT、Apache-2.0 或其他许可证，就认定见域草案自动获得相同许可。

### 6.2 正式实现来源规则

1. 在符合见域产品目标、Android 能力边界和安全要求的前提下，正式实现应优先复用许可证明确且允许商业使用、修改和分发的 MIT、Apache-2.0、CC0 等上游内容，并固定完整 40 位 Commit、目标文件、许可证文件、署名或 Notice 和修改说明。
2. 正式实现来源不明、无许可证、授权范围无法确认，或第三方具体正文、特殊结构、独特流程、示例无法与无授权部分拆分时，必须删除对应内容并由见域独立原创重写。
3. 尚未完成逐项原创性比对时，统一标记 `原创性待核验`，不得写成“已经确认完全原创”。
4. 外部仓库当前最新 Commit、研究时核验 Commit 和未来正式实现实际采用 Commit 必须分别记录。研究时核验版本不代表未来正式采用版本。
5. 仓库根目录许可证不自动覆盖书籍摘录、图片、二维码、音频、外部文章、视频文字稿、子模块、搬运内容、人物姓名、肖像、商标或人格权。

### 6.3 许可治理与产品风险分别判定

- 许可结论回答“能否按条件使用这段具体第三方内容”。
- 产品风险回答“即使可以使用，是否需要重写、免责声明、时效提示、人工复核或专业转介”。
- 两者不得互相替代。

## 7. 治理标签与发布优先级

治理标签可叠加。现有 20 项历史阵容资产统一执行 `[非本人声明]`；根据实际情况再增加：

```text
[高时效]
[金融风险]
[加密合规]
[政治敏感]
[心理健康]
[来源待核验]
[生产资产清理]
```

普通 Skill 可以只执行通用治理规则，不要求每项至少一个专项标签。

`[生产资产清理]` 只用于：

- 已确认存在需要清理、替换或重新授权的 references、图片、二维码、音频、脚本等资产；
- 或明确写为“尚未逐目录核验”，在完成核验前作为阻断标签。

发布判断采用单一优先级：

```text
阻断重构
> 原创性或许可待核验
> 补 Notice 与声明
> 可发布
```

低优先级动作不能覆盖高优先级阻断。例如需要重构的 Skill 不能因为补了 Notice 就标记为可发布。

## 8. 人物模拟与推荐资格

所有现有 20 项历史阵容资产必须统一显示：

> 这是基于公开资料生成的 AI 模拟视角，不代表本人，也不保证复现其当前或完整观点。

其中 `x_mentor` 在主类型上属于专业顾问，但为避免历史资产和聚合来源被误认为官方本人或平台授权，也执行同等清晰的非本人、非官方声明。

人物或历史阵容资产还必须：

1. 记录直接上游、材料来源类别和最后核验日期。
2. 区分历史观点、推断和当前事实。
3. 涉及政治、企业、投资、加密资产或快速变化技术时优先联网核验。
4. 不生成仿冒身份、授权声明、私密信息或“本人一定会这样决定”的确定性结论。
5. 不把独特表达风格的高相似模仿作为卖点。
6. 不把知名度、财富、职位或粉丝量等同于专业可靠性。
7. 全部可被搜索、浏览并在所有场景中正常参与自动推荐；敏感或高风险标签不得单独用于降低排名、全局隐藏或改成只能手动邀请，只能强化推荐理由、信息披露和输出治理。

## 9. 特殊能力边界

### 9.1 `office-document-productivity`

正式中文定位：**办公文档助手**。

状态：

```text
能力方向纳入 V1
正式实现尚未完成
通过重构与验收前不可发布
```

Android V1 允许：

- Word 正文、大纲和结构；
- PPT 逐页大纲和演讲要点；
- Excel 字段设计、公式思路和数据整理逻辑；
- 会议纪要、周报、月报、项目计划；
- 通知、申请和汇报材料；
- 模板、检查清单；
- 可复制的文本、Markdown、表格或 CSV 内容。

Android V1 禁止宣称：

- 直接控制 Windows Office；
- 执行 COM、VBA、宏或 PowerShell；
- 操作桌面文件系统；
- 自动修改电脑里的 Word、PPT 或 Excel；
- 保证复杂 Office 文件格式完全保真。

Anthropic 文档类 Skill 等第三方项目可以作为能力研究来源，但见域不得默认复制其正文、脚本、模板或资源，也不得把桌面或文件执行能力承诺带入 Android V1。

### 9.2 `original-expression-naturalizer`

保留现有 Skill ID，用户侧中文名称冻结为“去AI化助手”。名称出现时必须就近显示固定边界：“让真实内容更像你本人表达，不用于规避检测或伪造事实。”

它是**现实沟通文案任务助手**：

> 根据用户提供的真实事实、关系背景、行动目标，以及用户确认带入的其他 Skill 行动建议或材料，生成用户可以直接发送、提交或实际使用的现实沟通文案。

典型输出：

- 发给领导、同事、客户、老师、家人或朋友的信息；
- 请假、申请、说明、道歉、拒绝、协商、催办；
- 求职邮件、自我介绍、申请理由、工作汇报；
- 其他可直接发送或提交的内容。

允许：

- 减少模板感、机械感和空泛表达；
- 更符合具体关系、身份和情境；
- 更贴近用户真实表达习惯；
- 调整正式、口语、礼貌、直接或委婉程度；
- 把行动建议转化为可直接使用的现实文本。

它不负责：

- 整理多个 Skill 的讨论意见；
- 统一圆桌观点；
- 改写其他 Skill 的分析结论；
- 掩盖 Skill 之间的分歧。

禁止：

- 以检测对抗为产品目标，或承诺内容无法被识别；
- 伪造用户经历、事实、数据、引用或身份；
- 帮助隐瞒明确禁止使用 AI 的行为；
- 删除必须保留的诚信、来源或 AI 使用声明；
- 复制原 `academic-ai-evasion` 或 `humanizer-zh-academic` 的检测对抗提示词。

正式实现必须从零原创设计。状态为：

```text
能力方向纳入 V1
正式实现尚未完成
阻断重构并完成原创性、诚信与质量验收前不可发布
```

## 10. 最小元数据契约

每个官方候选至少记录：

| 字段 | 说明 |
|---|---|
| `skillId` / `displayName` | 稳定 ID 与用户可见名称 |
| `primaryType` / `primaryValue` | 主类型与主价值 |
| `domainTags` / `scenarioTags` | 领域和场景 |
| `inputTags` / `outputTags` | 输入和输出 |
| `riskLevel` / `governanceTags` | 风险等级与可叠加治理标签 |
| `networkMode` / `materialMode` | 联网与资料要求 |
| `collaborationTags` / `usageMode` | 协作职责与单、多 Skill 模式 |
| `researchSources` | 需求研究来源 |
| `implementationSources` | 正式实现来源及采用范围 |
| `auditCommit` / `adoptedCommit` | 研究时核验版本与实际采用版本 |
| `licenseStatus` / `originalityStatus` | 许可证与原创性状态 |
| `freshnessPolicy` / `disclosure` | 时效与声明 |
| `v1Gap` / `releaseStatus` | V1 缺口与发布门禁 |

现有 `skills_config.json` 尚不具备以上完整字段；本文不修改资产或 Schema。

## 11. 验收条件

- 44 项全部保持为 V1 阶段目标，允许按 V1.0、V1.1 等批次达到发布条件，且不把目标范围误写为当前可发布。
- 四类主类型互不混淆，允许跨领域多标签。
- 需求研究来源和正式实现来源分开记录。
- 正式实现优先复用许可明确且适用的第三方内容，来源不明、无许可证或无法拆分时独立原创。
- 许可治理和产品风险治理分别判定。
- 现有 20 项均有正常自动推荐资格、非本人声明和来源或时效要求。
- 敏感或高风险标签不得作为降低人物 Skill 排名、全局隐藏或改成只能手动邀请的依据。
- 办公文档助手不伪装桌面执行能力。
- `original-expression-naturalizer` 的用户侧名称为“去AI化助手”，只形成真实现实沟通文案，不承担圆桌观点整理或检测规避。
- 发布状态遵守“阻断重构 > 原创性或许可待核验 > 补 Notice 与声明 > 可发布”。
- 当前实现事实与目标模型明确区分。
