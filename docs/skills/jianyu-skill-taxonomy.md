# 见域 Skill 分类模型

> 状态：PR08-C 规格草案。本文描述目标产品模型，不代表当前 Android App 已完成相应字段、筛选、推荐或治理能力。
>
> 基线：`main@d6db5e1b825bab60852b6365eef0ef6deb5bb970`
>
> 适用范围：官方内置 Skill。V1 不支持用户创建、第三方导入或公开市场。

## 1. 结论

见域使用“**一个主类型 + 两类主价值 + 多维标签 + 使用模式 + 治理状态**”描述 Skill：

```text
主类型：人物视角 / 专业顾问 / 任务助手 / 工作流能力
主价值：现实支持 / 思维拓展 / 两者皆可
多维标签：领域、场景、输入、输出、风险、联网、资料、协作
使用模式：单 Skill / 多 Skill / 两者皆可
治理状态：现有接入 / 候选草案 / 待许可 / 待移动端评估 / 暂缓 / 排除
```

分类用于帮助用户理解和发现能力，不把 Skill 固定为永久模式。同一 Skill 可以跨领域、跨场景和跨价值使用，但必须只有一个主类型，避免卡片展示和推荐解释互相矛盾。

## 2. 四类主类型

| 主类型 | 定义 | 主要价值 | 必须披露 | 不得等同于 |
|---|---|---|---|---|
| 人物视角 | 基于公开、可追溯材料模拟某位人物常见的思考框架、判断偏好和表达特征 | 以思维拓展为主，也可支持现实问题 | 非本人声明、资料来源、资料时效、适用边界 | 本人真实意见、专业执照或事实权威 |
| 专业顾问 | 围绕一个专业领域提供解释、分析框架、问题清单和一般性建议 | 现实支持或两者皆可 | 专业边界、适用地区/版本、来源与人工复核条件 | 诊断、法律意见、投资保证、正式审批 |
| 任务助手 | 针对一次明确任务生成、修改、比较或检查可交付内容 | 以现实支持为主 | 所需输入、输出范围、事实与授权责任 | 自动替用户完成现实审批、签署或提交 |
| 工作流能力 | 按可复用步骤组织材料、检查节点、协作和成果，适合阶段推进 | 以现实支持为主，也可用于思维拓展 | 步骤、前置材料、中止条件、人工确认点 | 无确认的自动执行器或桌面脚本代理 |

类型判断规则：

1. 以用户实际获得的主要能力分类，不以名称中的“导师”“助手”机械判断。
2. 真实人物或明确人物模拟优先归入“人物视角”。
3. 需要连续步骤、检查点和成果交接的能力优先归入“工作流能力”。
4. 聚合方法论但不模拟具体人物的角色可归入“专业顾问”。
5. 类型不代表可靠性等级；人物知名度不得替代证据、来源和专业资质。

## 3. 两类主价值

### 3.1 现实支持

帮助用户处理生活、学习和工作中的具体事项，例如：

- 澄清任务与约束；
- 形成计划、清单或沟通稿；
- 整理资料、比较选项和核查事实；
- 生成可编辑成果；
- 明确下一步、阻碍和检查节点。

### 3.2 思维拓展

帮助用户重新理解问题和发现盲区，例如：

- 引入不同人物、领域和立场；
- 提供反方意见；
- 检查关键假设；
- 比较不同判断框架；
- 识别不确定性和遗漏视角。

### 3.3 标注规则

- 每个 Skill 标注 `现实支持`、`思维拓展` 或 `两者皆可`。
- 这是推荐和展示属性，不是用户议题的永久模式。
- 同一议题可以在两类价值之间反复切换。
- 主价值不能覆盖类型、风险或使用模式。
- “生活与工作”“思维与视角”“现实行动”不是正式主价值名称。

## 4. 多维标签

标签采用稳定标识符与中文显示名分离。PR08-C 只冻结语义，不提前决定 Room Schema、Kotlin 枚举或 JSON 字段实现。

### 4.1 领域标签

| 标识符 | 中文名 | 典型范围 |
|---|---|---|
| `learning_exam` | 学习与考试 | 学习规划、考公、面试、知识解释 |
| `career_workplace` | 职业与职场 | 职业选择、求职、沟通、管理、协作 |
| `office_operations` | 办公与运营 | 会议、公文、汇报、合同、人事、交接 |
| `writing_research` | 写作与研究 | 调研、事实核查、结构、引用、表达 |
| `life_relationships` | 生活与关系 | 家庭、关系、礼仪、冲突与边界 |
| `personal_finance` | 财务与消费 | 预算、消费决策、金融风险教育 |
| `health_wellbeing` | 健康与自我管理 | 睡眠、习惯、压力、一般健康信息 |
| `culture_entertainment` | 文化与娱乐 | 传统文化、旅行、娱乐性陪伴 |
| `creator_business` | 内容与商业 | 内容策划、传播、创业、增长 |
| `technology_productivity` | 技术与生产力 | AI、工程、文档、表格、演示 |
| `industry_professional` | 行业专业支持 | 专利、软著、法律清单、合规 |
| `decision_risk` | 决策与风险 | 假设、概率、尾部风险、取舍 |

一个 Skill 至少一个领域标签，可有多个；领域标签不等于专业资质。

### 4.2 场景标签

建议使用可组合场景标签，而不是继续扩张顶层分类：

`plan` 规划、`learn` 学习、`decide` 决策、`compare` 比较、`brainstorm` 发散、`challenge` 反方、`research` 调研、`verify` 核查、`write` 写作、`review` 审校、`communicate` 沟通、`practice` 演练、`summarize` 总结、`handover` 交接、`deliver` 成果交付。

### 4.3 输入标签

| 标签 | 含义 |
|---|---|
| `question` | 用户问题或目标 |
| `free_text` | 普通文本和补充说明 |
| `conversation_context` | 当前议题简报、已形成判断和分歧 |
| `notes` | 会议记录、草稿、清单 |
| `document_text` | 用户有权使用的文档文本 |
| `links` | 公开链接或来源入口 |
| `structured_data` | 表格化数据、字段或参数 |
| `personal_context_optional` | 用户主动选择加入的个人背景 |
| `sensitive_material` | 可能含隐私、商业秘密或受保护信息 |

输入标签描述目标产品可接受的材料类型，不代表当前 Android App 已实现所有文件读取能力。

### 4.4 输出标签

`analysis` 分析、`questions` 澄清问题、`comparison` 对比、`plan` 计划、`checklist` 清单、`draft` 草稿、`script` 沟通稿、`summary` 总结、`decision_record` 决策记录、`knowledge_note` 知识笔记、`table` 结构表、`review_report` 审校报告、`handover_package` 交接包、`audio_candidate` 可转音频成果。

### 4.5 风险标签

| 风险等级 | 适用情况 | 最低要求 |
|---|---|---|
| `general` | 普通创意、解释、低后果整理 | 说明关键假设，不编造事实 |
| `sensitive` | 隐私、职场、人际、声誉、版权、商业材料 | 用户授权确认、最小必要材料、避免冒充和操控 |
| `high_stakes` | 医疗、法律、金融、心理危机、重大职业或不可逆决定 | 来源、地区/版本、时效、不确定性、人工复核提示 |
| `urgent` | 紧急健康、安全、自伤他伤或重大现实危险 | 优先现实安全和人工帮助，不继续普通建议流程 |

高风险是响应方式和治理要求，不是把相关问题一律禁止。

### 4.6 联网标签

- `network_not_needed`：仅根据用户材料和稳定方法完成。
- `network_optional`：联网可补充当前信息，但离线仍可提供框架。
- `network_required`：正确完成必须核对当前政策、价格、职位、产品、法律或其他时效信息。
- `network_prohibited_for_material`：材料高度敏感时，不应发送到外部检索或第三方服务。

联网状态必须在推荐理由和开始前说明；无法联网时不得伪造“已核实”。

### 4.7 资料标签

- `material_none`：无需额外资料即可开始。
- `material_optional`：资料可提高质量。
- `material_required`：缺少关键材料不能给出可靠结果。
- `material_user_authorized`：必须确认用户有权使用。
- `material_sensitive`：需要隐私与保密提醒。
- `material_time_bound`：资料需要日期或版本。

### 4.8 协作标签

| 标签 | 在多 Skill 中的作用 |
|---|---|
| `independent_view` | 独立给出观点，避免互相抄写 |
| `complementary` | 补充不同领域或不同步骤 |
| `challenger` | 检查假设、反方和失败条件 |
| `verifier` | 核查事实、来源和时效 |
| `synthesizer` | 汇总共识、分歧、条件和下一步 |
| `workflow_owner` | 组织步骤、材料和检查节点 |
| `deliverable_builder` | 形成最终可编辑成果 |

协作标签用于检查阵容结构，不自动触发交叉讨论。交叉讨论仍需用户显式选择参与者和焦点。

## 5. 使用模式

| 模式 | 适用条件 |
|---|---|
| `single_only` | 能力只能在单独、受控流程中可靠工作；V1 应谨慎使用 |
| `single_preferred` | 明确任务由单 Skill 完成更高效，但可被多 Skill 引用 |
| `multi_preferred` | 主要价值来自与其他 Skill 的互补或反方关系 |
| `both` | 单 Skill 和多 Skill 均可 |

默认不把任何人物视角设为“专业裁决者”。高风险问题中的人物视角只能提供分析角度，必须由专业顾问、核查能力或现实专业人员补足。

## 6. 最小元数据契约

每个官方候选至少记录：

| 字段 | 说明 |
|---|---|
| `skillId` | 稳定唯一标识 |
| `displayName` | 用户可见名称 |
| `primaryType` | 四类主类型之一 |
| `primaryValue` | 现实支持、思维拓展或两者皆可 |
| `domainTags` / `scenarioTags` | 领域和场景 |
| `inputTags` / `outputTags` | 输入和输出 |
| `riskLevel` / `riskNotes` | 风险等级与具体边界 |
| `networkMode` | 联网要求 |
| `materialMode` | 资料要求与敏感性 |
| `collaborationTags` | 多 Skill 中的角色 |
| `usageMode` | 单 Skill、多 Skill或两者皆可 |
| `sourceRecords` | 本地资产、研究目录和上游来源 |
| `licenseStatus` | 已核验、待核验、不兼容或不适用 |
| `freshnessPolicy` | 资料日期、复核周期和失效条件 |
| `disclosure` | 非本人、非专业意见、娱乐等声明 |
| `displayStatus` | 正常、风险提示、能力限制、暂缓 |
| `integrationStatus` | 当前接入、候选、暂缓或排除 |

现有 `skills_config.json` 尚不具备以上完整字段；本文不修改资产或 Schema，后续实现由 PR08-E、PR08-F 和 PR09 决定。

## 7. 人物模拟契约

所有真实人物型 Skill 的详情页、加入确认和首次输出必须以清楚文案披露：

> 这是基于公开资料生成的 AI 模拟视角，不代表本人，也不保证复现其当前或完整观点。

同时必须：

1. 记录材料来源类别和最后核验日期。
2. 区分历史观点、推断和当前事实。
3. 涉及在世人物、政治、企业、投资或快速变化技术时优先联网核验。
4. 不生成仿冒身份声明、授权声明、私密信息或“本人会这样决定”的确定性结论。
5. 不把独特表达风格的高相似模仿作为卖点。
6. 不把人物知名度、财富或职位等同于专业可靠性。

## 8. 高风险 Skill 契约

高风险候选必须同时具备：

- **来源**：列出官方、权威或可追溯来源，不用模糊“据研究”替代。
- **时效**：显示资料日期、适用地区/版本和需要重新核验的条件。
- **边界**：说明能做一般信息、整理和问题清单，不能做何种专业结论。
- **不确定性**：明确假设、争议和缺失信息。
- **人工复核**：指出何时需要持牌专业人员、单位审批或现实支持。
- **用户确认**：保存、转发、提交或执行高后果成果前再次确认。
- **紧急转介**：出现紧急危险时优先现实帮助，不以普通对话替代。

## 9. 治理与状态

| 状态 | 含义 |
|---|---|
| `integrated_legacy` | 当前 App 已接入，但治理元数据尚需补齐 |
| `candidate_draft` | 已有原创候选草案，尚未进入 App |
| `license_pending` | 来源或许可证未逐项确认，禁止发布接入 |
| `mobile_scope_pending` | Android 能力、依赖或隐私边界待评估 |
| `compliance_rewrite` | 能力方向可保留，但名称、目标和正文必须合规重写 |
| `deferred` | V1 暂不接入，可保留研究记录 |
| `excluded` | 与安全、诚信或产品边界冲突，不进入候选池 |

一个候选可同时拥有多个治理标记。任何 `license_pending` 项在许可证核验完成前不得复制第三方正文、代码、脚本或素材，也不得标记为“可发布”。

## 10. 特殊能力边界

### 10.1 Windows 文档生产力助手

Android V1 可保留的能力：

- 文档、表格和演示的内容规划；
- 模板、字段、公式思路和质量检查清单；
- 对用户提供的文本或结构化数据进行整理；
- 生成可复制到 Word、Excel 或 PowerPoint 的内容；
- 说明需要在 Windows/Office 中由用户完成的操作步骤。

Android V1 不得宣称：

- 直接控制桌面 Office；
- 执行 PowerShell、VBA、COM、宏或本地脚本；
- 无授权读取 Windows 文件系统；
- 保证文件格式、公式、宏或渲染结果已经在真实 Office 中验证；
- 后台自动上传、编辑或提交文档。

该候选保持 `mobile_scope_pending + license_pending + deferred`，由 PR08-E 评估文件处理、依赖、许可证、隐私和供应链风险。

### 10.2 原创表达与写作自然化助手

允许：

- 识别机械、重复、空泛或不自然的表达；
- 帮助用户澄清真实观点、经历和证据；
- 调整结构、语气、节奏和可读性；
- 检查事实、引用、原创性声明和平台要求；
- 提醒用户遵守学校、单位、招聘、平台和出版规则。

禁止：

- 绕过 AIGC、抄袭、学术或招聘检测；
- 隐瞒不允许的 AI 使用；
- 伪造经历、数据、引用、作者身份或创作过程；
- 承诺“不可检测”；
- 提供针对检测系统的对抗技巧。

原研究项 `academic-ai-evasion` 不作为正式候选 ID；正式候选重命名为 `original-expression-naturalizer`，状态为 `compliance_rewrite + license_pending + deferred`。

## 11. 验收条件

- 四类主类型互不混淆，且允许跨领域多标签。
- 两类主价值不被写成永久模式或互斥入口。
- 人物型 Skill 均有非本人声明与来源/时效要求。
- 高风险 Skill 均有边界和人工复核要求。
- 推荐与协作标签不自动触发邀请或交叉讨论。
- Windows 文档能力不伪装桌面执行。
- 写作自然化能力不承诺规避检测。
- 当前实现事实与目标模型明确区分。
