# 见域核心交互流程

> 文档状态：PR08-B 核心流程规格草案  
> 适用范围：目标产品“见域”  
> 启动基线：`main@d6db5e1b825bab60852b6365eef0ef6deb5bb970`  
> 关联文档：[见域信息架构](./jianyu-information-architecture.md)；[见域页面状态矩阵](./jianyu-screen-state-matrix.md)  
> 重要说明：本文冻结用户可见交互行为和恢复规则，不代表当前 Android App 已实现，也不冻结代码接口、数据库事务、导航字符串、推荐算法或视觉表现。

## 1. 结论

见域的核心交互围绕四条主路径组织：

```text
表达问题 → 推荐与确认 → 开始议题
继续当前阶段 → 自由追问 / 点名回应 / 交叉讨论
建立下一阶段 → 推进议题三步确认
沉淀与复用 → 资料 / 阶段总结草稿 / 正式成果 / 归档与关联
```

所有关键流程遵守以下共同门禁：

1. 系统可以建议，用户负责确认；
2. 打开面板、查看详情、返回或取消均不构成确认；
3. 模式与 Skill 推荐必须说明理由；
4. 未确认前不得自动加入 Skill、带入资料、创建阶段或保存正式成果；
5. 自由追问继续当前阶段；
6. “推进议题”是唯一正式阶段推进入口；
7. 只有三步流程最终确认后才创建新阶段；
8. 响应批次和 `roundIndex` 不等于阶段；
9. 一个议题保持单一主线，不自动分叉；
10. 运行中已经完成的有效结果在部分失败、停止或恢复时尽量保留；
11. 进程重建后不得猜测用户意图或自动重复调用；
12. 高风险操作必须有明确影响说明和可撤销或二次确认边界。

## 2. 通用状态语言

### 2.1 用户决策状态

| 状态 | 含义 | 允许动作 |
|---|---|---|
| 未开始 | 仅有输入或浏览行为 | 编辑、取消、继续填写 |
| 待确认 | 系统已生成建议，但用户未批准 | 调整、查看详情、返回、确认 |
| 已确认 | 用户明确批准当前选择 | 创建、加入、调用或保存 |
| 已取消 | 用户主动退出 | 返回来源页，保留可恢复输入 |
| 需修正 | 输入不完整或存在冲突 | 修改后再次确认 |
| 处理中 | 已确认动作正在执行 | 查看进度、停止或等待 |
| 部分完成 | 一部分成功，一部分失败 | 保留成功、重试失败、忽略 |
| 失败 | 本次动作未完成 | 查看原因、修正、重试或取消 |
| 已恢复 | 从中断、离线或进程重建恢复 | 继续、重试或放弃 |

### 2.2 运行状态

```text
准备
→ 检查 Key / 网络 / 资料 / Skill 执行资格
→ 排队
→ 搜索（可选）
→ 思考
→ 流式输出
→ 成功 / 部分成功 / 全部失败 / 用户停止
→ 可选重试或继续
```

运行状态不改变产品对象层级。一次或多次响应批次仍可属于同一阶段。

### 2.3 返回与取消原则

- 返回上一步优先保留已填写内容；
- 关闭确认流程不执行隐式确认；
- 用户在最终提交前可修改任何可调项；
- 取消推进议题不创建空阶段；
- 取消交叉讨论不创建空讨论；
- 取消成果保存不创建空成果；
- 取消资料带入不改变议题；
- 系统返回与顶部返回语义一致；
- 进程重建后不能自动越过确认门禁。

## 3. F01：快速提问并开始新议题

### 3.1 目标

让用户不必先选择模式或 Skill，直接从自然语言问题开始。

### 3.2 入口

- 首页问题输入；
- 示例问题；
- 从 Skill 详情选择“用于新问题”；
- 从资料详情选择“围绕此资料提问”；
- 从成果详情选择“继续形成新问题”。

### 3.3 主流程

1. 用户输入问题；
2. 用户可选现实支持、思维拓展或组合，也可跳过；
3. 用户可添加资料或选择个人背景，默认不自动勾选；
4. 用户提交问题；
5. 系统检查最少必要信息；
6. 如缺少会显著改变建议的事实，系统只询问最少必要问题；
7. 系统生成：
   - 问题摘要；
   - 建议的现实支持 / 思维拓展方向；
   - 单 Skill / 多 Skill建议及理由；
   - Skill 候选、职责、风险、时效和所需资料；
   - 预期输出；
8. 进入推荐确认；
9. 用户调整并最终确认；
10. 系统创建议题和初始阶段；
11. 系统固定初始阶段的 Skill 阵容、资料与个人背景选择；
12. 系统开始第一次运行；
13. 进入议题工作区。

### 3.4 直接开始边界

“直接开始”可以减少确认步骤，但不能跳过以下内容：

- 看到最终问题摘要；
- 看到实际使用的 Skill；
- 看到推荐理由与高风险提示；
- 确认带入的资料和个人背景；
- 确认将创建新议题并开始调用。

### 3.5 取消与返回

- 从推荐确认返回首页时保留问题和选择；
- 取消后不创建议题、阶段或运行记录；
- 从 Skill 详情进入时返回原详情；
- 从资料或成果详情进入时返回原来源页。

### 3.6 失败与恢复

| 失败 | 行为 |
|---|---|
| 推荐生成失败 | 保留问题，允许重试、手动浏览 Skill 或使用轻量默认建议 |
| 无合适 Skill | 说明能力缺口，不强行推荐人物；允许修改问题 |
| 无可执行 Skill | 显示开发或门禁状态，不伪装为可开始 |
| 无 Key | 跳转 Key 设置，返回后恢复待确认内容 |
| 离线 | 标记无法核验时效；可降级或等待网络 |
| 资料读取失败 | 允许替换、移除或仅使用成功资料 |
| 创建议题失败 | 不开始调用，保留确认内容并允许重试 |
| 进程重建 | 恢复输入或待确认状态，不自动开始 |

## 4. F02：显式创建长期议题

### 4.1 适用场景

- 用户明确希望长期跟踪；
- 问题包含多个阶段；
- 暂时不希望立即调用 Skill；
- 需要先整理背景和资料；
- 从归档议题创建关联新议题。

### 4.2 主流程

1. 用户选择“新建议题”；
2. 输入标题、当前问题、背景和约束；
3. 可添加资料、个人背景和预期成果；
4. 可暂不选择 Skill；
5. 系统提供可编辑议题简报；
6. 用户确认：
   - 仅保存议题；
   - 保存并进入推荐确认；
   - 保存并开始初始阶段；
7. 若仅保存，议题处于“尚未开始首个运行”的活跃状态；
8. 若开始，继续 F01 的推荐确认门禁。

### 4.3 约束

- 创建议题不等于开始模型调用；
- 议题可以先存在，再确认初始阶段；
- 不允许创建没有任何可识别标题或问题的空白议题；
- 支持持久化议题草稿：仅保存议题，不推荐 Skill、不调用模型、不创建执行运行；退出或进程重建后仍可继续完善。

## 5. F03：模式与 Skill 推荐确认

### 5.1 目标

把系统建议变成用户可理解、可调整、可拒绝的选择。

### 5.2 推荐内容

系统至少提供：

- 为什么建议单 Skill 或多 Skill；
- 每个 Skill 负责什么；
- 与问题哪部分匹配；
- 需要什么资料；
- 预期输出；
- 风险、时效和联网要求；
- 人物模拟状态；
- 候选之间的重复与取舍；
- 当前是否具备执行资格。

### 5.3 用户操作

- 接受建议；
- 从多 Skill 改为单 Skill；
- 从单 Skill 改为多 Skill；
- 增加、删除或替换 Skill；
- 调整职责；
- 查看详情；
- 选择联网；
- 选择资料；
- 选择个人背景；
- 调整预期输出；
- 拒绝全部建议；
- 返回修改问题。

### 5.4 冲突处理

| 冲突 | 提示与选择 |
|---|---|
| 能力高度重复 | 保留一个、改选互补能力、保留但分配不同职责 |
| 观点过于单一 | 建议补充不同领域或立场，但不强制凑人数 |
| 高风险缺少核查 | 建议加入核查者、专业顾问或现实专业帮助 |
| 人物视角被当作专业裁决 | 明确仅作补充角度 |
| 资料不足 | 列出缺失项，允许稍后补充或降级 |
| 候选未通过执行门禁 | 仅显示状态，不允许伪装开始 |

### 5.5 确认原子性

最终确认必须把以下选择作为一个用户决策提交：

- 问题或阶段目标；
- 价值方向；
- 模式；
- Skill 阵容和职责；
- 资料；
- 个人背景；
- 联网；
- 预期输出；
- 风险确认。

任何一部分保存失败时，不得出现“部分创建议题、部分加入 Skill、已经调用但页面显示未开始”的不可解释状态。具体事务由 PR08-E 设计。

## 6. F04：Skill 分类、搜索、筛选与详情

### 6.1 分类浏览

1. 进入 Skill；
2. 查看四类主类型；
3. 选择领域或场景；
4. 查看候选卡片；
5. 可继续搜索、筛选、收藏或进入详情。

### 6.2 搜索

搜索覆盖：

- 正式名称与常见别名；
- 能力说明；
- 领域和场景；
- 输入和输出；
- 用户自然语言需求。

搜索状态：

```text
空查询
→ 输入中
→ 搜索中
→ 有结果 / 无结果 / 失败
→ 调整筛选或进入详情
```

### 6.3 筛选

筛选至少支持：

- 主类型；
- 现实支持 / 思维拓展；
- 领域和场景；
- 单 Skill / 多 Skill；
- 联网要求；
- 资料要求；
- 风险；
- 当前状态。

关闭筛选面板后保留已应用条件；清除筛选需要显式操作。

### 6.4 详情动作

- 用于新问题；
- 加入当前议题；
- 替换当前 Skill；
- 收藏或取消收藏；
- 查看来源、时效和能力边界。

所有“加入”或“替换”动作进入确认，不直接改变阵容。

### 6.5 失败与降级

- 搜索失败时保留查询；
- 无结果时提供修改关键词和清除筛选；
- 详情加载失败时保留卡片摘要并允许重试；
- 离线时显示本地可用信息和时效状态；
- 不能执行的 Skill 显示原因与状态，不提供误导性开始按钮。

## 7. F05：单 Skill 开始与邀请其他 Skill

### 7.1 单 Skill 开始

1. 用户在推荐确认选择单 Skill；
2. 确认问题、资料、个人背景和输出；
3. 创建或进入当前阶段；
4. 运行该 Skill；
5. 结果进入当前阶段消息流。

### 7.2 邀请其他 Skill

1. 用户在单 Skill 工作区选择“邀请其他 Skill”；
2. 系统根据当前阶段目标推荐候选及理由；
3. 用户可搜索、筛选或手动选择官方 Skill；
4. 展示将提供给新 Skill 的可编辑议题简报；
5. 用户选择带入的资料；
6. 用户确认新 Skill 职责；
7. 确认后当前阶段升级为多 Skill；
8. 历史单 Skill 回答保持不变；
9. 新 Skill 仅获得议题简报和用户确认资料；
10. 用户决定是否立即发起请求。

### 7.3 取消与失败

- 取消邀请不改变阵容；
- 新 Skill 加入失败时保留原单 Skill 状态；
- 资料准备失败时允许移除失败资料后继续；
- 进程重建时若尚未确认，不自动加入；
- 已确认但未完成写入时必须恢复为“待完成或需重试”，不能重复加入。

## 8. F06：多 Skill 独立回应与临时点名

### 8.1 默认多 Skill 回应

- 多 Skill 默认分别独立回应；
- 初始请求可由多个 Skill 建立不同视角；
- 后续请求不要求全部成员发言；
- 系统可以按相关性推荐回答者并说明理由；
- 用户可以调整实际参与者。

### 8.2 临时点名回应

1. 用户在输入区点名某个 Skill，或从阵容中选择“请其回应”；
2. 输入当前问题；
3. 界面明确显示“本次仅由该 Skill 回应”；
4. 用户发送；
5. 产生临时定向回应；
6. 回应仍属于当前阶段；
7. 多 Skill 阵容保持不变；
8. 下一次输入恢复默认参与者选择。

### 8.3 切换为长期单 Skill

如果用户希望持续只与一个 Skill 深聊：

1. 系统提供“切换为单 Skill”独立动作；
2. 展示对当前阵容的影响；
3. 用户确认；
4. 后续默认只选择该 Skill；
5. 其他 Skill 的历史回答保留；
6. 该操作不自动创建新阶段。

### 8.4 失败

- 点名 Skill 不可执行时说明原因；
- 单个点名失败时可重试，不影响其他历史；
- 不能把定向失败转换成全阵容自动回答；
- 进程重建后从持久化运行状态恢复，不重复发送。

## 9. F07：显式交叉讨论

### 9.1 入口

仅由用户主动选择“交叉讨论”触发。系统可以建议，但不能自动开始。

### 9.2 配置流程

1. 打开交叉讨论配置；
2. 系统展示建议参与者及理由；
3. 用户选择至少两个参与者；
4. 用户选择或编辑讨论焦点；
5. 展示每个参与者的职责；
6. 展示只进行一轮并在结束后整合；
7. 用户确认；
8. 系统创建交叉讨论运行；
9. 参与者围绕焦点回应；
10. 系统整合共识、分歧、适用条件、明确建议和下一步；
11. 结果进入当前阶段。

### 9.3 取消与误触

- 打开配置不创建讨论；
- 返回上一步保留已选参与者；
- 关闭配置需要明确放弃；
- 误触确认后，如果尚未发出任何调用，允许立即取消；
- 已开始后使用停止流程，保留已完成回复。

### 9.4 失败与恢复

| 状态 | 行为 |
|---|---|
| 部分参与者失败 | 保留成功内容，显示失败成员，可重试失败成员 |
| 全部失败 | 不生成伪整合，允许重试或返回配置 |
| 整合失败 | 保留原参与者内容，单独重试整合 |
| 用户停止 | 保留已完成内容，标记讨论已停止 |
| 进程重建 | 显示已持久化进度和可用恢复动作，不自动继续无限讨论 |

### 9.5 约束

- 不投票裁决真理；
- 不自动多轮辩论；
- 不允许表达类 Skill 擅自改写其他成员观点；
- 不掩盖分歧；
- 不自动创建新阶段。

## 10. F08：自由追问继续当前阶段

### 10.1 主流程

1. 用户在议题工作区输入补充、质疑、澄清或深入问题；
2. 可点名回答者，也可使用当前默认参与方式；
3. 用户发送；
4. 系统在当前阶段创建新的响应批次；
5. 展示搜索、思考和流式状态；
6. 成功内容进入当前阶段；
7. 当前阶段目标不变；
8. 阶段时间线不新增节点。

### 10.2 成熟提示

当系统判断当前阶段已经形成较完整的判断、分歧、行动或成果时，可以增强“推进议题”提示：

- 解释为什么建议推进；
- 提供可能方向；
- 仍允许忽略；
- 不遮挡自由追问；
- 不自动打开推进面板；
- 不自动生成新阶段。

### 10.3 停止与重试

- 停止只影响当前活动运行；
- 已完成回复保留；
- 未完成流式内容按技术策略标记为已停止或清理；
- 失败成员可原位重试；
- 忽略失败不删除成功成员；
- 重试仍属于当前阶段和当前请求关系。

## 11. F09：推进议题三步流程

### 11.1 入口规则

“推进议题”始终可用：

- 不要求先保存阶段总结；
- 不要求阶段被系统判断完成；
- 不要求全部 Skill 发言；
- 不要求先转为多 Skill；
- 打开入口不创建阶段。

### 11.2 第一步：选择推进方向

用户选择：

- 思维拓展；
- 现实支持；
- 两者组合；使用两个可独立选择的方向卡，同时选择仍只创建一个新阶段。

界面说明：

- 这是下一阶段的主要方向；
- 不改变议题主线；
- 不是永久标签；
- 可在以后再次切换。

返回或取消不改变当前阶段。

### 11.3 第二步：选择具体措施或自定义目标

**思维拓展**

- 引入反方意见；
- 查找遗漏视角；
- 检查关键假设；
- 比较不同立场；
- 深入某个问题；
- 自定义目标。

**现实支持**

- 明确下一步；
- 形成执行计划；
- 分析执行阻碍；
- 生成成果交付；
- 设置检查节点；
- 自定义目标。

用户可以：

- 选择预设措施；
- 编辑系统建议；
- 输入自定义目标；
- 返回第一步；
- 取消流程。

### 11.4 第三步：确认下一阶段摘要

必须展示：

- 下一阶段目标；
- 方向和措施；
- 默认继承内容；
- 当前或调整后的 Skill 阵容；
- 重点资料；
- 预期输出形式；
- 高风险或时效提示；
- 确认后将在原议题中创建新阶段。

默认继承：

- 议题背景；
- 已确认资料；
- 已保存成果；
- 当前 Skill 阵容；
- 已形成判断；
- 主要分歧；
- 当前行动项。

用户可以调整：

- 目标；
- Skill；
- 资料；
- 输出形式。

### 11.5 最终确认

只有用户选择最终确认后：

1. 校验必要条件；
2. 原子创建新阶段；
3. 写入继承关系和确认快照；
4. 切换工作区到新阶段；
5. 保留旧阶段；
6. 由用户选择立即开始运行或先进入新阶段。

### 11.6 取消、误触与恢复

| 情况 | 必须行为 |
|---|---|
| 第一步取消 | 回到原阶段，无新对象 |
| 第二步取消 | 保留当前阶段，可选择是否保留本地临时输入 |
| 第三步返回 | 回到第二步并保留设置 |
| 第三步关闭 | 明确询问放弃或保留待确认设置 |
| 误触最终确认但尚未写入 | 允许取消 |
| 已写入新阶段但尚未调用 | 允许明确撤销且不设置倒计时；撤销删除该空阶段和未提交运行设置并返回上一阶段 |
| 创建失败 | 停留原阶段，保留确认摘要并允许重试 |
| 进程重建 | 若未完成最终确认，不创建阶段；若已确认，按持久化状态恢复一次创建结果 |

### 11.7 禁止行为

- 不使用“下一轮”作为正式入口；
- 不把当前 `roundIndex` 递增当作新阶段；
- 不在打开面板时预建空阶段；
- 不覆盖原阶段；
- 不复制互相冲突的历史副本；
- 不自动创建分支议题；
- 不强迫用户完成当前阶段。

## 12. F10：阶段总结草稿与正式成果

### 12.1 生成草稿

入口可以来自：

- 用户主动选择“生成阶段总结”；
- 阶段成熟提示；
- 推进议题第三步前的可选准备；
- 成果分区。

主流程：

1. 用户选择生成；
2. 系统说明将使用的阶段、Skill 回复和资料；
3. 用户确认；
4. 系统生成阶段总结草稿；
5. 用户查看并编辑；
6. 草稿保持“未确认”状态。

### 12.2 草稿操作

用户可以：

- 编辑；
- 重新生成；
- 放弃；
- 保存为正式阶段总结；
- 转为行动方案；
- 转为决策记录；
- 转为知识笔记；
- 转为交付稿；
- 派生音频成果。

### 12.3 正式保存

1. 用户选择成果类型；
2. 检查标题、内容、来源和敏感提示；
3. 用户最终确认；
4. 系统保存正式成果；
5. 成果进入议题成果与全局成果库；
6. 保留原阶段、Skill、资料和草稿来源关系。

### 12.4 失败与恢复

- 草稿生成失败不产生空成果；
- 保存失败保留草稿；
- 音频生成失败不影响文本成果；
- 导出失败不改变正式成果；
- 进程重建后恢复草稿需有明确状态，不得把未确认草稿升级为正式成果。

## 13. F11：资料加入、确认、失败与移除

### 13.1 加入来源

- 首页；
- 推荐确认；
- 议题工作区；
- 推进议题第三步；
- 全局资料库；
- 关联新议题。

### 13.2 确认流程

1. 用户选择或添加资料；

3. 必要时进行读取或解析；
4. 显示将用于哪个议题和阶段；

- 查看原因；
- 查看来源；
- 确认；
- 拒绝；
- 稍后处理。

### 13.4 失败

- 敏感资料不允许外部检索时，必须清楚说明；

- 资料移除不删除历史使用记录；

## 14. F12：归档、继续与关联新议题

### 14.1 主动归档

6. 议题进入已归档；

### 14.2 继续原议题

2. 选择继续；
3. 展示原归档简报；
4. 用户补充“现在有什么变化”；

6. 创建独立议题；
7. 记录来源议题关系；
8. 原议题保持不变。

### 14.4 创建全新议题

不需要来源关系时，回到 F02。

## 15. F13：删除与彻底清除

### 15.1 普通删除

1. 用户选择删除对象；
2. 系统显示对象类型和影响；
3. 用户确认；
4. 执行删除或进入可恢复状态；
5. 展示结果。

普通删除不得被写成归档，也不得自动彻底清除。

### 15.2 彻底清除

1. 用户选择彻底清除；
2. 系统计算影响范围；
3. 展示关联议题、阶段、资料、成果、个人背景和历史引用；
4. 明确不可恢复；
5. 二次确认；
6. 执行；
7. 展示成功、部分失败或失败阶段；
8. 必要历史位置使用匿名占位。

### 15.3 误触防护

- 不用滑动或长按作为唯一确认；
- 不允许单次轻触完成彻底清除；
- 确认按钮与取消按钮语义清楚；
- 辅助技术焦点顺序安全；
- 运行中对象不可被静默清除。

## 16. F14：停止、部分成功、全部失败与重试

### 16.1 用户停止

1. 用户点击停止；
2. 系统立即反馈“正在停止”；
3. 停止未完成调用；
4. 保留已完成有效回复；
5. 清理或标记未完成流式占位；
6. 显示“已停止”与可用后续动作；
7. 用户可修改问题、重试失败部分或继续当前阶段。

### 16.2 部分成功

必须展示：

- 成功的 Skill；
- 失败的 Skill；
- 失败原因；
- 是否影响整合；
- 重试失败 Skill；
- 忽略失败；
- 修改阵容后重试；
- 仅基于成功内容继续。

不得删除成功回复或把整批标为全部失败。

### 16.3 全部失败

必须：

- 不生成伪成功结果；
- 保留用户输入；
- 展示可读错误；
- 区分无 Key、离线、限流、资料失败、Skill 不可执行和未知错误；
- 提供修正入口；
- 防止重复点击造成重复运行。

### 16.4 重试

重试必须固定：

- 原议题；
- 原阶段；
- 原用户请求；
- 目标失败 Skill 或失败步骤；
- 已成功结果；
- 用户当前修正后的 Key、网络或资料选择。

重试不创建新阶段，不删除成功结果，不改变未确认的 Skill 阵容。

## 17. F15：无 Key、离线与联网降级

### 17.1 无 Key

- 在开始调用前阻断；
- 说明 Key 由用户自行导入；
- 提供进入 API Key 设置；
- 返回后恢复原问题、确认或运行准备状态；
- 不丢失用户输入；
- 不自动绑定未确认 Key 策略。

### 17.2 离线

根据任务区分：

| 任务 | 离线行为 |
|---|---|
| 不需要联网 | 正常继续 |
| 联网可选 | 降级并标记未核验 |
| 必须联网 | 阻断当前步骤，允许等待、提供资料或取消 |
| 敏感资料禁止外部检索 | 即使联网也不得上传或检索 |

### 17.3 网络恢复

- 提示网络已恢复；
- 不自动重复可能产生费用或副作用的调用；
- 用户明确选择继续或重试；
- 已完成内容保留。

## 18. F16：进程重建与未完成动作恢复

### 18.1 目标

应用被系统回收、崩溃或重启后，用户应看到可解释的真实状态，而不是内存状态被清空后猜测。

### 18.2 可恢复对象

目标上至少需要区分：

- 未提交问题输入；
- 待确认推荐；
- 推进议题步骤与临时选择；
- 草稿；
- 已确认但尚未开始的运行；
- 运行中；
- 部分成功；
- 失败待重试；
- 停止中；
- 已完成；
- 无法恢复。

具体持久化范围由 PR08-E 决定。

### 18.3 恢复规则

- 未最终确认的推进设置不得生成新阶段；
- 已确认创建的阶段不得重复创建；
- 已完成回复不得重复调用；
- pending 占位不能被误当正式消息；
- 无法恢复的运行必须说明原因；
- 用户可以重试、放弃或仅保留已完成内容；
- 恢复后保持原议题和阶段；
- 不因重启把定向回应改为全阵容回应；
- 不因重启自动启动交叉讨论；
- 不因重启把草稿保存为正式成果。

### 18.4 恢复入口

- 首页“恢复未完成操作”；
- 议题列表状态提示；
- 议题工作区运行卡片；
- 推荐确认恢复；
- 推进议题恢复；
- 成果草稿恢复。

同一未完成动作只显示一个主要恢复入口，避免多个页面重复触发。

- 部分成功不得显示为全部成功；

- 草稿不得显示为正式成果；
