# 见域信息架构

> 文档状态：PR08-B 信息架构规格草案  
> 适用范围：目标产品“见域”  
> 启动基线：`main@d6db5e1b825bab60852b6365eef0ef6deb5bb970`  
> 开发分支：`docs/pr-08b-information-architecture`  
> 重要说明：本文定义目标产品的信息层级、入口、页面职责与返回关系，不代表当前 Android App 已经实现，也不冻结 Android Route 字符串、Room Schema、Kotlin 类型、推荐算法、视觉 Token 或品牌表现。

## 1. 结论

见域的目标信息架构采用“**问题优先、议题持续、Skill 可发现、资料与成果可追溯、系统能力集中管理**”的结构：

```text
首页：先表达问题
  → 可选现实支持 / 思维拓展
  → 系统给出模式与 Skill 候选及理由
  → 用户确认后开始议题

议题：持续承载背景、阶段、消息、资料与成果
  → 自由追问继续当前阶段
  → 推进议题建立新的明确阶段
  → 阶段时间线完整保留

Skill：分类、搜索、筛选、详情与推荐确认
资料库：汇总输入与依据，保留议题和阶段来源
成果库：汇总用户确认保存的输出，保留生成与确认来源
设置：Key、遥测、本地数据、安全、导入导出与恢复入口
```

移动端顶层建议采用四个一级目的地：

1. **首页**
2. **议题**
3. **Skill**
4. **资料与成果**

“资料与成果”是导航分组名称，不是新的业务对象；进入后使用“资料 / 成果”两个页内 Tab，默认落在资料 Tab，并可切换成果 Tab。设置从全局顶部入口进入，不占用底部一级位置。

本架构不强迫用户先选择模式或 Skill，不把现实支持与思维拓展拆成两套产品，不把响应批次或 `roundIndex` 解释为阶段，也不允许系统在未确认时自动加入 Skill、创建新阶段、保存正式成果、归档议题或带入长期个人背景。

## 4. 正式对象与内容层级

### 4.1 核心对象

```text
问题
  ↓ 用户确认开始
议题
  ├── 背景与约束
  ├── 当前 Skill 阵容
  ├── 阶段时间线
  │   ├── 阶段目标
  │   ├── 消息与响应批次
  │   ├── 已确认资料
  │   ├── 阶段总结草稿
  │   └── 正式成果
  ├── 议题级资料
  ├── 议题级成果
  └── 归档与关联关系
```

约束：

- 问题是入口，不是长期容器；
- 议题是最高层持续容器；
- 阶段是议题内围绕明确目标的推进节点；
- 响应批次只表示一次用户请求产生的一批回复；
- 圆桌是多 Skill 协作形式，不是整个产品；
- 一个议题保持单一主线；
- 新阶段不覆盖旧阶段；
- 独立主线必须由用户显式创建或关联新议题。

### 4.2 四类内容不得混淆

| 内容 | 定义 | 可否自动持久保存 | 主要位置 |
|---|---|---:|---|
| 消息 | 用户、Skill 或系统产生的时序内容 | 按运行与历史规则保存 | 议题工作区 |
| 阶段总结草稿 | 系统基于当前阶段生成、等待用户编辑或确认的内容 | 不得自动进入成果库 | 当前阶段、成果编辑页 |
| 正式成果 | 用户明确确认后保存的判断、行动方案、知识笔记或可交付内容 | 仅确认后 | 议题成果、全局成果库 |
| 导出文件 | 用户主动导出的数据或成果载体 | 由导出动作产生 | 设置、分享或文件选择流程 |

进一步约束：

- 普通 Skill 回复不是正式成果；
- 复制文本不是保存正式成果；
- 阶段总结草稿被关闭或放弃时，不产生空成果；
- 导出文件不自动成为业务成果；
- 音频可作为成果的输出形式，但必须保留与源消息或源成果的关系；
- 恢复快照属于本地恢复能力，不进入成果库。

## 5. 全局导航

### 5.1 一级目的地

| 一级目的地 | 主要任务 | 默认落点 | 不承担 |
|---|---|---|---|
| 首页 | 表达问题、查看继续入口、接受推荐 | 问题输入 | 完整议题管理、完整 Skill 目录 |
| 议题 | 浏览、搜索、筛选、继续和归档议题 | 活跃议题列表 | 自动生成新阶段 |
| Skill | 分类、搜索、筛选、查看详情和发起确认 | Skill 发现 | 未确认即加入议题 |
| 资料与成果 | 全局汇总、检索和回到来源 | 资料 Tab，可切换成果 Tab | 脱离来源复制成新对象 |

### 5.2 全局次级入口

设置从全局顶部入口进入，至少包含：

- API Key；
- 联网与模型相关设置；
- 遥测与诊断；
- 本地数据与存储；
- 加密导入导出；
- 恢复快照；
- 应用锁；
- 隐私与高风险说明；
- 关于与版本信息。

PR08-B 只确定入口和返回关系。具体安全算法、存储和数据迁移交由 PR08-E 与 PR09。

### 5.3 全局搜索边界

全局入口可以提供跨域搜索，但必须清楚区分结果类型：

- 议题；
- Skill；
- 资料；
- 成果。

搜索结果必须显示类型和来源。搜索结果不会自动改变 Skill 阵容、带入资料、创建阶段或保存成果。

## 6. 首页信息架构

### 6.1 首页第一优先级：问题输入

首屏必须优先提供自然语言问题输入，允许用户直接描述：

- 想解决的事情；
- 当前背景和约束；
- 希望获得的帮助；
- 已有资料；
- 需要的输出。

用户无需先理解 Skill、单 Skill、多 Skill、圆桌或工作流。

### 6.2 现实支持与思维拓展

问题输入附近提供可选辅助：

- 跳过；
- 仅现实支持；
- 仅思维拓展；
- 两者组合。

行为规则：

- 默认不强制选中；
- 两类可以同时选择；
- 两类只是当前推荐和推进方向，不是永久议题类型；
- 用户以后可在同一议题中切换；
- 选择不会立即开始模型调用；
- 解释文案不得改写正式名称。

### 6.3 首页辅助区

按优先级可展示：

1. 继续最近活跃议题；
2. 恢复上次未完成的输入或待确认推荐；
3. 最近使用的 Skill；
4. 已归档议题的继续提示；
5. 示例问题或能力引导。

示例问题只能帮助表达，不得暗示系统已读取用户未确认的长期背景。

### 6.4 首页提交后的分流

```text
输入问题
  ├── 信息足够 → 生成推荐确认
  ├── 关键事实缺失 → 先询问最少必要信息
  ├── 无需推荐 → 仍进入轻量确认，可保持“暂不选 Skill”
  ├── 无合适能力 → 说明缺口，允许编辑问题或浏览 Skill
  └── 紧急现实危险 → 优先安全提示和现实求助，不进入普通推荐
```

“暂不选 Skill”只表示用户还未确定阵容；正式开始模型调用前仍需至少有一个当前可执行 Skill，或者明确进入仅保存议题草稿的路径。具体执行资格由 PR08-C 与 PR08-E 冻结。

## 7. 推荐确认信息架构

### 7.1 目的

推荐确认页是“系统建议”和“用户正式开始”之间的门禁。系统可以推荐，但不得替用户作决定。

### 7.2 必须展示

- 用户问题和可编辑摘要；
- 当前选择的现实支持、思维拓展或组合；
- 建议使用单 Skill 或多 Skill的理由；
- 每个候选 Skill 的职责和匹配理由；
- 需要的资料；
- 预期输出；
- 风险、时效、联网与人物模拟状态；
- 当前执行资格；
- 用户确认带入的个人背景；
- 开始后将创建或继续哪个议题。

### 7.3 用户可调整

用户可以：

- 修改问题；
- 跳过或更改两类价值；
- 切换单 Skill / 多 Skill；
- 增加、移除或替换 Skill；
- 打开 Skill 详情；
- 选择是否联网；
- 选择带入哪些资料；
- 选择带入哪些个人背景；
- 修改预期输出；
- 取消并返回首页；
- 保存为未开始的议题草稿；该能力已纳入 V1，只保存议题，不推荐 Skill、不调用模型、不创建执行运行。

### 7.4 确认结果

只有明确确认后才可以：

- 创建新议题或继续已有议题；
- 创建初始阶段；
- 固定当前阶段的 Skill 阵容快照；
- 带入用户确认的资料和个人背景；
- 开始模型调用。

打开详情、搜索、返回、收藏、修改筛选或关闭页面均不视为确认。

## 8. Skill 发现信息架构

### 8.1 发现入口

Skill 一级目的地包含：

- 分类浏览；
- 搜索；
- 筛选；
- 最近使用；
- 收藏；
- 推荐给当前议题；
- 开发中或门禁待完成项目的状态说明。

### 8.2 分类层级

先展示四类主类型：

1. 人物视角；
2. 专业顾问；
3. 任务助手；
4. 工作流能力。

再按 PR08-C 定义的领域、场景、输入、输出、风险、联网、资料与协作标签筛选。

界面不得把全部候选平铺成名人列表，也不得使用热度、财富、职位或粉丝量代替专业可靠性。

### 8.3 Skill 卡片最低信息

- 正式名称；
- 主类型；
- 一句话能力说明；
- 现实支持、思维拓展或两者皆可；
- 单 Skill、多 Skill或两者皆可；
- 是否需要联网；
- 是否需要用户提供资料；
- 风险与能力限制；
- 时效状态；
- 人物模拟声明；
- 当前状态：可执行、开发中、门禁待完成等。

视觉层级由 PR08-D 决定，字段语义和推荐资格由 PR08-C 决定。

### 8.4 Skill 详情

详情至少包含：

- 能解决什么；
- 不适合什么；
- 所需输入；
- 可形成的输出；
- 单 Skill / 多 Skill适用方式；
- 在多 Skill 中的职责；
- 联网、时效与风险；
- 来源和许可状态；
- 人物模拟声明；
- 当前执行资格；
- 加入当前议题、用于新问题或收藏入口。

### 8.5 从 Skill 进入议题

```text
Skill 详情
  ├── 用于新问题 → 返回问题输入并预选该 Skill
  ├── 加入当前议题 → 展示理由与影响确认
  ├── 替换当前 Skill → 展示替换前后职责
  └── 收藏 → 仅本地提高可访问性
```

任何路径都不得在未确认时调用 Skill 或带入议题资料。

## 9. 议题信息架构

### 9.1 议题列表

议题一级目的地至少提供：

- 活跃；
- 已归档；
- 搜索；
- 最近更新；
- 按阶段状态筛选；
- 按使用的 Skill 筛选；
- 按是否有正式成果筛选。

每个议题摘要至少显示：

- 标题；
- 当前阶段目标；
- 最近更新时间；
- 当前 Skill 阵容摘要；
- 未完成运行或失败提示；
- 正式成果数量；
- 归档状态。

### 9.2 议题工作区

议题工作区是目标产品的核心页面，包含以下稳定区域：

1. **议题顶部**
   - 标题；
   - 活跃或归档状态；
   - 当前阶段；
   - Skill 阵容；
   - 归档、更多操作和返回入口。

2. **阶段上下文**
   - 当前阶段目标；
   - 现实支持 / 思维拓展方向；
   - 重点资料；
   - 预期输出；
   - 关键判断、分歧和行动摘要。

3. **协作内容**
   - 用户消息；
   - Skill 独立回应；
   - 临时定向回应；
   - 显式交叉讨论；
   - 搜索、思考、流式和失败状态；
   - 阶段总结草稿。

4. **输入与一级动作**
   - 自由追问输入；
   - 停止；
   - 重试失败 Skill；
   - 邀请其他 Skill；
   - 点名回应；
   - 发起交叉讨论；
   - 推进议题。

5. **议题内分区**
   - 阶段时间线；
   - 资料；
   - 成果。

### 9.3 自由追问与推进议题的并列关系

- 自由追问位于持续输入区，用于继续当前阶段；
- 推进议题作为始终可见的一级动作；
- 阶段成熟时可以增强提示并解释理由；
- 增强提示不得遮挡自由追问或阻止继续当前阶段；
- 打开推进议题面板不会创建新阶段；
- 最终确认前，时间线不出现新阶段占位。

### 9.4 单 Skill 工作区

单 Skill 状态下：

- 当前主要 Skill 明确可见；
- 保留邀请其他 Skill 的入口；
- 邀请确认后升级为多 Skill；
- 历史单 Skill 回答保持原样；
- 邀请的新 Skill 默认接收可编辑议题简报和用户选定资料；
- 不默认接收全部原始聊天。

### 9.5 多 Skill 工作区

多 Skill 状态下：

- 展示当前阵容与职责；
- 默认分别独立回应；
- 不要求每次全部 Skill 发言；
- 点名某个 Skill 只产生临时定向回应；
- 点名不会自动切换为单 Skill；
- 交叉讨论必须显式触发；
- 删除 Skill 不删除历史回答、资料或成果。

### 9.6 显式交叉讨论

工作区提供“交叉讨论”入口，打开配置面板：

- 选择参与者；
- 选择或编辑讨论焦点；
- 查看为何推荐这些参与者；
- 确认只进行一轮；
- 确认结束后由系统整合；
- 取消不生成讨论记录。

交叉讨论结果必须保留共识、分歧、适用条件、明确建议和下一步，不以投票裁决真理。

## 10. 阶段时间线

### 10.1 时间线职责

阶段时间线用于回顾同一议题的连续推进，不是消息轮次列表。

每个阶段节点至少展示：

- 阶段序号或时间；
- 明确目标；
- 方向和措施；
- 创建原因；
- 继承自哪个阶段；
- 当时确认的 Skill 阵容；
- 重点资料；
- 关键判断、分歧和行动；
- 已保存成果；
- 运行失败或停止记录。

### 10.2 阶段切换

- 默认打开当前阶段；
- 查看旧阶段不改变当前阶段；
- 旧阶段内容只读回顾，除非用户显式从其建立关联新议题；
- 新消息默认进入当前阶段；
- 返回当前阶段的动作必须清楚可见；
- 不把 `roundIndex`、响应批次或全部 Skill 的一次齐答显示成阶段。

### 10.3 新阶段创建

新阶段只由推进议题第三步最终确认创建。创建后：

- 新阶段属于原议题；
- 旧阶段完整保留；
- 不复制历史为多个互相冲突的副本；
- 继承关系可追溯；
- 当前工作区切换到新阶段；
- 若创建失败，仍停留在原阶段并显示可恢复错误。

---

## 11. 资料信息架构

### 11.1 议题内资料

议题内“资料”分区至少区分：

- 已确认资料；
- 待确认推荐；
- 当前阶段重点资料；
- 历史阶段使用过的资料；
- 加载或解析失败的资料；
- 已移除但历史仍引用的资料状态。

每项资料至少显示：

- 名称或摘要；
- 来源；
- 所属议题；
- 首次关联阶段；
- 当前使用状态；
- 时效或更新时间；
- 是否敏感；
- 是否允许联网使用；
- 解析或可用状态。

### 11.2 全局资料库

全局资料库用于：

- 搜索；
- 按议题、阶段、来源、类型和时间筛选；
- 查看引用关系；
- 选择加入当前议题；
- 查看失效、待更新或解析失败状态。

从资料库加入议题必须经过确认，不得自动改变历史议题。

### 11.3 资料失败

资料失败包括：

- 无法读取；
- 解析失败；
- 来源失效；
- 权限不足；
- 内容过大；
- 联网不可用；
- 时效未核验；
- 敏感资料不允许外部检索。

失败时保留用户输入和已完成结果，允许：

- 重试；
- 替换资料；
- 移除该资料后继续；
- 仅使用已成功资料继续；
- 取消本次运行。

---

## 12. 成果信息架构

### 12.1 议题内成果

议题内“成果”分区展示：

- 阶段总结；
- 行动方案；
- 决策记录；
- 知识笔记；
- 交付稿；
- 音频成果；
- 其他 PR08-F 最终确认的类型。

每项正式成果显示：

- 类型；
- 标题；
- 状态；
- 所属议题与阶段；
- 使用的 Skill；
- 引用的资料；
- 用户确认时间；
- 后续修订关系；
- 可用的复制、编辑、导出或派生入口。

### 12.2 阶段总结草稿

阶段总结草稿：

- 先在当前阶段出现；
- 用户可以编辑、放弃、重新生成或转化；
- 未确认时不得进入成果库；
- 用户明确确认后成为正式成果；
- 确认失败时保留草稿并允许重试；
- 关闭页面、Activity 重建或进程重建后继续保留草稿且不自动过期；精确持久化方案由 PR09 设计。

### 12.3 全局成果库

全局成果库用于：

- 搜索与筛选；
- 按议题、阶段、类型和更新时间查看；
- 回到来源；
- 复制、导出或继续编辑；
- 作为后续阶段的已保存成果使用。

全局汇总不切断成果与原议题、阶段、资料和 Skill 的来源关系。

### 12.4 导出边界

导出入口必须说明：

- 导出的是正式成果、议题内容还是完整本地数据；
- 文件格式和保护方式；
- 是否包含资料；
- 是否包含音频；
- 是否包含个人背景；
- 是否属于可跨设备备份；
- 是否包含设备绑定恢复快照。

导出文件不自动进入成果库，恢复快照不作为用户业务成果展示。

---

## 13. 归档、关联与恢复

### 13.1 归档

- 归档由用户主动触发；
- 系统只能提示；
- 归档前说明影响；
- 正在生成时先要求停止或等待；
- 归档不删除历史；
- 已归档议题仍可搜索、查看、继续或关联。

### 13.2 继续归档议题

继续时：

1. 展示原归档简报；
2. 要求用户补充“现在有什么变化”；
3. 显示原 Skill 阵容、资料和成果；
4. 允许用户调整后确认；
5. 原归档简报保持不变；
6. 新变化和新内容单独记录。

### 13.3 关联新议题

关联新议题用于独立主线：

- 显示来源议题；
- 带入可编辑议题简报；
- 默认仅带入用户选定资料和可调整 Skill；
- 不默认复制全部原始聊天；
- 新议题拥有独立阶段时间线；
- 原议题保持不变。

### 13.4 恢复归档状态

用户可以把归档议题恢复为活跃。恢复只改变状态，不自动创建阶段或调用 Skill。

---

## 14. 删除与彻底清除

### 14.1 普通删除

普通删除适用于可恢复或有保留期的删除策略，具体实现由 PR08-E 决定。界面必须：

- 展示删除对象；
- 说明影响范围；
- 提供取消；
- 避免与归档混淆；
- 在存在运行中任务时阻止误删或先停止。

### 14.2 彻底清除

彻底清除用于不可恢复地删除议题、资料、成果或个人背景引用，必须：

- 显示关联议题、阶段、资料、成果和导出影响；
- 二次确认；
- 使用明确不可恢复文案；
- 不以普通返回或单次轻触完成；
- 失败时说明清除到哪个阶段；
- 不泄露已清除原文或敏感类别；
- 历史必要位置使用匿名占位。

### 14.3 删除后的来源关系

- 删除资料不得静默伪造完整来源；
- 删除成果不得改写原消息；
- 移除 Skill 不删除其历史回答；
- 删除个人背景普通记录不自动改写历史议题；
- 彻底清除必须覆盖用户在确认页看到的议题、阶段、消息、资料关联、草稿、成果、背景引用和相关资产；精确数据库级联与文件删除事务由 PR09 实现并通过故障注入验证。

### 15.1 返回原则

- 删除确认；

- 草稿确认。

目标信息架构需要独立设计导航图，不能只在现有三个 Tab 上追加对话框。

### 16.2 当前状态与目标语义差异

| 当前事实 | 目标约束 |
|---|---|
| `ChatSession` 直接承载全部消息 | 议题需承载阶段、资料、成果与来源关系 |

| 音频挂在消息字段 | 目标音频可作为成果形式并保留来源 |
| Markdown 明文复制或保存 | 目标成果导出与完整数据备份必须区分 |
| pending 与多数运行状态在内存 | 目标需覆盖停止、失败和进程重建恢复 |

### 16.3 既有 `testTag` 迁移纪律

当前稳定标签包括：

- 为首页问题输入、推荐确认、议题工作区、推进议题、阶段时间线、Skill 发现、资料库和成果库补充明确语义标签；
- 不用视觉位置或显示文本作为唯一测试定位方式。

## 17. 窄屏、主题与无障碍行为

### 17.1 窄屏

- 一级动作不依赖并排展示；
- 复杂筛选可收纳为可恢复面板；
- 议题工作区始终保留问题输入、停止和推进议题入口；
- Skill 阵容、阶段摘要和资料状态允许折叠，但关键风险不可隐藏；
- 三步推进每次只聚焦一个决策；
- 表格内容必须有卡片或纵向替代；
- 横向滚动不能成为阅读正文的唯一方式。

### 17.2 明暗主题

PR08-B 不定义颜色值，但要求：

- 所有状态不能只依赖颜色表达；
- 错误、风险、成功、等待和选中状态均有文字或图标语义；
- 明暗主题下信息层级、焦点和禁用状态保持等价；
- 用户输入、草稿、正式成果和系统提示可被可靠区分。

### 17.3 无障碍

- 所有图标按钮有可理解名称；
- 触控目标满足平台最低尺寸；
- 屏幕阅读器能够读出 Skill 名称、职责、风险与选择状态；
- 流式输出不逐字符高频播报，使用节流后的状态通知；
- 生成完成、停止、部分失败、全部失败和恢复成功提供可感知反馈；
- 焦点在打开和关闭面板后返回合理位置；
- 动效可降低或关闭；
- 不以长按作为唯一入口；
- 彻底清除等高风险操作不能因辅助技术焦点跳转而误触。

## 18. 验收清单

### 18.1 对象与术语

- [ ] 全文用户可见对象统一使用“资料”；
- [ ] 消息、阶段总结草稿、正式成果和导出文件明确区分；
- [ ] “推进议题”是唯一正式阶段推进入口；
- [ ] “下一轮”不作为目标功能名称；
- [ ] 响应批次和 `roundIndex` 不等于阶段；
- [ ] 一个议题保持单一主线。

### 18.2 首页与推荐

- [ ] 首页问题优先；
- [ ] 现实支持、思维拓展可跳过、单选或组合；
- [ ] 不强迫先选模式或 Skill；
- [ ] 模式与 Skill 推荐展示理由；
- [ ] 用户确认前不创建议题、不加入 Skill、不调用模型、不带入资料。

### 18.3 议题与阶段

- [ ] 自由追问继续当前阶段；
- [ ] 推进议题始终可用；
- [ ] 阶段成熟时只增强提示；
- [ ] 三步流程完成前不创建新阶段；
- [ ] 旧阶段完整保留；
- [ ] 阶段时间线不展示响应批次为阶段；
- [ ] 归档、继续、关联新议题和恢复路径清楚。

### 18.4 Skill、资料与成果

- [ ] Skill 支持分类、搜索、筛选、详情和确认；
- [ ] 单 Skill 可邀请其他 Skill；
- [ ] 多 Skill 点名只是临时定向回应；
- [ ] 交叉讨论显式选择参与者和焦点；
- [ ] 资料保留来源与使用状态；
- [ ] 草稿经确认后才成为正式成果；
- [ ] 全局资料库和成果库不切断来源关系；
- [ ] 音频只作为成果形式之一。

### 18.5 状态与边界

- [ ] 空、加载、生成、流式、部分成功、全部失败、离线、无 Key、资料失败可到达；
- [ ] 停止、重试、取消、误触和进程重建有恢复路径；
- [ ] 窄屏、明暗主题和无障碍行为完整；
- [ ] 不决定视觉 Token、推荐算法或技术 Schema；
- [ ] 不把目标设计描述为当前已实现。
