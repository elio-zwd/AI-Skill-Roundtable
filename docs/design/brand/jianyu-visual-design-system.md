# 见域视觉设计系统

> 状态：PR08-D 视觉 Token 与组件规格草案
> 基线：`main@d6db5e1b825bab60852b6365eef0ef6deb5bb970`
> 本文只定义视觉承载，不修改当前 Compose 主题、Android 资源、Route、UiState、业务状态或 `testTag`。Token 最终值由 PR08-F 与后续实现验收确认。

## 1. 视觉结论

见域采用**内容优先、编辑部式层级、克制的品牌色、边界清楚的状态语言**。用户应快速分辨：

- 问题、议题和阶段；
- 资料、消息、草稿和正式成果；
- Skill 类型、职责、价值方向、风险和执行状态；
- 搜索、思考、流式、部分成功、失败和停止；
- 继续当前阶段与“推进议题”建立下一阶段的区别。

视觉识别来自“开放边界”图形、靛蓝主色、青绿 / 紫色方向辅助色、编辑层级，以及阶段、证据、分歧和行动路径。避免满屏头像、霓虹、玻璃拟态和复杂仪表盘。

## 2. 设计原则

1. **内容先于装饰**：层级优先使用字号、留白、分组和细边框，阴影最后使用。
2. **一个产品，两类方向**：现实支持与思维拓展共享页面壳、导航、主色、组件和状态体系。
3. **状态不只靠颜色**：每个状态至少包含文字和图标 / 形状 / 控件状态中的一种。
4. **用户控制可见**：推荐、加入 Skill、带入资料、保存成果和创建阶段都要显示确认状态。
5. **克制的 AI 反馈**：动效用于解释运行和状态变化，不使用粒子爆炸、头像旋转或逐字闪烁。

## 7. 圆角、边框与层级

| Token | 值 | 用途 |
|---|---:|---|
| `radius.xs` | 6dp | 小标签、代码块 |
| `radius.sm` | 10dp | 输入、按钮 |
| `radius.md` | 14dp | 标准卡片 |
| `radius.lg` | 18dp | 重点面板 |
| `radius.xl` | 24dp | 品牌容器 |
| `radius.full` | 999dp | 状态点和短 Chip |

默认卡片 1dp 细边框；选中卡片 1.5～2dp 主色边框 + 选中图标；风险卡使用 3dp 语义边 + 标题，不使用整卡高饱和背景；焦点环不小于 2dp。

层级：

- `level.0`：页面背景，无阴影；
- `level.1`：标准卡片，细边框或极轻阴影；
- `level.2`：浮动工具条、运行状态卡；
- `level.3`：Bottom Sheet / Dialog；
- `level.4`：紧急或不可逆系统模态。

暗色主题优先用边框和明度差，而非厚重阴影。

## 8. 图标与动效

图标采用圆角线性风格，20 / 24 / 28dp，视觉线宽约 1.75～2dp。选中或紧急状态可填充，但必须保留文字。Emoji 不作为正式导航图标。

核心语义：议题使用开放容器，阶段使用路径节点，资料使用来源页 / 链接，成果使用已确认文档，证据使用引用 / 核验，分歧使用分叉 / 对照，行动使用检查点，风险使用盾牌 / 警示。

动效时长：

| Token | 时长 | 用途 |
|---|---:|---|
| `motion.instant` | 90ms | 按下反馈 |
| `motion.fast` | 160ms | Chip 和列表状态 |
| `motion.standard` | 240ms | 卡片展开 |
| `motion.emphasized` | 360ms | 面板和阶段切换 |
| `motion.brand` | ≤480ms | 启动页一次性展开 |

搜索、思考和流式使用低频、可解释反馈；禁止无限旋转多 Agent、头像轮播、高频呼吸光和逐字符闪烁。减少动效时改为淡入或即时切换，状态完成不依赖动画结束。

## 9. 核心组件

### 9.1 按钮与输入

- Primary：当前决策区唯一主要提交；
- Secondary：调整、查看和重试；
- Tertiary：低频辅助；
- Destructive：不可逆操作，文案必须具体；
- Icon：48dp 触控目标，必须有可理解名称。

禁用按钮说明原因。运行中防重复提交。问题输入和自由追问使用清晰标签，不只依赖 placeholder；键盘打开后发送、停止和取消保持可达。

### 9.2 标签与 Skill 卡

标签优先级：主类型 → 主价值 → 使用模式 → 风险 / 时效 / 联网 → 领域与场景。卡片首屏最多建议 3 枚标签。

Skill 卡至少显示：

```text
名称 + 主类型
一句话能力
现实支持 / 思维拓展 / 两者皆可
单 / 多 Skill 适用方式
当前职责或匹配理由
联网、资料、风险、时效、人物模拟、执行资格
主要动作
```

人物 Skill 不通过大头像获得更高权重；人物声明在详情和确认中完整可见。

### 9.3 议题、阶段、资料和成果

议题卡：标题、当前阶段目标、更新时间、Skill 阵容、正式成果数量和运行 / 归档状态。

阶段节点：阶段序号 / 时间、目标、方向、措施、继承关系、Skill 快照、重点资料、判断、分歧、行动和成果。响应批次不显示为阶段。

资料卡：名称、来源、时效、敏感 / 联网限制、解析状态、所属议题 / 阶段和使用状态。

成果卡明确区分草稿、待确认、正式成果、导出文件和音频派生状态。正式成果显示确认时间与来源链。

### 9.4 证据、分歧、行动、成果和风险

| 类型 | 形状与布局 |
|---|---|
| 证据 | 左侧引用边 + 来源行 |
| 分歧 | 对照行 / 双列 + 适用条件 |
| 行动 | 检查点列表 + 时间 / 负责人（如有） |
| 成果 | 已确认容器 + 来源链 |
| 风险 | 语义边框 + 风险标题 + 下一步 |

### 9.5 运行状态卡

显示当前阶段、参与 Skill、搜索 / 思考 / 流式 / 停止 / 失败状态、完成 / 失败数量和可用动作。部分成功保留成功内容，失败项原位显示；不使用一个总进度假装所有 Skill 同步。

## 10. 协作模式视觉语言

### 10.1 单 Skill

主 Skill 和职责清楚可见，保留“邀请其他 Skill”入口。单 Skill 与多 Skill 共享页面骨架。

### 10.2 多 Skill

使用阵容列表或职责矩阵，不使用头像堆叠。每个 Skill 显示职责和独立状态；默认独立回应；不显示投票、排名或胜负。

### 10.3 临时定向回应

用户消息和回复显示“定向给：Skill 名称”及聚焦标记；不改变页面主模式；回复结束后仍显示多 Skill 阵容。

### 10.4 显式交叉讨论

配置显示参与者、焦点和“一轮讨论”边界。内容以观点、引用、质疑、条件和证据展示，不模拟头像争吵。收束固定保留共识、分歧、适用条件、明确建议和下一步；结束后不自动创建新阶段。

## 11. “推进议题”与阶段时间线

“推进议题”始终位于议题工作区一级动作区，与自由追问并列但含义不同。阶段成熟时可增加轻量理由，不遮挡输入、不自动打开、不强迫推进。

三步面板顶部显示“推进议题”“步骤 N / 3”和当前议题 / 阶段摘要。手机使用高层 Bottom Sheet 或全屏面板，每步聚焦一个决策，底部固定返回 / 继续 / 最终确认。

第三步显示：下一阶段目标、方向和措施、默认继承、Skill 阵容、重点资料、预期输出、风险与时效，以及确认后将在原议题创建新阶段。最终按钮明确“创建下一阶段”。最终确认前不在时间线预建节点。

阶段时间线使用纵向节点；当前、历史、停止、部分失败和成果状态同时使用文字、图标与颜色。查看旧阶段显示只读状态和“回到当前阶段”。

“两者组合”精确控件、已创建未运行阶段撤销规则由 PR08-F 冻结。

## 12. 明暗主题、窄屏与无障碍

明暗主题保持相同信息层级、风险、选中、禁用、焦点和操作可用性。暗色避免纯黑大面积背景和高饱和大色块，以边框和明度差分层。

Material You 可后续评估，但品牌主动作、方向和风险语义不得混淆；对比不足时回退品牌预设。

窄屏：单列、12dp 边距、48dp 触控目标、标签换行、主要 / 危险动作纵向、筛选可恢复、时间线纵向、表格转卡片，输入 / 停止 / 推进议题始终可达。

无障碍：

- 普通文字目标 4.5:1，大文字与非文本控件至少 3:1；
- 所有图标按钮有名称；
- TalkBack 读出 Skill 名称、类型、职责、风险、执行与选择状态；
- 运行状态不逐字符播报，只播报关键变化；
- 打开面板后焦点进入标题，关闭后回到触发入口；
- 危险确认默认焦点不放在确认按钮；
- 拖动、滑动和长按都有按钮替代；
- 支持 200% 字号和减少动效。

## 13. `testTag` 迁移纪律

当前稳定标签：

```text

new_session_button
chat_input
send_button
stop_button
retry_failed_characters_button
dismiss_failed_characters_button
```

PR08-D 不修改标签。后续：

- `chat_input`、`send_button`、`stop_button` 在语义等价时可延续；
- `new_session_button` 不得静默改为“推进议题”；
- `character_hall` 不得静默复用为 Skill 目录；
- `audio_library` 不得继续假设音频是独立最高层对象；
- 变更必须与 Compose UI Test、导航测试和迁移说明同 PR 更新；
- 视觉位置、颜色和显示文本不能成为唯一测试定位方式。

Token 建议按 `color.brand.*`、`color.direction.*`、`color.surface.*`、`color.semantic.*`、`space.*`、`radius.*`、`elevation.*`、`type.*`、`motion.*` 和 `icon.*` 命名。页面不得私建新的全局调色板。
