# 见域最终视觉方向统一比较计划

> 状态：独立视觉决策门禁 / PR09-16 输入门禁。
>
> 本文用于比较候选视觉方向，不代表最终 Logo、App Icon 或主视觉已经批准。
>
> 产品行为与页面结构以 [`jianyu-prd.md`](../../product/jianyu-prd.md) 为准。

## 1. 目标

解决“单看 Logo 难以判断真实产品效果”的问题，在相同内容、相同信息架构、相同页面状态下比较候选方向，让用户根据实际页面承载效果选择最终视觉基线。

## 2. 候选范围

### 候选 0：原有已完成视觉版本

- 作为既有页面结构、信息密度和使用感受基线；
- 不因 PR08-D 新增 A／B／C 而自动废弃；
- 需定位原版对应的截图、设计稿或可运行页面；
- 若原版资产无法定位，必须明确记录缺失，不得凭描述重造为“原版”。

### 候选 A：开域窗

- 当前推荐深化方向；
- 优点：小尺寸、单色、App Icon 和加载动效适配较稳；
- 风险：可能接近窗口、取景框、扫描或设计工具图标。

### 候选 B：域界折页

- 优点：知识工作、编辑部、资料和成果气质强；
- 风险：可能被理解为笔记、阅读或文档工具。

### 候选 C：多视线汇聚

- 优点：多观点和多视角表达最直接，动态延展潜力强；
- 风险：可能接近眼睛、罗盘、信号或通用 AI 网络图标。

## 3. 统一比较素材

所有候选必须使用同一组内容：

```text
产品：见域
口号：看见更多观点，打开认知边界
示例议题：我要不要在未来半年转向机器人嵌入式岗位？
方向：现实支持 + 思维拓展
示例 Skill：职业发展顾问、嵌入式工程顾问、塔勒布视角
阶段：阶段 1 · 明确目标与约束
```

不得通过更换文案、角色数量、页面信息密度或异常状态，让某个候选获得不公平优势。

## 4. 必须比较的页面

### 4.1 App Icon

输出：

- Android Adaptive Icon 前景与背景关系；
- 圆形、圆角矩形、方形和水滴等常见蒙版；
- 16、24、32、48、96、192、512 和 1024 px；
- 浅色、暗色和高对比背景；
- 单色通知图标可行性。

### 4.2 首页

包含：

- 问题输入；
- 现实支持与思维拓展方向卡；
- “获取建议”主操作；
- “保存议题”次级操作；
- 最近议题；
- Skill 组合快捷入口；
- 空、加载和无 Key 状态。

### 4.3 Skill 推荐确认

包含：

- 单 Skill / 多 Skill 建议；
- 推荐理由；
- 职责；
- 风险和时效；
- 人物非本人声明；
- 资料和个人背景确认；
- 增删、替换和最终开始操作。

### 4.4 议题工作区

分别比较：

- 单 Skill；
- 多 Skill 默认独立回应；
- 临时点名；
- 显式交叉讨论；
- 流式输出；
- 部分成功和失败原位重试；
- 停止状态。

### 4.5 推进议题三步面板

必须展示：

1. 现实支持 / 思维拓展方向卡，支持单选或组合；
2. 措施和自定义目标；
3. 下一阶段摘要、Skill、资料、背景和预期输出确认。

还需展示：

- 取消；
- 提交中；
- 新阶段创建后且尚未执行时的“撤销阶段”；
- 无成果直接推进的说明。

### 4.6 阶段时间线

展示：

- 当前阶段；
- 历史阶段；
- 阶段目标；
- 总结草稿；
- 正式成果；
- 尚未开始的新阶段；
- 归档议题恢复后的历史连续性。

### 4.7 资料与成果

使用一个一级入口、页内双 Tab：

- 资料；
- 成果。

展示筛选、来源、议题和阶段关系、空状态、失败状态和详情深链。

### 4.8 回收站与运行中归档

展示：

- 回收站无自动过期；
- 恢复和彻底清除；
- 运行中触发归档时的“等待完成后归档 / 停止生成并归档”选择。

### 4.9 去AI化助手

Skill 卡和详情必须同时出现固定边界：

> 让真实内容更像你本人表达，不用于规避检测或伪造事实。

不得使用“检测通过”“不可识别”“降重”“规避审核”等宣传文案或视觉暗示。

## 5. 适配范围

每个候选至少输出：

- 浅色主题；
- 暗色主题；
- 360 dp 窄屏；
- 412 dp 常见手机；
- 字体放大 1.3 倍；
- 减少动效；
- TalkBack 阅读顺序说明。

## 6. 评价维度

采用 1～5 分，并记录文字依据：

| 维度 | 判断问题 |
|---|---|
| 品牌独特性 | 是否容易与通用 AI、文档、相机或设计工具混淆 |
| 见域含义 | 是否表达“看见更多观点、打开认知边界” |
| 产品匹配 | 是否适合多 Skill 思考与行动工作台，而非纯聊天或笔记 |
| 信息承载 | 高密度内容、阶段和多成员状态是否仍清晰 |
| 小尺寸识别 | App Icon、通知和单色状态是否可靠 |
| 明暗主题 | 主色、层级和语义色是否稳定 |
| 长期耐看 | 是否避免短期流行的霓虹、玻璃或过度 AI 视觉 |
| 无障碍 | 对比度、焦点、状态和非颜色提示是否充分 |
| 实施成本 | Compose、Adaptive Icon 和现有组件迁移复杂度 |
| 法务风险 | 商标、商店和同类图形相似度初筛风险 |

评分只用于辅助，不以总分自动替代用户选择。

## 7. 允许的混合方案

可以组合不同候选的优点，例如：

```text
原有页面信息结构
＋ A 的品牌骨架和小尺寸图标
＋ B 的知识编辑部与成果气质
＋ C 的多视角动态反馈
```

混合时必须重新检查：

- 图形语义是否矛盾；
- Token 是否出现多套主色；
- 组件是否像来自不同产品；
- 动效是否增加认知负担；
- 品牌是否仍能形成单一记忆点。

## 8. 用户决策输出

比较完成后，用户需要明确选择：

- 最终基础方向：0 / A / B / C / 混合；
- Logo 方向；
- App Icon 方向；
- 页面主视觉。

决策必须写入 [`pr-08f-integration-decisions.md`](../../planning/pr-08f-integration-decisions.md)，并同步更新品牌与页面验收规格。
