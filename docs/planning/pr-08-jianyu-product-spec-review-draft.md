## 3. 产品定义与对象模型

### 3.1 正式产品定义

> 见域是一款面向个人的多智能体思考与行动工作台。用户围绕持续议题，调用人物视角、专业顾问、任务助手和工作流能力，通过自由追问与分阶段推进，沉淀判断、行动方案和知识成果。

### 3.2 核心对象

```text
问题是入口
Skill 是能力载体
议题是持续容器
阶段是议题内推进节点
圆桌是多 Skill 协作形式
成果是判断、行动方案、知识笔记或可交付内容
```

对象关系：

- 用户从问题开始，不要求先理解 Agent、Skill 或工作流；
- Skill 提供人物视角、专业顾问、任务助手或工作流能力；
- 议题持续承载背景、资料、对话、阶段、分歧、行动和成果；
- 阶段围绕一个明确目标推进；
- 圆桌只是多 Skill 的协作形式，不等于整个产品；
- “轮次”只描述一次响应批次，不是最高层产品对象。

## 4. 两类核心价值

正式名称为：

### 4.1 现实支持

处理生活、学习和工作中的具体事情，例如任务拆解、规划、沟通、研究、写作、核查、决策和成果交付。

### 4.2 思维拓展

引入不同人物、领域、立场、反方意见和思维模型，帮助用户重新理解问题、发现盲区和拓展认知边界。

### 4.3 使用规则

- 用户可跳过、单独选择或组合；
- 同一议题可在两类方向之间反复切换；
- 两类不是永久标签；
- 两类不自动形成两条独立议题线；
- 首页不得强迫用户先选分类；
- “生活与工作”“思维与视角”“现实行动”不是正式名称。

## 5. 单 Skill、多 Skill 与推荐

### 5.1 单 Skill

适合明确问题、垂直任务和持续咨询。

### 5.2 多 Skill

适合复杂议题、重大决策、长期成长和跨领域协作。

### 5.3 切换和历史规则

- 单 Skill 可邀请其他 Skill，升级为多 Skill；
- 多 Skill 中点名某个 Skill 只产生临时定向回答；
- 临时定向回答不自动退出多 Skill；
- Skill 增删不删除历史回答、资料或成果；
- 中途加入 Skill 使用可编辑议题简报，不默认传递全部原始聊天；
- 系统推荐 Skill 时提供候选和理由；
- 只有用户确认后才加入。

### 5.4 V1 Skill 范围

- 只提供官方内置 Skill；
- 不支持用户创建 Skill；
- 不支持第三方导入；
- 不提供公开市场；
- 原有人物型 Skill 全部保留；
- 纳入研究目录全部 25 个条目；
- “张雪峰视角”去重后约 44 个官方候选；
- 最终接入以来源、许可证、能力重复、安全和 Android 可行为准；
- 首页不平铺全部候选，通过问题推荐、分类、搜索和筛选发现。

### 5.5 特殊 Skill 边界

“Windows 文档生产力助手”可以进入候选池，但 Android 无法执行的桌面自动化不得伪装为可执行功能。

原“规避 AIGC 检测类”转化为“原创表达与写作自然化助手”，禁止：

- 绕过检测或审查；
- 隐瞒不允许的 AI 使用；
- 伪造经历、数据、引用或作者身份；
- 承诺无法被检测；
- 提供针对检测系统的对抗技巧。

## 6. 议题、阶段与推进议题

### 6.1 议题

议题是持续容器，承载：

- 背景和约束；
- 对话和协作；
- 已确认资料；
- 阶段节点；
- 判断、分歧和行动；
- 已保存成果。

一个议题保持单一主线。需要独立处理时，由用户显式创建或关联新议题。

### 6.2 自由追问

自由追问用于补充、质疑、澄清或深入当前阶段目标，不创建新阶段。

### 6.3 推进议题

正式入口名称为 **推进议题**。

入口规则：

- 始终可用；
- 阶段成熟时可以增强提示和说明理由；
- 用户可以忽略提示并继续自由追问；
- 打开入口不创建新阶段；
- 取消或返回不改变原阶段；
- 不强迫用户必须先完成当前阶段；
- 不等于让全部 Skill 重新回答；
- “下一轮”只作为历史术语。

### 6.4 三步确认

1. **选择推进方向**
2. **选择具体措施或自定义目标**
3. **确认下一阶段摘要**

只有第三步最终确认后才创建新阶段。

第三步至少展示：

- 下一阶段目标；
- 方向和措施；
- 默认继承内容；
- 当前或调整后的 Skill 阵容；
- 重点资料；
- 预期输出形式。

### 6.5 正式方向和措施

**思维拓展**

- 引入反方意见；
- 查找遗漏视角；
- 检查关键假设；
- 比较不同立场；
- 深入某个问题；
- 自定义目标。

**现实支持**

- 明确下一步；
- 形成执行计划；
- 分析执行阻碍；
- 生成成果交付；
- 设置检查节点；
- 自定义目标。

### 6.6 默认继承与调整

默认继承：

- 议题背景；
- 已确认资料；
- 已保存成果；
- 当前 Skill 阵容；
- 已形成判断；
- 主要分歧；
- 当前行动项。

用户可调整：

- 下一阶段目标；
- Skill；
- 资料；
- 输出形式。

### 6.7 阶段关系

- 新阶段仍属于原议题；
- 旧阶段完整保存；
- 不覆盖原阶段的目标、消息、资料、判断、分歧、行动或成果；
- 一个议题保持单一主线；
- 不自动创建分支议题；
- 不自动复制互相冲突的历史副本；
- 阶段历史保留来源、目标、继承和成果关系。

## 7. 圆桌、交叉讨论与结果

### 7.1 默认协作

- 多 Skill 默认分别独立回应；
- 交叉讨论不是默认自动流程；
- 交叉讨论必须由用户显式触发；
- 用户选择参与者和讨论焦点；
- 完成一轮后由系统整合。

### 7.2 结果结构

圆桌不投票裁决真理。结果应包含：

- 共识；
- 分歧；
- 适用条件；
- 明确建议；
- 下一步。

系统可以给出推荐和理由，但用户保留最终决定权。高风险事项必须说明条件、不确定性和信息时效。

## 8. 资料、成果、归档与个人背景

### 8.1 资料与成果

采用“议题内管理 + 全局汇总”：

- 议题内管理对话、资料、成果和阶段；
- 全局资料库和成果库支持跨议题搜索与复用；
- 内容保留原议题、阶段、Skill 和来源关系；
- 音频作为成果的一种输出形式；
- 阶段总结先生成草稿，用户编辑确认后才保存为正式成果；
- 默认先生成通用总结，再可转为行动方案、决策记录、知识笔记或交付稿。

### 8.2 归档和关联

- 议题由用户主动归档；
- 系统可以提示但不能自动归档或删除；
- 相似问题可以继续原议题、基于归档创建关联新议题或创建全新议题；
- 关联新议题带入可编辑议题简报和可调整 Skill，不默认复制全部原始聊天；
- 基于归档继续时提示用户补充“现在有什么变化”；
- 原归档简报不被后续内容改写。

### 8.3 个人背景

- 以可见、可编辑、可选择的独立条目管理；
- 系统可推荐相关背景，但默认不勾选；
- 只有用户主动加入并确认后才保存长期信息；
- 支持编辑、停用、归档和删除；
- 普通删除不改写历史议题；
- 彻底清除前展示影响范围并二次确认；
- 部分引用可精确移除或替换；
- 清除后使用不泄露原文和敏感类别的匿名占位。

## 9. 本地保存、应用锁与加密备份

### 9.1 保存模型

- V1 本地保存；
- 不做账号和自动云同步；
- 支持手动导入导出。

### 9.2 应用锁和本地库

- 应用锁可选；
- 支持生物识别或应用 PIN；
- 本地库由设备安全密钥保护；
- 本地库保护与应用锁相互独立。

### 9.3 加密导出

- 导出文件始终加密；
- 使用独立备份密码；
- 密保问题只作辅助；
- 忘记备份密码后不能用密保重置或解密；
- 修改备份密码需要原密码；
- 改密码生成新备份，不覆盖唯一旧备份；
- 新备份自动校验；
- 可以在隔离空间执行验证导入。

### 9.4 导入、快照与回退

第 35～49 题已由第 62 题整体批准：

1. 相同数据自动去重；
2. 差异版本由用户选择当前、备份或两者；
3. 不静默覆盖冲突数据；
4. 替换当前库前创建并验证恢复快照；
5. 导入预览先分类汇总，再展开逐项差异；
6. 导入先在隔离区完成解密、结构和完整性校验；
7. 正式写入采用全有或全无的原子操作；
8. 任一步失败不得修改当前库；
9. 错误信息展示失败阶段、数据是否受影响和下一步；
10. 快照保留到用户主动删除；
11. 本地操作记录不得包含正文、密码或敏感内容；
12. 快照由设备安全密钥保护；
13. 显示单份和总占用，容量不足只提醒；
14. 回退前创建并验证“回退前快照”；
15. 快照记录名称、来源、时间、数据量、大小和可选备注；
16. 快照不包含备份密码或应用锁凭据；
17. 损坏快照保留并标记不可用；
18. 快照创建后立即验证，恢复前再次验证；
19. 支持手动快照和备注；
20. 加密导出默认不包含设备绑定恢复快照。

这些结论冻结用户可见行为和数据安全目标，不提前冻结 Room Schema、算法、文件格式、容量阈值或事务实现。

## 10. 高风险问题

医疗、法律、金融等高风险问题采用分级响应，不完全禁止。

- 提供一般信息、分析框架和可核查依据；
- 说明信息时效、适用条件和不确定性；
- 不作诊断、正式法律意见、收益保证或专业执照意见；
- 重要决定前提示具备资质的专业人员复核；
- 紧急、人身安全或重大不可逆场景优先提示现实帮助；
- 不自动执行决定；
- 高风险 Skill 披露来源、限制、能力边界和信息时效。
