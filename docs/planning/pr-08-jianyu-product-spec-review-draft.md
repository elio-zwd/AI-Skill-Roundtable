# 1. 已确认核心决策

## 1.1 品牌与产品定位

- **主品牌：见域。**
- **口号：看见更多观点，打开认知边界。**
- 组合显示：**见域｜看见更多观点，打开认知边界**。
- 产品定位：

> 见域是一款面向个人的多智能体思考与行动工作台。用户围绕持续议题，调用不同专业视角与工作流能力，经过自由追问和分阶段推进，沉淀判断、行动方案与知识成果。

- 产品不再以“20 位名人聊天 App”或“AI 智囊圆桌”作为最高层定义。
- 圆桌只是多 Skill 协作形式，不等于整个产品。

## 1.2 两类使用价值

### 现实支持

处理生活、学习和工作中真实发生的事情，例如任务拆解、规划、沟通、研究、写作、决策和成果交付。

### 思维拓展

引入不同人物、领域、立场、反方意见和思维模型，帮助用户重新理解问题、发现盲区并拓展认知边界。

### 跨界规则

- 两类价值不是互斥模式；
- 同一议题可以从现实支持进入思维拓展，也可以反向进入现实行动；
- 切换时不强制拆分议题，不丢失背景、资料、判断和行动记录；
- 界面可以提示当前推进意图，但不能给整条议题贴上不可变化的永久分类。

对应决定：第 2、4、52 题及“议题推进结构”补充讨论。

## 1.3 核心产品对象

```text
问题：用户进入产品的自然入口
Skill：人物视角、专业顾问、任务助手和工作流能力的统一载体
议题：持续承载背景、资料、对话、阶段、判断、行动和成果的容器
单 Skill：明确问题或持续咨询的使用模式
多 Skill：处理复杂议题的协作模式
圆桌：多 Skill 的主要协作形式
阶段推进：同一议题从当前目标进入下一个明确目标
成果：经用户确认保存的判断、方案、行动、笔记或交付稿
个人背景：由用户控制、可选择带入不同议题的长期信息条目
```

## 1.4 首页与议题创建

已确认首页采用“问题优先”的组合入口：

- 用户可以直接描述问题；
- “现实支持”“思维拓展”作为可选辅助方向，可不选、单选或组合使用；
- 用户可以主动选择或调整 Skill；
- 系统可以根据问题推荐模式和 Skill；
- 系统推荐后先进入确认步骤，用户可增删、替换、关闭推荐，再开始正式议题；
- 不强制用户先理解或选择单 Skill、多 Skill、现实支持、思维拓展等内部结构。

对应决定：第 2、3 题；第 53、54 题沿用这些既有决定，不新增独立结论。

## 1.5 第一版 Skill 边界

- 第一版只提供**官方内置 Skill**；
- 支持搜索、筛选、自由组合、邀请和中途调整；
- 第一版不支持用户创建、导入或保存自定义 Skill；
- 第一版不建设公开 Skill 市场；
- “考公规划”“主管任务拆解”等垂直能力，可以作为官方精选 Skill 逐步纳入；
- 真实人物型 Skill 必须明确 AI 模拟、信息来源和时效边界。

对应决定：第 7、51 题。

## 1.6 单 Skill 与多 Skill

- 单 Skill 与多 Skill 是并列使用模式；
- 单 Skill 可邀请其他 Skill，升级为多 Skill；
- 多 Skill 圆桌中点名某个 Skill，只代表本次定向回答，不会自动退出圆桌；
- 用户希望长期只与某个 Skill 深聊时，应执行明确的“转为单 Skill 持续咨询”动作；
- 模式调整不丢失同一议题的背景、资料、历史回答、阶段结论和成果。

对应决定：第 1、12 题。

## 1.7 多 Skill 回应规则

- 首次进入多 Skill 圆桌时，可让已选 Skill 建立初始不同视角；
- 后续自由追问，系统默认选择与当前问题相关的 Skill 回应；
- 用户可指定一个或多个 Skill 回应；
- 指定多个 Skill 时，用户可自行排序，也可使用系统按相关度排序；
- 多个 Skill 默认先分别独立回应，保留清楚的角色归属；
- 系统不得未经用户操作自动增删圆桌 Skill；
- 移除 Skill 只影响后续参与，已有回答和成果继续保留。

对应决定：第 8、9、12、13 题。

## 1.8 交叉讨论

- 交叉讨论必须由用户显式触发；
- 禁止根据普通自然语言语义自动误触发；
- 至少两位 Skill 已独立回应后，用户可点击“发起交叉讨论”；
- 用户选择参与 Skill，并明确讨论焦点；
- 相关 Skill 围绕焦点回应一轮，随后输出整合结果；
- 默认不自动进行无限多轮辩论。

对应决定：第 9、10 题及补充说明。

## 1.9 中途邀请与推荐 Skill

新增 Skill 时：

- 系统先生成一份可查看、可编辑的“议题简报”；
- 简报包含原始问题、已确认背景、当前阶段目标、关键观点与分歧、已保存成果及用户指定材料；
- 不默认把全部原始聊天记录直接交给新 Skill；
- 用户确认议题简报后，才可邀请新 Skill。

推荐 Skill 时：

- 必须由用户点击“推荐 Skill”触发；
- 只有议题简报确认后才能使用；
- 推荐结果展示候选 Skill 与推荐理由；
- 用户可以选择一个或多个候选，再逐个确认邀请；
- 系统不得自动将候选加入圆桌。

对应决定：第 11～13 题。

## 1.10 自由追问与议题阶段推进

- 自由追问始终是一级操作，用于在当前目标中补充、质疑、深挖或点名 Skill；
- 原称“下一轮”的能力不等于继续聊天或让全部 Skill 重复回答；
- 该能力的产品含义是“议题阶段推进”：当前阶段形成结果后，用户主动进入下一个明确目标；
- 推进仍属于同一议题，并继承背景、资料、判断和行动记录；
- 当前暂定总入口名称为“推进议题”，最终名称和位置仍待 UX 设计审核；
- 已确认的两类代表推进意图：
  - 思维方向：**拓展新视角**；
  - 行动方向：**形成行动方案**；
- 两类推进意图可反复切换，不形成两套割裂产品。

对应决定：第 4 题后续讨论及 PR #21。

## 1.11 阶段总结与成果沉淀

- 阶段结束时，系统自动生成简短的“阶段总结草稿”；
- 用户可编辑、修正、删除和补充；
- 用户点击“保存为成果”后，草稿才成为正式成果；
- 未保存草稿不自动堆积到成果区；
- 默认先生成通用阶段总结，再由用户按需要转为：
  - 行动方案；
  - 决策记录；
  - 学习或思考笔记；
  - 汇报、方案或其他交付稿。

对应决定：第 5、6 题。

## 1.12 圆桌收束与建议权

圆桌不通过投票制造唯一结论，也不让某个固定主 Skill 强行裁决。

默认收束结构：

1. 共识；
2. 分歧；
3. 条件化建议；
4. 下一步。

系统应给出明确推荐及依据，但：

- 最终决策权属于用户；
- 不自动替用户执行重要决定；
- 高风险事项必须说明不确定性、适用条件和信息来源；
- 不得把 AI 建议描述为真实人物意见、专业执照意见或保证结果。

对应决定：第 50、55 题。

## 1.13 议题归档、恢复与重复识别

- 议题只能由用户主动归档；
- 系统可以提示，但不得自动归档、删除或结束；
- 归档后保留对话、Skill、简报和成果，可搜索、查看和恢复。

发现新问题与既有议题相近时：

- 系统提示相关进行中或已归档议题，不自动合并；
- 用户可选择：
  1. 继续原对话；
  2. 基于归档议题开启新对话；
  3. 仍然创建全新议题。

基于归档开启新对话时：

- 带入可编辑的完整议题简报；
- 默认继承原 Skill 组合，但允许调整；
- 不直接带入全部原始聊天记录；
- 引导用户补充“现在有什么变化”；
- 原归档简报保持不变；
- 新对话单独保存当前变化和更新后的简报；
- 新旧议题保留关联，但旧结论不自动视为当前事实。

对应决定：第 14～18 题。

## 1.14 个人背景

- 个人背景由独立条目组成，并带分类标签；
- 支持查看、编辑、停用、归档和删除；
- 新建议题时，系统可推荐相关背景，但默认不勾选；
- 用户手动确认后，背景才会带入议题；
- 系统不得默认使用全部历史记忆；
- 新的长期信息只有在用户主动点击“加入个人背景”后，才生成可编辑草稿；
- 用户确认后才保存，系统不得自动从对话中写入长期背景；
- 停用或归档条目不再用于未来推荐，但已有历史议题不受影响。

对应决定：第 19～22 题。

# 2. 第一版范围与明确不做

## 2.1 第一版范围

第一版产品规格应覆盖：

1. 问题优先的首页入口；
2. 官方内置 Skill 的发现、选择、推荐与确认；
3. 单 Skill 咨询与多 Skill 圆桌；
4. 单转多、圆桌内定向回答和中途调整；
5. 显式交叉讨论；
6. 自由追问与议题阶段推进；
7. 可编辑的议题简报和阶段总结；
8. 成果保存与类型转换；
9. 议题归档、恢复、关联新对话和重复议题提示；
10. 用户可控的个人背景；
11. 本地加密、精确清除、加密导入导出和恢复快照；
12. 高风险建议的不确定性、条件和来源提示；
13. 旧会话和旧 Skill 的兼容迁移规划。

## 2.2 第一版明确不做

- 不支持用户创建、导入或保存自定义 Skill；
- 不建设公开 Skill 市场；
- 不做账号体系和自动云同步；
- 不自动使用所有历史信息；
- 不自动从对话提取并写入个人背景；
- 不自动增删 Skill；
- 不通过语义自动触发交叉讨论；
- 不自动合并相似议题；
- 不自动归档、自动删除议题或恢复快照；
- 不将现实支持与思维拓展强制拆为两个议题；
- 不要求用户先选择模式或分类才能提问；
- 不用 Skill 投票替代用户决策；
- 不由系统自动执行高风险决定；
- 不把所有原始聊天记录默认交给新加入 Skill；
- 不在 PR08 规格冻结前修改生产代码；
- 不在本轮确定 Room Schema、加密算法、数据库迁移或 Kotlin 类型；
- 不在完成商标、应用商店、域名和重名核验前宣称“见域”可以正式商用。

# 3. 默认实现方案（待审核）

> 本章不是已冻结产品事实。审核通过后，才可转为 PR08-B、C、D、E 的输入。

## 3.1 首页默认结构

建议采用：

1. 主入口：自然语言问题输入；
2. 辅助项：现实支持／思维拓展方向标签，可跳过；
3. 辅助项：选择 Skill；
4. 内容区：最近议题、已归档议题入口和官方 Skill 发现入口；
5. 提交问题后显示推荐确认面板，不直接进入正式对话。

系统可默认推荐 1～3 个 Skill，但数量不是核心冻结项，需结合成本、首屏长度与问题复杂度测试。

## 3.2 推荐确认默认结构

建议展示：

- 系统理解的问题摘要；
- 推荐使用单 Skill 或多 Skill 的理由；
- 推荐 Skill、角色类型与推荐原因；
- 用户增删、替换、排序或全部关闭的操作；
- “开始议题”明确确认动作。

## 3.3 议题工作区默认结构

建议至少包含：

- 当前议题标题与阶段目标；
- 当前参与 Skill；
- 消息与独立回应时间线；
- 自由追问输入；
- 阶段总结草稿；
- “推进议题”入口；
- 资料、成果与历史阶段入口。

“推进议题”的最终位置、名称和承载方式仍由 PR08-B 与 PR08-D 联合提出方案，不在本文冻结。

## 3.4 非核心导入、恢复与快照默认值

以下内容来自第 35～49 题。用户曾选择推荐方案，但随后要求统一作为非核心默认方案审核，因此状态统一为“待审核”：

1. 完全相同的数据自动去重；有差异时逐项选择保留当前版本、备份版本或两者；
2. 用备份替换当前库前，强制创建当前库恢复快照；
3. 导入预览先显示分类汇总，展开后显示逐项差异；
4. 导入先在隔离区完成解密、结构和完整性校验；正式写入采用全有或全无；
5. 任一步失败不修改当前本地库，并显示失败阶段与可读错误；
6. 恢复快照一直保留，直到用户主动删除；
7. 仅在本地记录不含正文、密码和敏感内容的操作摘要；
8. 恢复快照始终使用设备安全密钥加密；
9. 显示单份快照大小和总占用，达到阈值只提醒，不自动删除；
10. 从快照回退前，先创建“回退前快照”，再隔离校验和原子替换；
11. 快照由系统生成明确名称、来源、创建时间、数据量和大小，用户可添加备注；
12. 快照保存完整加密本地库副本，不包含备份密码和应用锁凭据；
13. 损坏快照保留并标记为不可用，说明原因，由用户决定是否删除；
14. 快照创建后立即验证；查看详情或准备恢复时再次验证；
15. 允许用户手动创建快照并添加备注；
16. 加密导出备份默认只包含当前本地库，不包含恢复快照。

## 3.5 默认错误与恢复原则

- 所有导入、替换、回退先在隔离空间验证；
- 关键数据写入采用原子操作；
- 不通过吞掉错误或删除旧数据制造“成功”；
- 用户可见错误应说明发生阶段、当前数据是否受影响以及下一步；
- 任何自动建议都不能绕过用户确认。

# 4. 隐私、加密、清除、备份、导入与恢复规则

## 4.1 存储边界

- 第一版默认仅本地保存；
- 支持手动导出和导入；
- 暂不做账号云同步或应用云备份；
- 本地库默认使用设备安全密钥加密，与应用锁是否开启无关；
- 密钥保存在系统安全存储中，不写入应用普通文件；
- 卸载应用、清除应用数据或设备安全密钥丢失后，未导出的数据不可恢复。

对应决定：第 27、29 题。

## 4.2 应用锁

- 支持可选应用锁，默认不强制开启；
- 可使用设备生物识别或应用 PIN；
- 应用锁保护“谁能进入应用”，本地库加密保护“数据库文件被复制后的可读性”；
- 应用锁 PIN 不应依赖云端账号找回；
- 应用锁与备份密码是两套不同凭据。

对应决定：第 28 题。

## 4.3 个人背景删除与彻底清除

普通删除：

- 从个人背景列表移除条目；
- 历史议题保留当时的上下文快照，避免改写过去判断依据。

彻底清除：

- 用户主动选择并二次确认；
- 先展示影响范围，再按层级清除；
- 必须清除个人背景原条目；
- 默认清除自动生成的议题简报、阶段总结和上下文快照中的相关内容；
- 用户手写消息和用户编辑成果，必须额外明确勾选才清除；
- 自动生成内容只涉及部分信息时，默认精确移除或替换相关片段，也可选择删除整份；
- 局部清除后保留匿名占位，例如：`[已按用户请求清除，日期]`；
- 占位不显示原文或敏感信息类别；
- 彻底清除后不保留应用内可恢复原文副本。

对应决定：第 23～26 题。

## 4.4 加密导出备份

- 导出文件始终加密；
- 用户设置独立备份密码；
- 备份密码不等于应用锁 PIN，不上传、不自动回显；
- 忘记备份密码时无法解密恢复；
- 密保问题只能作为可选提示或修改密码时的二次确认；
- 密保答案不能在忘记原密码后直接重置备份密码；
- 修改备份密码必须验证原密码；
- 修改后重新生成一份新密码备份，不覆盖原文件；
- 新备份先自动完成解密与结构完整性校验；
- 用户可选择在临时隔离空间进行验证导入，不覆盖当前库。

对应决定：第 30～33 题。

## 4.5 导入

- 导入前先解密、校验并预览差异；
- 当前库已有数据时，用户选择“合并”或“用备份替换当前库”；
- 替换前提示保护当前数据，并按待审核默认方案创建恢复快照；
- 正式导入前不得修改当前库；
- 详细冲突、原子写入和快照规则见第 3.4 节，待集中审核。

对应决定：第 34 题；第 35～49 题作为待审核默认方案。

# 5. 议题、Skill、圆桌收束与成果沉淀规则

## 5.1 议题生命周期

```text
提出问题
→ 确认问题理解、模式和 Skill
→ 创建议题
→ 自由追问与独立回应
→ 可选交叉讨论
→ 形成阶段总结草稿
→ 编辑并保存成果
→ 继续当前阶段 / 推进议题 / 主动归档
→ 恢复原对话或基于归档开启关联新对话
```

## 5.2 Skill 生命周期

```text
系统推荐或用户选择
→ 用户确认加入
→ 参与独立回应
→ 可被点名、排序或参与交叉讨论
→ 用户可中途移除
→ 历史回答继续保留
```

新增 Skill 必须经过议题简报确认；推荐 Skill 必须由用户点击触发并逐个确认邀请。

## 5.3 圆桌收束

每次需要收束时，输出：

- 共识；
- 分歧；
- 条件化建议；
- 下一步。

系统可以提出倾向性建议，但必须展示理由、条件和不确定性；用户保留最终决定权。

## 5.4 成果生命周期

```text
系统生成阶段总结草稿
→ 用户编辑、修正和补充
→ 用户选择成果类型
→ 用户点击保存为成果
→ 成果进入议题并可后续更新、引用或导出
```

未点击保存的草稿不得被描述为正式成果。

# 7. 可验证验收标准

## 7.1 产品与入口

- [ ] 首页允许用户直接输入问题，不要求先选模式或分类；
- [ ] 用户可主动选择 Skill，也可查看系统推荐；

- [ ] 第一版界面不出现创建、导入或公开发布自定义 Skill 的入口。

## 7.2 单／多 Skill 与圆桌

- [ ] 单 Skill 可在不丢失上下文的情况下邀请其他 Skill；
- [ ] 多 Skill 中点名一个 Skill 不会自动退出圆桌；
- [ ] 用户可以指定多个 Skill 和回复顺序；
- [ ] 系统不得未经用户确认自动增删 Skill；
- [ ] 交叉讨论只能由显式操作触发；
- [ ] 交叉讨论要求用户确认参与者和焦点；
- [ ] 圆桌收束包含共识、分歧、条件化建议和下一步。

- [ ] 自由追问和议题阶段推进是两个不同动作；
