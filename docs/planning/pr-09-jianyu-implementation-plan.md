# PR09：见域生产实施总计划

> 状态：PR08-F 输出的正式实施计划。
>
> 启动门禁：PR08-F Draft PR 完成只读验收并经用户明确批准后，才能从合并后的最新 `main` 创建生产分支。
>
> 本文描述后续实施，不表示当前 Android App 已完成迁移。

## 1. 目标

把当前“AI 智囊圆桌”Android 工程分批迁移为“见域”，在不迁移旧包数据的前提下，建立新的应用身份、领域模型、导航、Skill 目录、执行运行、资料成果、阶段推进和安全导入导出能力。

## 2. 冻结输入

### 产品与身份

```text
App：见域
口号：看见更多观点，打开认知边界
applicationId：com.elio.jianyu
namespace：优先同步为 com.elio.jianyu
目标仓库：jianyu-workbench
目标官网：jianyu.my-elio.online
旧 App：不保留
旧包数据：不迁移
```

### 产品对象

- 议题是持续容器；
- 阶段是议题内推进节点；
- 响应批次与 `roundIndex` 不等于阶段；
- 执行运行需要显式建模；
- 资料、消息、阶段总结草稿、正式成果和导出文件分离；
- 单 Skill 与多 Skill 并列；
- 显式交叉讨论默认单次生效；
- 推进议题采用三步确认；
- 未运行新阶段允许撤销；
- 草稿跨进程持久保存；
- 普通删除进入无自动过期回收站；
- 运行中归档需要显式选择；
- V1 允许保存官方 Skill 组合，不开放自定义 Skill。

## 3. 实施原则

1. 每个对话只负责一个任务、一个分支和一个 PR；
2. 不直接修改默认分支；
3. 每个 PR 从当时最新稳定 `main` 创建；
4. 数据模型、导航壳、执行调度和导入替换属于不可并行域；
5. UI、Skill 目录和独立成果组件只有在接口冻结后才能并行；
6. 优先测试驱动：先写失败场景和契约测试，再实现；
7. 不为通过检查而删除测试、降低断言或吞掉异常；
8. 未执行的测试必须标记为未验证；
9. 任何包名、仓库名、DNS 或发布动作都需要独立授权；
10. 最终视觉未确认前，不提交正式 Logo、App Icon 和完整品牌资源迁移。

## 4. 阶段划分

### PR09-01：新应用身份与构建基座

目标：建立 `com.elio.jianyu` 新应用身份和可复现构建基线。

范围：

- `applicationId`；
- `namespace`；
- Kotlin 主源码与测试包路径；
- Manifest、Activity、资源引用；
- Room Schema 输出路径；
- ADB 脚本、品牌检查、CI、R8 和构建产物名称；
- 新沙箱启动验证。

禁止：

- 旧包数据迁移；
- 同时重构领域模型；
- 提前落地未确认视觉资产；
- 仓库改名和 DNS。

完成条件：

- Debug / Release 构建成功；
- 单元测试、Lint、Migration Test 和 Instrumentation Test 通过；
- 新包可独立安装；
- 旧包存在时互不覆盖；
- 新包首次启动为空数据库；
- Key 需要重新配置。

回滚：回滚该 PR 即恢复旧应用身份；由于未迁移旧数据，不做数据回滚。

### PR09-02：领域模型与 Room Schema

目标：显式建立议题、阶段、执行运行、资料、草稿、成果、参与者快照、个人背景、Skill 组合和回收站模型。

建议领域关系：

```text
Issue
├─ Stage
│  ├─ Message
│  ├─ ExecutionRun
│  ├─ StageParticipantSnapshot
│  ├─ MaterialReference
│  ├─ StageSummaryDraft
│  └─ Result
├─ SavedSkillSet
├─ PersonalContextUsage
└─ Archive / Trash metadata
```

PR08-F 不冻结表名和字段；本 PR 必须先用测试证明：

- 议题和阶段关系；
- `roundIndex` 仅为响应批次；
- 草稿持久化；
- 未运行阶段撤销；
- 回收站恢复；
- 彻底清除级联边界；
- 新沙箱没有旧包 Migration。

不可并行：Repository、导航和执行运行不得在 Schema 未冻结前自行定义重复模型。

### PR09-03：Repository、事务与进程恢复

目标：建立领域 Repository、事务边界、状态恢复和幂等写入。

必须覆盖：

- 仅保存议题；
- 新阶段创建与撤销；
- 阶段总结草稿保存和放弃；
- 成果确认；
- 归档、恢复和关联新议题；
- 回收站与彻底清除；
- 运行状态重建；
- 部分成功保留；
- 失败重试不重复成功成员。

测试：事务失败注入、进程重建、重复提交、并发点击、数据库异常和附件缺失。

### PR09-04：导航壳与一级目的地

目标：把当前旧 Route 迁移为目标产品导航。

目标目的地：

- 首页；
- 议题；
- Skill；
- 资料与成果；
- 设置作为全局次级入口。

必须实现：

- 深链；
- 返回栈；
- 归档和回收站入口；
- “资料 / 成果”页内 Tab；
- 旧 `testTag` 到新标签的兼容映射。

不实现完整业务页面，只建立可测试壳和占位状态。

### PR09-05：官方 Skill 目录与推荐基础

目标：建立四类 Skill、发布状态、来源、风险、推荐理由和保存官方 Skill 组合。

范围：

- 目录 Schema；
- 44 项候选的状态台账；
- 现有 20 项人物 Skill 搜索和正常自动推荐资格；
- 人物非本人声明；
- 发布门禁；
- 最近使用、收藏和 Skill 组合；
- V1.0 / V1.1 状态字段。

禁止：

- 依据人物争议或风险标签降低排名；
- 把未通过门禁的候选标为可执行；
- 用户创建或导入 Skill；
- 未审计地复制第三方正文。

### PR09-06：推荐确认与首页议题创建

目标：实现问题优先首页、方向选择、推荐确认和仅保存议题。

必须覆盖：

- 现实支持 / 思维拓展双方向卡，可跳过、单选或组合；
- 获取建议；
- 保存议题但不运行；
- 推荐理由；
- Skill 增删替换；
- 资料与个人背景确认；
- 用户确认前不创建运行。

### PR09-07：单 Skill 与多 Skill 执行运行

目标：把现有调度基础迁移为显式 `ExecutionRun`。

必须保留或重建：

- 顺序执行；
- 请求预算；
- 流式占位；
- 停止；
- 部分成功；
- 全部失败；
- 原位重试；
- 进程恢复；
- 成功成员不重复执行。

`roundIndex` 只表示响应批次。

### PR09-08：临时点名与显式交叉讨论

目标：实现多 Skill 中单次点名和单次交叉讨论。

规则：

- 选择参与者和焦点；
- 默认只作用于当前指令；
- 完成后恢复独立回应；
- 不自动把全部资料、背景或其他输出发送给参与者；
- 记录本次实际使用的上下文；
- 输出保留共识、分歧、条件和下一步。

### PR09-09：资料、个人背景与来源时效

目标：建立资料库、议题关联、个人背景显式带入、来源和时效核验。

必须覆盖：

- 资料授权；
- 敏感材料最小化；
- 本次实际使用的背景展示；
- 来源和日期；
- 联网必需 / 可选 / 禁止；
- 资料失败不破坏议题；
- 页面和单项错误分离。

### PR09-10：阶段总结草稿、成果与音频资产

目标：实现草稿持久化、用户确认成果和独立音频资产。

必须覆盖：

- 草稿跨 Activity / 进程重建；
- 无自动过期；
- 保存为成果；
- 主动放弃；
- 无成果直接推进；
- 成果与议题、阶段、资料和 Skill 关系；
- 音频作为可关联资产，不继续只是 `Message` 可选字段；
- 导出文件不等于新成果。

### PR09-11：推进议题与阶段时间线

目标：实现正式“推进议题”三步流程。

步骤：

1. 方向；
2. 措施或自定义目标；
3. 下一阶段摘要、Skill、资料、背景和预期输出确认。

必须覆盖：

- 入口始终可用；
- 两类方向组合仍创建单一阶段；
- 取消不改变当前阶段；
- 最终确认后创建新阶段；
- 未运行新阶段可撤销且无倒计时；
- 一旦运行改用停止或后续推进；
- 旧阶段完整保留。

### PR09-12：归档、回收站与彻底清除

目标：实现归档恢复、运行中归档选择和无自动过期回收站。

必须覆盖：

- 等待完成后归档；
- 停止生成并归档；
- 恢复原议题；
- 创建关联新议题；
- 普通删除进入回收站；
- 回收站不自动过期；
- 容量不足只提醒；
- 彻底清除明确不可恢复范围。

### PR09-13：加密导出与设备绑定快照

目标：分别实现可移植加密导出和设备绑定恢复快照。

必须先冻结并测试：

- 威胁模型；
- 密钥派生与加密参数；
- 版本兼容；
- 完整性校验；
- 快照创建和恢复前验证；
- 手动快照和备注；
- 回退前快照；
- 容量不足提示；
- 加密导出默认不包含设备快照。

安全参数必须由专门评审决定，不从 PR08 文档直接推断。

### PR09-14：隔离导入、差异与原子替换

目标：实现导入隔离校验、差异展示、用户冲突选择和可回退替换。

必须覆盖：

- 临时隔离区；
- 格式、版本、完整性和安全校验；
- 相同数据自动去重；
- 冲突数据用户选择；
- 替换前已验证快照；
- Room、WAL/SHM、附件和后台任务一致性；
- 失败不修改当前库；
- 显示失败阶段和错误；
- 故障注入和原子切换回退。

### PR09-15：隐私、Key、遥测与高风险收口

目标：统一 API Key、隐私、遥测、来源时效和高风险响应。

必须覆盖：

- 新包 Key 重新配置；
- Key 不进入日志、导出或遥测；
- 遥测默认和同意边界；
- 个人背景和敏感资料最小化；
- 医疗、法律、金融、心理和紧急安全响应；
- 人物风险不等于推荐降权；
- 去AI化助手固定边界和诚信门禁。

### PR09-16：品牌视觉与页面实现

启动条件：最终视觉方向已经用户确认。

范围：

- Compose Token；
- Logo、App Icon、启动页和关于页；
- 首页、推荐确认、议题工作区、推进面板、时间线和资料成果页面；
- 明暗主题；
- 窄屏；
- 字体放大；
- TalkBack；
- 减少动效；
- Adaptive Icon 和通知图标。

禁止在候选未确认时把 A“开域窗”当作最终资产。

### PR09-17：端到端回归与发布准备

目标：完成全链路测试、性能、安全、可访问性和发布门禁。

必须覆盖：

- 首页到议题运行；
- 单 / 多 Skill；
- 点名和交叉讨论；
- 自由追问和推进议题；
- 草稿、成果和音频；
- 归档、回收站和恢复；
- 导出、快照、导入和回退；
- 进程重建；
- 离线、无 Key、限流和服务失败；
- 性能、内存、数据库和大数据量；
- 无障碍；
- 隐私和敏感信息扫描。

### PR09-18：仓库、官网与正式发布管理员阶段

需要用户单独授权：

- 仓库改名为 `jianyu-workbench`；
- 更新本地 `origin`、README、Badge、Release 和外部链接；
- 部署 `jianyu.my-elio.online`；
- DNS、HTTPS、`/privacy`、`/terms`、`/docs`、`/releases` 和下载入口；
- 正式签名、发布渠道和应用商店信息。

该阶段不能与核心代码重构并行。

## 6. 并行规则

### 绝对串行

- PR09-01、02、03、04；
- PR09-07 与执行运行模型相关修改；
- PR09-13、14；
- PR09-17；
- PR09-18。

### 接口冻结后可有限并行

- PR09-05 Skill 目录；
- PR09-09 资料与背景；
- PR09-10 成果与音频；
- PR09-16 视觉组件。

并行任务不得修改同一 Entity、DAO、Route、共享状态机或应用主题根文件。

## 7. 每个 PR 的统一门禁

每个实现 PR 必须包含：

- 目标和非目标；
- Base SHA；
- 修改文件范围；
- 领域契约；
- 失败场景；
- 自动化测试；
- 手动验收步骤；
- 数据兼容和回滚；
- CI 证据；
- 未验证项；
- 给本地 AI 的只读验收 Prompt。

未经用户明确授权，不合并 PR，不删除分支，不修改仓库设置、DNS 或服务器。
