## 1. 目标与边界

把当前“AI 智囊圆桌”Android 工程分批迁移为“见域”，在不迁移旧包数据的前提下，建立新应用身份、领域模型、导航、Skill 目录、执行运行、资料成果、阶段推进和安全导入导出能力。

本文保留 PR09-01～18 作为**能力域编号**，便于需求追踪；实际施工按依赖拆成 22 个原子步骤。编号不代表可以按数字机械执行。

PR09 不得：

- 重新询问或推翻已确认的第 1～62 题、PR #24 五项决定和 PR08-F 七项决定；
- 设计旧包 `com.elio.skillroundtable` 到新包的数据桥接；
- 在最终视觉确认前落地正式 Logo、App Icon 或完整品牌资产；PR09-01～15 可先实施，PR09-16 与 17 必须等待视觉门禁；
- 在路线图中提前冻结 Room 表名、字段、Kotlin 类型、KDF、AEAD 或原子替换算法；
- 把路线图直接当作修改代码的施工单。

## 2. 启动门禁

每个实施步骤必须同时满足：

1. 上游 PR 已合并，并重新核对最新 `main` SHA；
2. 从该 SHA 创建独立分支和 Draft PR；
3. 检查开放 PR、文件所有权和不可并行域；
4. 在该实施分支先建立精确执行计划，至少写明：
   - 准确的创建、修改和测试文件路径；
   - 消费与产出的接口、状态和数据契约；
   - 首个失败测试、预期失败原因和通过条件；
   - 原子提交边界；
   - 构建、测试、静态检查与人工验收命令；
   - 故障注入、进程恢复和回滚步骤；
   - 独占文件与禁止触碰文件；
   - 未验证项；
5. 计划通过只读复核后才写生产代码；
6. 完成前执行 `verification-before-completion`，不得复用旧 Head 的证据。

执行计划不得保留影响施工的 `TODO`、`TBD` 或未选择候选。若实际文件结构在上游 PR 中变化，以当时仓库为准，不能从本路线图臆造路径。

## 3. 全程安全不变量

隐私、Key、遥测、来源时效和高风险边界从 PR09-01 起就是每个 PR 的验收条件，不等到 PR09-15 才补：

- Key、备份密码、应用锁凭据、个人背景正文和敏感资料不得进入日志、遥测、导出元数据或测试夹具；
- 新包 Key 必须重新配置；
- 资料和个人背景按最小必要范围传递，并记录本次实际使用内容；
- 医疗、法律、金融、心理和紧急安全响应必须保留条件、不确定性和转介边界；
- 人物风险标签不得变成推荐降权；
- “去AI化助手”的名称与诚信边界必须在所有用户可见入口同时出现；
- 每个数据写入 PR 都要覆盖失败不丢失、重试幂等和进程重建；
- 每个 PR 都要执行秘密扫描并明确遥测变化。

PR09-15 只负责全局审计和遗漏收口，不负责首次建立这些约束。

## 5. 分阶段施工契约

### 5.1 PR09-01：应用身份

- **输入**：PR08-F 合并后的最新 `main`；目标 `applicationId` / `namespace`；不迁移旧包数据。
- **输出**：`com.elio.jianyu` 可构建、可安装、空沙箱启动的工程基座；源码与测试包路径、Manifest、CI、脚本和 Schema 输出配置一致。
- **文件域**：Gradle、Manifest、Kotlin 包路径、资源引用、构建脚本、CI 和开发脚本；独占这些根配置文件。
- **独立验收**：Debug / Release、单测、Lint、Instrumentation、新旧包并存、新包首次启动为空、Key 需重新配置。
- **失败测试**：旧包数据或 Key 被新包读取；Manifest / Provider 仍引用旧包；R8 或测试包路径失配。
- **回滚**：整 PR 回滚到旧应用身份；没有跨包数据回滚。
- **大小判断**：大但内聚；禁止夹带领域重构和正式视觉资产。

### 5.2 PR09-02A：核心领域 Schema

- **输入**：01；规范性产品对象。
- **输出**：Issue、Stage、Message、ExecutionRun、参与者快照的最小关系与 DAO 契约。
- **文件域**：核心 Entity、DAO、Database、Schema 导出和数据库测试；独占数据库根定义。
- **独立验收**：`roundIndex` 只表示响应批次；Stage 与 Run 可分别恢复；外键、索引和事务失败测试通过。
- **失败测试**：把响应批次当阶段；重复运行写入；孤儿 Stage / Run；进程重建状态歧义。
- **回滚**：在未进入后续长期测试前回滚整个初始 Schema；发布后必须使用 Migration。
- **大小判断**：原 02 过大，拆出核心运行模型。

### 5.3 PR09-02B：资源与生命周期 Schema

- **输入**：02A 已合并接口。
- **输出**：资料引用、个人背景使用记录、阶段总结草稿、成果、音频资产引用、官方 Skill 组合、归档与回收站元数据。
- **文件域**：资源与生命周期 Entity / DAO、关系测试；不得改写 02A 核心语义。
- **独立验收**：草稿持久化、组合保存官方成员、顺序和可选默认职责、回收站恢复、彻底清除边界可表达。
- **失败测试**：删除背景改写历史；草稿自动过期；默认职责改写官方 Skill 边界；组合保存自定义 Skill；资产产生孤儿引用。
- **回滚**：回滚 02B；若 02A 已进入下游，不回退 02A。
- **大小判断**：与 02A 串行，避免一次冻结全部 Schema。

### 5.4 PR09-03：Repository 与恢复

- **输入**：02A、02B。
- **输出**：领域 Repository、事务边界、幂等写入和进程恢复接口；不包含完整页面。
- **文件域**：Repository、事务协调、恢复适配器和对应测试；独占写事务。
- **独立验收**：仅保存议题、阶段创建/撤销、草稿保存/放弃、成果确认、归档/恢复、回收站和部分成功均可由契约测试验收。
- **失败测试**：双击重复提交、事务中断、附件缺失、数据库异常、重试重复成功成员、进程回收后重复创建。
- **回滚**：保留 Schema，回滚 Repository 适配层；不得以直接 DAO 调用形成第二套业务路径。
- **大小判断**：较大；只做数据与恢复接口，页面和调度留给后续。

### 5.5 PR09-04：导航壳

- **输入**：03 的只读/写入入口与目标信息架构。
- **输出**：首页、议题、Skill、资料与成果、设置次级入口的 Route 壳、深链和返回栈；业务页面使用占位状态。
- **文件域**：顶层 App、navigation、Route 壳和导航测试；独占根导航图。
- **独立验收**：五类目的地、资料/成果 Tab、归档/回收站入口、深链、返回栈和旧 `testTag` 兼容映射。
- **失败测试**：深链打开错误 Tab；进程恢复后返回栈错乱；旧标签静默改义；占位页触发业务写入。
- **回滚**：回滚新导航壳并恢复上一个入口；不回滚 Repository。
- **并行**：可与 05 有限并行，但 05 不得修改根导航。

### 5.6 PR09-05：Skill 目录

- **输入**：02B 的官方组合契约、03 的 Repository 接口和 44 项 Skill 台账。
- **输出**：四类 Skill、发布状态、来源、风险、推荐元数据、收藏/最近使用和官方组合目录。
- **文件域**：Skill 领域、目录数据、目录页面与测试；通过 04 预留接口接入，不直接改根导航。
- **独立验收**：44 项状态真实；20 项人物 Skill 可发现且不因风险降权；未过门禁项目不可执行；组合可保存可选默认职责但不能改写官方 Skill 或包含自定义 Skill。
- **失败测试**：风险标签影响排名；未发布 Skill 可调用；缺少人物非本人声明；“去AI化助手”缺少就近诚信边界。
- **回滚**：回滚目录实现，保留 02B 存储契约。
- **并行**：只与 04 有限并行。

### 5.7 PR09-07：执行运行

- **输入**：03、04、05；现有 Gemini 调用链的已验证事实。
- **输出**：显式 ExecutionRun 状态机，支持单/多 Skill、顺序执行、预算、流式、停止、部分成功、原位重试和进程恢复。
- **文件域**：执行调度、网络编排、运行 ViewModel / Route 和运行测试；独占执行状态机。
- **独立验收**：成功成员不重复执行；停止与失败状态持久；`roundIndex != Stage`；无 Key / 离线 / 限流可恢复。
- **失败测试**：停止后仍写入；进程重建重复扣预算；重试全部成员；流式占位永不终结；日志泄露 Key。
- **回滚**：以单一兼容适配层回退到旧调用链；兼容层在本阶段结束前指定删除阶段，不保留两套入口。
- **大小判断**：高风险且不可并行。

### 5.8 PR09-09：资料与个人背景

- **输入**：03、07；资料和背景产品契约。
- **输出**：资料库/关联、背景库/议题显式带入、来源日期、联网条件和实际使用记录。
- **文件域**：material / personal-context 领域、授权适配、页面与测试；独占上下文组装接口。
- **独立验收**：背景默认不勾选；只发送确认内容；资料失败不破坏议题；编辑、停用、归档、删除和彻底清除边界一致。
- **失败测试**：全量背景静默传递；删除改写历史；敏感类别出现在匿名占位；资料失败升级为页面全失败。
- **回滚**：关闭新上下文入口并保留底层记录；禁止退回静默全量传递。

### 5.9 PR09-10A：草稿与成果

- **输入**：03、07、09。
- **输出**：阶段总结草稿持久化、通用总结到成果的用户确认、成果来源链和无成果直接推进接口。
- **文件域**：draft / result 领域、Repository 适配、页面和测试；独占成果确认事务。
- **独立验收**：Activity / 进程重建后草稿仍在；草稿不自动过期；只有确认后才成为成果；导出文件不是成果类型。
- **失败测试**：恢复时草稿自动升级；保存失败丢草稿；放弃误删正式成果；无成果推进被阻断。
- **回滚**：回滚成果 UI/适配，保留已持久化草稿；提供版本兼容读取。
- **大小判断**：原 10 过大，先完成文本草稿和成果。

### 5.10 PR09-10B：音频资产

- **输入**：10A 的成果接口和 02B 的资产关系。
- **输出**：音频作为独立可关联资产，具备生命周期、错误隔离和来源关系。
- **文件域**：音频存储、后台任务、成果关联和测试；不得重写 10A 成果状态机。
- **独立验收**：音频失败不影响文本成果；删除/恢复/彻底清除无孤儿文件；进程重建任务可恢复。
- **失败测试**：附件缺失、任务取消、空间不足、重复生成、成果删除后的孤儿文件。
- **回滚**：关闭音频入口并保留可识别资产元数据，随后由受控清理任务处理。

### 5.11 PR09-06：首页与推荐

- **输入**：04、05、07、09；仅保存议题与用户确认规则。
- **输出**：问题优先首页、双方向卡、获取建议、推荐确认、仅保存议题和开始运行闭环。

## 6. 共享文件与不可并行域

| 域 | 独占阶段 | 规则 |
|---|---|---|
| Gradle / Manifest / 包路径 / CI | 01 | 后续确需修改时必须说明为何不属于 01 遗漏 |
| Database / Entity / DAO / Schema | 02A、02B 串行 | 03 以后不得绕过所有权新增平行模型 |

| 根导航与 `ui/App.kt` | 04 | 页面阶段通过预留 Route 接口接入 |
| 执行状态机 | 07 | 08、11、12 只能消费或提交独立接口变更 |
| 上下文组装 | 09 | 06、08 不得自行拼接全量背景 |

需要跨域修改时，实施计划必须写出单一整合提交和所有者；不得让两个开放 PR 同时修改同一核心文件。

## 7. 中间兼容层

只允许为降低迁移风险建立以下短期兼容层：

- 01 的旧包引用编译映射；
- 04 的旧/新 `testTag` 映射；
- 07 的旧调度到 ExecutionRun 适配；
- 11 的历史“下一轮”数据读取适配；
- 13B / 14 的备份格式版本读取适配。

每个兼容层必须有真实调用方、测试、删除条件和最晚删除阶段。禁止保留新旧两套页面入口、Repository 或状态机。

## 8. 每个 PR 的完成输出

每个实施 PR 必须报告：Base、Head、分支、提交、净文件范围、契约变化、失败测试、实际命令和退出码、CI、未验证项、风险、回滚点、兼容层状态、下一阶段可消费接口，以及本地 AI 只读验收 Prompt。

未经用户明确授权，不标记 Ready、不合并、不删除分支、不修改仓库设置、DNS 或服务器。
