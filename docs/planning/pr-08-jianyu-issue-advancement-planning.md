## 2. 产品对象与正式术语

### 2.1 议题与阶段

- **议题**是持续容器，承载背景、资料、协作过程、判断、分歧、行动和成果；
- **阶段**是同一议题内围绕一个明确目标展开的推进节点；
- 一个议题保持单一主线，可连续建立多个阶段；
- 新阶段不会覆盖、改写或删除旧阶段。

### 2.2 自由追问与推进议题

| 行为 | 正式用途 | 是否创建新阶段 |
|---|---|---|
| 自由追问 | 补充、质疑、澄清或深入当前阶段目标 | 否 |
| 推进议题 | 建立一个新的明确阶段目标 | 仅在最终确认后创建 |
| 新议题 | 处理与当前主线不同、需要独立承载的问题 | 创建新的议题，不属于本流程 |

“推进议题”不能被描述为让所有角色再次回答、重复当前讨论或自动执行固定工作流。

“下一轮”只可作为历史术语出现，不再作为当前正式功能名称；“轮次”只可描述模型或成员的一次响应批次，不是最高层产品对象。

## 3. 入口与提示规则

正式入口名称为：**推进议题**。

入口规则：

1. 入口始终可用，不要求用户先完成阶段总结、保存成果或满足系统判定；
2. 当当前阶段成果较成熟时，系统可以增强提示并解释推荐理由；
3. 用户可以忽略提示、继续自由追问或随时主动推进；
4. 打开入口本身不会创建新阶段；
5. 用户返回、取消或关闭确认流程时，原阶段保持不变；
6. 不强迫用户必须“完成当前阶段”才能继续使用议题。

系统可以推荐推进方向、措施或 Skill，但推荐只提供候选与理由，必须由用户确认。

---

## 4. 三步确认流程

推进议题采用轻量三步确认。只有第三步完成最终确认后，系统才在原议题中创建新阶段。

### 第一步：选择推进方向

用户选择本次新阶段的主要方向：

- **思维拓展**；
- **现实支持**。

两类方向可在同一议题中反复切换，也可以跨界组合，不是互斥模式、永久标签或两条独立议题线。

### 第二步：选择具体措施或自定义目标

用户选择预设措施，或填写自己的下一阶段目标。预设措施只用于帮助表达目标，不替代用户确认。

### 第三步：确认下一阶段摘要

确认摘要至少展示：

- 下一阶段目标；
- 选择的方向和措施；
- 默认继承的内容；
- 当前或调整后的 Skill 阵容；
- 使用的重点资料；
- 预期输出形式。

用户可以返回前一步修改。只有明确确认后才创建新阶段；取消流程不生成空阶段、草稿阶段或重复历史副本。

---

## 5. 推进方向与具体措施

### 5.1 思维拓展

用于重新理解问题、发现盲区、检查论证或深化关键部分。

可提供：

- 引入反方意见；
- 查找遗漏视角；
- 检查关键假设；
- 比较不同立场；
- 深入某个问题；
- 自定义目标。

### 5.2 现实支持

用于把已有理解转化为可执行、可检查或可交付的结果。

可提供：

- 明确下一步；
- 形成执行计划；
- 分析执行阻碍；
- 生成成果交付；
- 设置检查节点；
- 自定义目标。

“生活与工作”“思维与视角”“现实行动”均不是本流程的正式分类名称。界面可以为“现实支持”“思维拓展”提供通俗说明，但不得替换正式术语或把两类设计成割裂产品。

---

## 6. 默认继承与用户可调整内容

### 6.1 默认继承

进入新阶段时默认继承：

- 议题背景；
- 已确认资料；
- 已保存成果；
- 当前 Skill 阵容；
- 已形成判断；
- 主要分歧；
- 当前行动项。

继承表示这些内容继续可用并保留来源关系，不表示把历史内容复制为多个独立副本。

### 6.2 用户可以调整

用户在确认前可以调整：

- 下一阶段目标；
- Skill；
- 资料；
- 输出形式。

Skill 的邀请、移除、替换、单 Skill 与多 Skill 切换均不是推进议题的必经条件。系统推荐 Skill 时必须说明理由并由用户确认；调整 Skill 不删除旧阶段回答、资料或成果。

多 Skill 中点名某个 Skill 只产生临时定向回答，不自动退出多 Skill 协作，也不自动创建新阶段。

---

## 7. 阶段关系与历史保留

创建新阶段后必须满足：

1. 新阶段仍属于原议题；
2. 旧阶段完整保存并可回顾；
3. 新阶段不覆盖原阶段的目标、消息、资料、判断、分歧、行动或成果；
4. 一个议题保持单一主线，阶段按明确关系连续推进；
5. 系统不自动创建分支议题；
6. 系统不自动把历史内容复制成多个互相冲突的副本；
7. 需要独立主线时，由用户显式创建或关联新议题；
8. 阶段历史应保留来源、目标、继承关系和已保存成果的可追溯关系。

本节冻结产品语义，不提前规定 Room Schema、Kotlin 类型、数据库表、存储格式或迁移算法。

---

## 8. 与 Skill、圆桌和成果的关系

- 自由追问继续当前阶段，不因回复次数自动升级为新阶段；
- 推进议题建立新目标，不要求所有 Skill 重新发言；
- 新阶段可沿用当前 Skill，也可由用户调整阵容；
- 多 Skill 圆桌仍不通过投票裁决真理；
- 阶段结果可收束为共识、分歧、适用条件、明确建议和下一步；
- 预期输出可以是判断、行动方案、知识笔记或可交付内容；
- 系统生成的阶段总结或成果草稿需由用户确认后，才成为正式保存成果。
