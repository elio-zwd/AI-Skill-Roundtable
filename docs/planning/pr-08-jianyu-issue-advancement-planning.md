## 1. 已确认结论

原称“下一轮”的功能，不应理解为“让 AI 再回复一次”或“自动进入固定流程”。

它的产品定位是：**议题阶段推进**。当用户认为当前讨论已经获得阶段性结果时，可以在不离开同一议题的前提下，明确选择接下来要推进的目标。

用户界面先以一个总入口承接该行为，暂定名称为：**推进议题**。

进入后，用户先选择本次推进的意图：

| 类别 | 作用 | 已确认的代表入口 |
|---|---|---|
| 思维拓展 | 继续理解问题、发现盲区、比较立场或思维模型 | 拓展新视角 |
| 现实行动 | 将已有讨论转化为可执行或可交付的工作 | 形成行动方案 |

这两个类别是“本次推进的意图”，不是给议题贴上的永久标签，也不取代“现实支持 / 思维拓展”两类核心价值。任一议题可以在两类推进意图之间反复切换。

## 2. 与自由追问、新议题的分工

| 行为 | 适用时机 | 对上下文的处理 |
|---|---|---|
| 自由追问 | 仍在当前目标内补充背景、质疑、深挖、点名某个 Skill | 保持当前阶段和议题上下文 |
| 推进议题 | 当前目标已形成阶段性结果，准备进入一个新的明确目标 | 保持同一议题；继承对话、资料、结论和行动记录 |
| 新议题 | 用户开始处理与当前问题无关的新问题 | 新建独立上下文，不默认继承原议题 |

因此，“推进议题”不替代输入框；自由追问必须继续是一级操作。

## 3. 推进后的最小语义

每一次推进至少应能明确：

1. **来源**：承接哪个议题及其已形成的阶段性结果；
2. **目标**：用户这次想把议题推进到什么方向；
3. **继承**：哪些背景、资料、结论和行动记录继续可用。

Skill 阵容是否变化、是否从单 Skill 升级为多 Skill、是否从多 Skill 中临时指定一个回答者，均为可选动作，不是点击“推进议题”的必经条件。

已确认的模式规则仍然适用：

- 多 Skill 中临时点名某个 Skill，只是“本轮定向回答”，不自动退出圆桌；
- 若用户想长期只与该 Skill 深聊，应使用单独的“转为单 Skill 持续咨询”动作；
- 两种情况都保留同一议题的既有上下文。

## 4. 后续需要单独讨论的具体措施

以下内容尚未冻结，必须由后续独立对话提出方案并由用户确认，不能在本文中擅自决定：

| 讨论项 | 需要确定的内容 |
|---|---|
| 总入口呈现 | “推进议题”放在输入区、阶段总结卡、更多菜单或其他位置；采用按钮、底部面板或其他承载方式 |
| 思维拓展措施 | 除“拓展新视角”外，是否提供反方核查、深入分析、换角度、证据比较等；各自的触发条件和 Skill 推荐规则 |
| 现实行动措施 | 除“形成行动方案”外，是否提供下一步拆解、成果交付、解决阻碍等；各自的产出结构与适用场景 |
| 系统建议边界 | 系统何时建议推进、如何说明理由、是否允许用户完全跳过建议 |
| 阶段结束标准 | 用户如何确认“当前阶段已够用”；是否需要阶段总结、保存或命名 |
| 目标输入方式 | 用户自由填写、选择预设、接受系统建议或组合使用的具体流程 |
| Skill 调整流程 | 推进时如何邀请、移除、替换 Skill，及推荐与人工选择的关系 |
| 成果沉淀 | 推进前后如何展示和保存判断、行动、资料、可交付内容与未决问题 |
| 异常与恢复 | 生成失败、用户停止、部分 Skill 失败、离线或恢复议题时的产品行为 |
| 文案与视觉 | 两类推进意图的最终名称、层级、图标、状态和无障碍表达 |

## 5. 对 PR08 后续任务的约束

### PR08-B：信息架构与核心交互

PR08-B 应将本文作为已确认输入，完成两类推进意图的完整用户流程、状态矩阵和返回路径。PR08-B 不得把“推进议题”重新定义为“重复发言”或固定工作流。

### PR08-C：Skill 分类、发现与推荐

PR08-C 应支持在推进时按当前目标推荐或由用户主动调整 Skills；推荐理由必须可解释，且不应因为选择某一类推进意图而限制跨界能力。

### PR08-D：品牌与视觉设计系统

PR08-D 应让“思维拓展”和“现实行动”容易区分，但避免设计成两套割裂的产品。本文不锁定颜色、图标或页面布局。

### PR08-E：技术影响与 PR09 迁移评估

PR08-E 应评估“阶段推进”对现有会话、消息、轮次、资料、行动和成果模型的影响，但不得在没有最终规格前提前锁定 Room Schema 或生产实现。

## 6. 后续讨论的完成条件

后续独立讨论完成时，至少应产出：

- 每个类别下保留哪些具体推进措施，以及不做哪些；
- 每项措施的触发条件、用户可见文案、输入和预期结果；
- 用户自选 Skill 与系统推荐在各流程中的位置；
- 单 / 多 Skill、跨界推进与阶段上下文的保持规则；
- 空、加载、失败、停止、恢复和历史继续的行为；
- 可由 PR08-B、C、D、E 分别吸收的明确输入。

在这些内容经过用户确认前，本文的“已确认结论”以外部分均应视为待决，不得直接进入 PR09 生产代码。
