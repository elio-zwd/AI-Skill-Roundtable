## 2. 第 56 题：推进议题入口与阶段推进流程

**状态：已确认，56.1～56.4 均选择 A。**

第 56 题冻结到“产品行为与信息层级”的颗粒度，不在本阶段冻结像素级视觉、具体控件样式和动画。

### 2.1 入口可用时机

采用“始终可用，阶段成熟时重点提示”：

- 用户在议题工作区中始终可以找到“推进议题”入口；
- 当系统判断当前阶段已经形成阶段性结论、明确分歧或可行动结果时，可在阶段总结附近增强提示；
- 用户不需要等待系统许可才能推进；
- 系统不得强制用户推进，也不得自动结束当前阶段；
- 用户仍可选择继续自由追问、保存成果、调整 Skill 或暂不推进。

“推进议题”暂时继续作为规格名称。最终用户可见文案可由 PR08-D 提出优化方案，但不得改变其“进入下一阶段目标”的产品含义。

### 2.2 与自由追问的关系

- **自由追问**：继续补充、质疑、深挖或澄清当前阶段目标；
- **推进议题**：在当前阶段已有一定结果后，切换到一个新的明确阶段目标；
- 两者都是一级能力，不互相替代；
- 普通自然语言输入不得被系统擅自解释为阶段推进；
- 阶段推进必须经过用户显式操作和最终确认。

### 2.3 轻量分步面板

点击“推进议题”后采用轻量分步面板：

1. 选择推进方向：
   - **拓展新视角**；
   - **形成行动方案**。
2. 选择具体措施，或直接填写自定义推进目标；
3. 查看并确认下一阶段摘要：
   - 下一阶段目标；
   - 参与 Skill；
   - 重点资料；
   - 预期成果。

只有用户完成确认后，系统才创建下一阶段。选择方向或措施本身不得立即切换阶段，避免误触和上下文丢失。

### 2.4 默认继承与按需调整

推进时默认继承：

- 当前议题背景；
- 已确认资料；
- 已保存成果；
- 当前 Skill 组合；
- 当前阶段已形成的关键判断、分歧和行动记录。

用户在确认前可以：

- 修改下一阶段目标；
- 增加、移除或调整参与 Skill；
- 选择下一阶段重点使用的资料和成果；
- 选择或修改预期成果类型；
- 返回上一步或取消推进。

默认继承用于降低操作成本，不代表所有历史原文都必须重新发送给模型。具体上下文压缩、议题简报和隐私边界由 PR08-B、PR08-C、PR08-E 进一步设计。

### 2.5 同一议题下新增阶段节点

推进完成后：

- 新阶段仍属于原议题，不自动创建独立议题；
- 旧阶段完整保留，不被新目标覆盖或改写；
- 新阶段拥有独立的阶段目标、参与过程、阶段总结草稿和成果；
- 用户可以通过阶段时间线查看和回顾旧阶段；
- 回看旧阶段不等于回滚当前阶段，也不会删除后续内容；
- 一个议题可以连续拥有多个阶段，并在思维与行动方向之间反复切换；
- 归档和关联新议题仍按第 14～18 题规则处理，不与阶段推进混用。

### 2.6 留给后续设计的自由度

本决定暂不冻结：

- 入口在页面中的精确坐标；
- 按钮颜色、图标、尺寸和动画；
- 使用底部面板、侧边面板或其他轻量承载方式；
- 提示文案的最终措辞；
- 阶段时间线的具体视觉样式。

但 PR08-B 与 PR08-D 的方案必须满足：

- 入口持续可发现；
- 阶段成熟时能在阶段总结附近获得更明显提示；
- 不与自由追问混淆；
- 不跳过用户确认；
- 不把轻量推进设计成复杂的新建议题流程。

本决定覆盖规格审阅稿第 6.1 节中“推进议题最终名称、位置和承载方式仍待确认”的原状态。最终视觉稿可调整名称和承载样式，但不得改变上述行为契约。

## 3. 第 57 题：推进方向与具体措施

**状态：已确认，选择 A。**

采用“两个主要方向 + 展开具体措施”的结构。

默认只展示两个主要方向：

1. **拓展新视角**；
2. **形成行动方案**。

### 3.1 拓展新视角

展开后可选择：

- 听取反方意见；
- 补充遗漏视角；
- 检查关键假设；
- 比较不同立场；
- 深入某个问题。

### 3.2 形成行动方案

展开后可选择：

- 拆解下一步；
- 制定执行计划；
- 解决当前阻碍；
- 准备成果交付；
- 明确检查节点。

### 3.3 自定义目标

- 用户可以不使用预设措施，直接填写本次推进目标；
- 预设措施用于降低操作成本，不得限制议题实际方向；
- 两个方向可在同一议题中反复切换，不自动拆分议题；
- 推进后继续继承背景、资料、判断、行动记录和已保存成果。

本决定覆盖规格审阅稿第 6.1 节中“具体措施清单仍待确认”的原状态。

## 4. 第 58 题：两类价值的用户可见名称

**状态：已确认，选择 A。**

正式名称继续使用：

- **现实支持**；
- **思维拓展**。

界面应搭配通俗说明：

- 现实支持：解决事情、形成行动；
- 思维拓展：发现盲区、打开视角。

补充规则：

- 两类价值不是互斥分类；
- 用户可以不选、单选或组合使用；
- 同一议题可以在两类价值之间自然切换；
- 不得给整条议题加上不可变化的永久分类；
- 首页不得强迫用户先选择价值方向才能提问。

本决定覆盖规格审阅稿第 6.1 节中“两类价值最终展示名称仍待确认”的原状态。

## 5. 第 59 题：第一版官方内置 Skill 规模

**状态：已确认。**

第一版官方内置 Skill 采用“原有人物型 Skill + 新研究目录全部候选”的组合方案。

### 5.1 总体范围

- 原有约 20 个人物型 Skill 全部保留；
- 纳入 `docs/skills/research-catalog/catalog/skills-catalog.json` 中的全部 25 个目录条目；
- 其中“张雪峰视角”与现有 App 资产重复，接入时去重；
- 去重后的官方内置候选总规模约为 44 个；
- 最终实际数量以 PR08-C 的逐项核验结果为准，不因重复资产、许可证或安全问题虚报数量；
- 第一版仍不支持用户创建、导入或公开 Skill 市场。

### 5.2 类型结构

官方内置 Skill 至少分为：

1. **人物视角**：原有人物角色，主要提供不同人物、领域和立场视角；
2. **专业顾问**：职业、学习、消费、产品、健康管理等专业支持；
3. **任务助手**：会议、写作、研究、沟通、交接等具体任务处理；
4. **工作流能力**：合同检查、软著、专利、Office 文档等结构化流程。

所有 Skill 可以拥有多个标签，不强制只属于一个分类。

### 5.3 展示与推荐

- 首页不得平铺全部约 44 个 Skill；
- 系统根据用户问题推荐少量相关 Skill；
- 用户可进入完整目录搜索、筛选、查看和主动选择；
- 完整目录按人物视角、专业顾问、任务助手、工作流能力及业务标签组织；
- 推荐不得自动加入议题，仍需用户确认；
- 原有人物型 Skill 与新增任务型 Skill 应共同出现在产品体系中，分别体现“看得更广”和“把事做完”。

### 5.4 Windows 文档生产力助手

原目录中标记为 `research-only` 的“Windows 文档生产力助手”纳入官方候选池：

- 用于 Word、Excel、PPT 等文档工作流规划、内容组织和质量检查；
- Android 端无法直接执行的桌面自动化能力不得伪装成可执行功能；
- PR08-E 必须评估移动端可用范围、外部文件处理、脚本依赖、许可证和隐私风险；
- 无法在移动端安全执行的部分，可以保留为操作指导、检查清单或成果生成能力。

### 5.5 原“规避 AIGC 检测类”的合规转化

原目录中的“规避 AIGC 检测类”不以绕过检测或规避审查的名称和目标直接上线，而是转化为：

> **原创表达与写作自然化助手**

允许的能力：

- 改善机械、重复和不自然的表达；
- 帮助用户澄清自己的观点、补充真实经历和证据；
- 调整结构、语气、可读性和个人表达；
- 检查事实、引用和原创性声明；
- 提醒用户遵守学校、单位、平台和出版要求。

明确禁止：

- 以绕过 AIGC 检测、抄袭检测、学术审查或招聘筛选为目标；
- 伪造个人经历、研究数据、引用、作者身份或原创过程；
- 帮助用户隐瞒不允许的 AI 使用；
- 承诺“无法被检测”或提供针对检测系统的对抗技巧。

PR08-C 应为该 Skill 重新编写原创说明、名称、边界和安全测试，不得直接复用上游规避检测提示词。

### 5.6 接入门禁

全部候选在进入生产实现前必须逐项完成：

- 重复能力和资产去重；
- 来源、许可证和可使用范围核验；
- Skill 名称、职责、输入输出和适用场景定义；
- 高风险等级与提示规则；
- 隐私、外部文件、真实人物模拟和内容安全检查；
- 至少一组正常场景、边界场景和拒绝场景测试设计。

本决定覆盖规格审阅稿第 6.1 节中“第一版官方内置 Skill 最终清单仍待确认”的原状态。逐项清单与接入优先级由 PR08-C 输出，PR08-F 最终整合。

## 6. 第 60 题：资料、成果与音频的信息架构

**状态：已确认，选择 A。**

采用“议题内管理 + 全局汇总”的双层信息架构。

### 6.1 议题内管理

每个议题内部至少包含：

- 对话；
- 资料；
- 成果；
- 阶段记录。

资料和成果必须保留与原议题、阶段、Skill 和上下文的关联。

### 6.2 全局汇总

产品提供：

- 全局资料库；
- 全局成果库。

全局视图用于跨议题搜索、筛选、查看和复用，但不能切断内容与原议题的关系。

### 6.3 音频定位

- 音频不再作为独立核心产品对象或孤立内容库；
- 音频作为成果的一种输出形式；
- 阶段总结、行动方案、报告或其他成果可以生成音频版本；
- 音频版本应保留对原成果和原议题的引用关系；
- 现有音频能力的兼容与迁移方案由 PR08-B、PR08-E 和 PR08-F 进一步设计，PR08 不修改生产代码。

本决定覆盖规格审阅稿第 6.1 节中“资料、成果和现有音频库最终位置仍待确认”的原状态。

## 7. 第 61 题：高风险问题处理规则

**状态：已确认，选择 A。**

采用“分级响应，不完全禁止”的原则。

### 7.1 一般风险

职业、学习、工作和普通生活问题可以正常提供分析、建议和行动方案，同时说明关键假设和适用条件。

### 7.2 较高风险

医疗、法律、金融等领域：

- 只提供一般信息、分析框架和可核查依据；
- 明确说明不确定性、适用条件和信息时效；
- 对关键事实提供来源或核查方向；
- 明确建议在重要决策前寻求具备资质的专业人员复核；
- 不得将 AI 输出描述为正式诊断、法律意见、投资保证或专业执照意见。

### 7.3 紧急或重大不可逆风险

涉及紧急危险、严重人身安全风险或重大不可逆决定时：

- 优先提示风险和寻求现实帮助；
- 不自动执行决定；
- 不提供绕过安全、法律或专业审查的操作方案；
- 根据场景提供适当的人工帮助或紧急支持入口。

### 7.4 Skill 边界

- 每个可能进入高风险领域的官方 Skill 必须标注能力边界；
- 系统应根据问题风险选择允许参与的 Skill 和回应方式；
- 来源、限制和时效必须可见；
- 系统可以给出有条件的倾向性建议，但最终决定权属于用户。

本决定覆盖规格审阅稿第 6.1 节中“高风险领域具体处理级别仍待确认”的原状态。引用格式、具体分级阈值和人工复核界面仍由 PR08-C、PR08-D、PR08-E 提出方案，并在 PR08-F 整合。

## 8. 对后续 PR08 的约束

- PR08-B 应据此设计常驻可发现、阶段成熟时增强提示的“推进议题”入口，以及轻量三步确认和阶段时间线；
- PR08-B 应据此设计两层推进措施和议题内／全局双层信息架构；
- PR08-C 应据此整理原有人物型 Skill 与研究目录全部候选，完成去重、分类、来源、许可、风险、展示和推荐方案；
- PR08-C 应将原“规避 AIGC 检测类”重构为合规的“原创表达与写作自然化助手”，不得实现检测规避能力；
- PR08-D 应保留“现实支持／思维拓展”正式名称及通俗说明，并提出“推进议题”的最终文案和轻量承载样式；
- PR08-E 应评估现有音频模块迁移为成果输出形式的兼容成本，并评估 Windows 文档生产力能力在 Android 端的可行范围；
- PR08-F 应把第 56～61 题补充进正式题号索引和最终规格；
- 第 56～61 题均已确认，但本文不构成启动 PR09 的授权；
- PR09 仍必须等 PR08-F 完成并获用户明确批准后开始。
