## 1. 总体实施原则

1. 一个对话只负责一个分支、一个任务和一个 PR。
2. 不直接修改 `main`，不使用未经说明的堆叠分支。
3. PR09 启动时先读取最终 PR08-F、根目录与目标目录 `AGENTS.md`、开放 PR、CI 和最新代码。
4. 先建立可验证完成条件，再写测试，再实现。
5. 身份迁移、核心数据模型和导入替换属于不可并行域。
6. 不把旧包数据迁移、兼容桥或旧 App 保留重新加入范围。
7. 不在功能 PR 中顺带升级 Kotlin、AGP、Compose、Navigation、Room 或网络依赖。
8. 每个 PR 明确测试、回滚、未验证项和对后续 PR 的接口。
9. 数据结构一旦进入共享基线，后续修改必须带 Migration、Schema 和 Migration Test。
10. 仓库改名、DNS 和服务器操作必须独立授权；普通代码 PR 不执行管理员变更。
11. 任何高风险安全结论必须有实际命令、测试、CI 或审计证据。
12. PR09 最终编号和分支名由 PR08-F 冻结；下文编号用于表达依赖顺序。

## 9. PR09-07：定向回应与显式交叉讨论

### 目标

在多 Skill 议题中实现两个独立运行类型，不改变当前阵容或阶段。

### 定向回应

- 用户明确点名一个 Skill；
- 运行参与者只有该 Skill；
- transcript 仍来自当前阶段；
- 完成后保持多 Skill 模式；
- 不创建新阶段；
- 不移除其他 Skill。

### 交叉讨论

- 用户显式打开；
- 选择参与者和焦点；
- 建立一次独立 `CROSS_DISCUSSION` 运行；
- 参与者可看到受控上下文；
- 结束后生成整合结果，但不通过投票裁决真理；
- 输出共识、分歧、适用条件、建议和下一步。

### 测试

- 定向回应不改变阵容；
- 交叉讨论未确认不运行；
- 参与者子集；
- 焦点为空/过长；
- 部分失败；
- 停止和重试；
- 结果关系；
- 历史可回顾；
- 不自动进入下一阶段。

### 回滚

关闭新运行类型入口，保留已写入历史的通用 Run/Message 数据可读。

### 并行约束

不可与单/多 Skill 引擎、Transcript 或预算核心改动并行。

- 类型：判断、行动、知识笔记、交付稿、音频；

- TTS 生成和转码 Worker；
- 文件临时写入、校验、原子重命名；
- 成果库和音频播放；
- 删除与孤儿清理；
- 旧消息音频仅作为当前开发数据，不设计跨包迁移。

### 完成条件

- 总结草稿只有用户确认后成为正式成果；
- 音频可以来源于成果，不强制绑定消息；
- Worker 幂等；
- 数据库与文件状态可恢复；
- 删除成果不会误删仍被引用的资料；
- 音频失败不影响文本成果。

### 测试

- 草稿确认；
- 多版本成果；
- TTS 成功/失败；
- 转码中断和重试；

- 空间不足；
- 删除与孤儿扫描；
- Activity/进程重建后播放状态；
- 音频导出策略。

### 回滚

### 并行约束

## 21. 每个 PR 的本地只读验收 Prompt 必须要求

1. 拉取远端最新代码；
2. 获取目标 Base 和 PR 分支；
3. 检出精确 PR Head SHA；
4. 记录 OS、Shell、Git、JDK、Gradle、Android SDK 和设备版本；
5. 确认工作区干净；
6. 执行 `git diff --name-status Base...Head` 和 `git diff --check Base...Head`；
7. 只进行读取、构建、测试和验收；
8. 不修改文件、不自动格式化、不提交、不推送、不合并；
9. 运行 PR 描述中的命令；
10. 记录每条命令、退出码和关键日志；
11. 核对 CI 属于精确 Head；
12. 报告失败项、复现步骤、第一条根因和可能原因；
13. 将结果反馈给对应远端开发对话。
