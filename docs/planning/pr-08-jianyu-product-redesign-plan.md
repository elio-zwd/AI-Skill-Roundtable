## 2. 已冻结的共享契约

### 2.1 品牌与技术标识

| 类型 | 已确认值 |
|---|---|
| 产品 / App 名称 | **见域** |
| 口号 | **看见更多观点，打开认知边界** |
| 仓库目标名称 | **`jianyu-workbench`** |
| 官网目标域名 | **`jianyu.my-elio.online`** |
| Android `applicationId` 目标 | **`com.elio.jianyu`** |

当前 App 尚未正式发布，因此：

- 不保留旧 App；
- 不迁移旧包数据；
- 不设计旧 Room、Keystore、偏好设置、私有文件或会话的跨包桥接；
- PR09 按全新应用身份完成干净迁移；
- namespace、Kotlin 包路径、Room Schema 路径、CI、脚本和发布元数据优先同步清理旧 `skillroundtable` 技术标识。

### 2.2 产品定位

> 见域是一款面向个人的多智能体思考与行动工作台。用户围绕持续议题，调用人物视角、专业顾问、任务助手和工作流能力，通过自由追问与分阶段推进，沉淀判断、行动方案和知识成果。

### 2.3 两类核心价值

- **现实支持**：处理生活、学习和工作中的具体事情；
- **思维拓展**：引入不同人物、领域、立场和思维模型，发现盲区并拓展认知边界。

两类可跳过、单独或组合使用；不是互斥入口、永久标签或两条独立议题线。

### 2.4 两种使用模式

- **单 Skill**：明确问题、垂直任务或持续咨询；
- **多 Skill**：复杂议题、重大决策、长期成长和跨领域协作。

单 Skill 可升级多 Skill；多 Skill 中点名某个 Skill 只是临时定向回应，不自动退出协作。

### 2.5 议题与阶段

- 问题是入口；
- Skill 是能力载体；
- 议题是持续容器；
- 圆桌是多 Skill 的主要协作形式，不等于整个产品；
- 自由追问继续当前阶段目标；
- “推进议题”进入新的明确阶段目标；
- 新阶段仍属于原议题，旧阶段完整保留；
- 一个议题保持单一主线，不自动分叉。

### 2.6 Skill 边界

- 第一版只提供官方内置 Skill；
- 不支持用户创建、导入或公开市场；
- 原有人物型 Skill 全部保留；
- 纳入研究目录全部 25 个条目；
- 去重后官方候选规模约 44 个；
- 通过问题推荐、分类、搜索和筛选发现；
- 系统只给候选与理由，由用户确认加入。

### 2.7 圆桌结果

圆桌不通过投票裁决，结果收束为：

- 共识；
- 分歧；
- 适用条件；
- 明确建议；
- 下一步行动。

系统可给出推荐及依据，用户保留最终决定权。

### 2.8 资料、成果与安全

- 资料和成果采用议题内管理与全局汇总；
- 音频保留为成果输出形式；
- 阶段总结先生成草稿，用户确认后保存；
- V1 本地保存，不做账号和自动云同步；
- 应用锁可选，本地库由设备安全密钥保护；
- 加密导入导出、冲突预览、隔离校验、原子写入和恢复快照规则按第 27～49 题执行；
- 医疗、法律、金融等高风险问题采用分级响应，不完全禁止，也不作诊断、法律结论或收益保证。

## 5. 设计原则

### 5.1 问题优先

首页先帮助用户表达问题。现实支持、思维拓展和 Skill 选择均为可选辅助，不要求用户理解 Agent 或工作流术语。

### 5.2 用户确认优先

系统可以推荐模式、Skill、资料和推进方向，但加入 Skill、开始议题、推进阶段和保存正式成果都必须由用户确认。

### 5.3 议题持续，阶段可回顾

旧阶段不可被新阶段覆盖。历史阶段、材料、结论、分歧和成果必须可回顾，并保持来源关系。

### 5.4 自由追问与推进议题并列

自由追问不是低级入口，“推进议题”也不是重复所有成员发言。二者分别服务当前目标深化和新阶段目标切换。

### 5.5 Skill 不是名人列表

人物视角、专业顾问、任务助手和工作流能力并列。人物模拟必须披露来源、时效和非本人声明。

### 5.6 从对话走向成果

见域不止展示回复，还要支持阶段总结、行动、资料、知识笔记和可交付内容的保存、更新与复盘。

### 5.7 视觉服务内容

推荐整体气质：

```text
70% 高级生产力工具
20% 智库编辑部
10% AI 动态反馈
```

避免满屏霓虹、复杂仪表盘或只靠头像堆叠表达多智能体。

### 5.8 高风险诚实边界

不把 AI 建议包装成专业结论；明确来源、信息时效、条件、不确定性和需要现实专业帮助的情形。
