## 1. 本阶段目标

完成一条真实可用的资料闭环：

1. 【资料】一级页先展示资料与成果总览；
2. 用户可进入完整资料列表、搜索并查看生命周期状态；
3. 用户可新增链接资料、文本资料或本地文件资料；
4. 用户可打开资料详情、编辑信息、归档、删除、恢复与彻底清除；
5. 资料始终是输入与依据，不会自动成为成果，也不会自动发送给任何 Skill 角色；
6. 现有成果库继续作为独立对象，UI-05 再收口成果详情与“保存为成果”链路。

个人背景不再和资料并列为【资料】页 Tab；它保留现有数据能力，并在 UI-06 迁移到【我的】正式入口。

## 2. 资料主页面

### 2.1 顶部

- 标题：`资料`
- 副标题：`你的依据与沉淀`
- 搜索进入完整资料列表并聚焦搜索框；
- `+` 打开“新增资料” Bottom Sheet。

### 2.2 双概览卡

- 资料卡：展示当前未清除资料数量，说明 `文件、链接与摘录`；
- 成果卡：展示最新正式成果数量，说明 `方案、笔记与文稿`；
- 两卡等权，不展示增长、完成率或伪统计；
- 点击分别进入完整资料列表和成果列表。

### 2.3 最近内容

- 最近资料按 `updatedAt` 倒序，最多 2 项；
- 最近成果按 `confirmedAt` 倒序，最多 2 项；
- 仅展示真实标题、来源类型、时间与已有摘要；
- 不伪造“用于 N 个会话”等当前数据模型无法证明的文案；
- 空状态说明如何新增资料或从对话明确保存成果。

底部固定语义：`只有你明确保存的内容才会成为成果。`

## 3. 新增资料

Bottom Sheet 提供三个入口：

- 上传文件：通过 Android 系统文件选择器选择；导入前显示文件名、类型、大小和可提取状态；
- 添加链接：保存 URL、资料名称、来源名称、备注和敏感标记；保存动作不联网抓取；
- 粘贴文本：保存摘录或文本笔记、标题、正文、来源和敏感标记。

新增资料必须选择当前可用会话作为内部归属；界面称“会话”，不得暴露旧 `issueId`。若没有可用会话，阻止保存并提供返回【对话】开始会话的说明，不创建虚假记录。

文件导入边界：

- 文本、Markdown、CSV、JSON、HTML 读取为本地正文；
- DOCX 只提取标准 `word/document.xml` 文本；
- PDF 必须使用可验证的本地文本提取实现后才标记为可用于对话；无法提取时保留明确失败，不把文件名伪装成正文；
- 读取大小和字符数设上限，失败不写数据库；
- 保存不会自动带入会话或发送给模型。

## 4. 完整资料列表与详情

- 列表支持标题/来源搜索、生命周期筛选和新增；
- 活跃、停用、归档、已删除、待清除、已清除均使用文字与图标，不只靠颜色；
- 资料卡点击进入详情，卡片本身不直接执行删除；
- 详情展示标题、来源类型、来源定位、归属会话、正文预览、敏感状态和更新时间；
- 编辑使用完整页面/全屏容器，不继续使用拥挤的通用 AlertDialog；
- 删除与彻底清除沿用现有 Repository 生命周期和影响范围确认，不新增 destructive migration。

## 5. 状态与失败

- 加载只读本地数据；
- 资料读取失败和成果读取失败互不吞掉另一侧成功内容；
- 搜索无结果与真正空资料分开；
- 保存中禁止重复提交；
- 失败保留表单草稿；
- 系统返回、关闭按钮和取消都不写入；
- 进程重建至少恢复当前列表/总览选择，未确认新增不自动保存。

## 6. 架构与测试

- Route 负责 ViewModel、文件选择器、Toast/Sheet 与导航副作用；
- Screen 只消费不可变 UiState 与事件；
- 文件读取放在独立 importer，不在 Composable 主线程读取；
- 不修改 Room Schema；复用 `MaterialReference`、正式成果聚合器和现有生命周期事务；
- 保留现有稳定 `resources_*` testTag，并为总览、新增 Sheet、资料详情和编辑器补充稳定标签。

必须验证：

- 总览数量和最近排序；
- 资料/成果对象不混淆；
- 链接/文本保存及取消；
- 文件格式、大小、空正文和读取失败；
- 敏感正文不在列表预览泄漏；
- 生命周期恢复/删除/清除；
- 加载、空、无结果、部分失败；
- 编译、单测、Lint、Debug APK 与 AndroidTest APK。

模拟器上的完整交互与视觉证据按用户要求统一留到 UI-09。
