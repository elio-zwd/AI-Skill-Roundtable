# UI-05｜成果确认、列表、筛选与详情实施规格

> 状态：执行基线（依据用户 2026-09-22“完成全部项目并分阶段提交、最终统一模拟器验收”的授权）
>
> 产品基线：ADR-009、术语契约、产品模型与 PRD。

## 1. 本阶段目标

1. 用户在正式会话的节点草稿中显式打开“保存为成果”流程；
2. 只有点击“确认保存”且事务成功后，才创建正式成果；取消、系统返回和失败均不创建成果；
3. 成果库只展示已确认成果，支持搜索、类型筛选和最新/历史版本切换；
4. 成果详情使用二级全屏容器，展示 Markdown 正文、来源会话、对话节点、版本和可验证来源关系；
5. 资料选择继续复用现有执行上下文确认事务：默认不选择、不允许联网、不继承敏感确认；
6. 资料、个人背景、草稿和正式成果保持不同对象语义。

## 2. 保存为成果

- 入口文案统一为“保存为成果”，不再使用“确认正式成果”作为首层动作；
- 使用 Bottom Sheet，不使用拥挤的通用 AlertDialog；
- 标题默认继承当前成果修订标题，否则使用“节点总结”；
- 类型沿用持久化枚举：行动方案、决策记录、知识笔记、交付稿、通用总结；
- 展示准备保存的完整草稿摘要、选定消息数量和来源使用范围；
- 主按钮为“确认保存”，保存中禁止重复提交；
- 底部固定说明：`确认后，这段内容才会成为正式成果。`

当前 `StageResultService` 的原子确认与来源校验继续作为唯一写入口，不新增第二写路径。

## 3. 成果列表与筛选

- 默认只显示每条修订链的最新版本，按保存时间倒序；
- 搜索覆盖标题、摘要、来源会话和对话节点；
- 筛选使用 Bottom Sheet，类型可多选，可显式开启历史版本；
- 空库与筛选无结果分开说明；
- 修订关系异常时保留历史并提示，不把孤儿、循环或分叉伪装成单链；
- 筛选取消不改变已应用条件，重置后恢复默认。

## 4. 成果详情

- 使用全屏 Dialog 容器模拟二级页面，关闭后回到原列表位置；
- 展示标题、`已保存成果`、类型、保存时间、来源会话、对话节点和版本；
- 正文按 Markdown 阅读排版，不截断；
- 来源追溯只展示 Repository 实际恢复的数据；不可用时明确说明，不从正文猜测；
- 支持复制正文和打开来源会话；
- 本阶段不伪造尚未实现的外部导出、分享或成果删除成功状态。

## 5. 对话资料选择与旧链路边界

正式会话执行继续使用现有 `ContextConfirmationDialog`、`prepareExecutionContext` 与使用快照：

- 资料和个人背景默认均不勾选；
- 用户可检查和修改本次精确摘录；
- 联网发送和敏感内容分别确认；
- 超过字符上限时阻止确认，不静默截断；
- 取消不生成使用快照。

首页聊天目前仍由旧 `RoundtableViewModel` / legacy `ChatSession` 驱动，消息级“保存为成果”和“选择资料”尚无可靠的 Issue/Stage 归属与来源事务。UI-05 不以复制文本或 Toast 冒充完成；该链路纳入后续“对话统一”阶段，完成领域会话迁移后再接入同一成果与上下文事务。

## 6. 验证

- 保存 Sheet 的打开、取消、类型切换、保存中门禁和失败保留；
- 成果库搜索、类型、历史版本、空与部分失败；
- 全屏详情、Markdown 正文、复制和来源会话回跳；
- Repository/Service 既有原子确认、来源不匹配回滚和修订分叉测试继续通过；
- `compileDebugKotlin`、`testDebugUnitTest`、`lintDebug`、`assembleDebug`、`assembleDebugAndroidTest`。

模拟器交互与视觉证据按用户要求统一留到最后总验收阶段。
