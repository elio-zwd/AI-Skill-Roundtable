## Frozen product decisions

- 当前 44 项全部作为可发现的 **Skill 角色**进入角色目录。
- 发现 Chip：`全部 / 思考方法 / 职业成长 / 研究学习 / 产品创造 / 沟通表达 / 办公事务 / 生活工具`。
- `生活工具` 包含：预算消费、习惯身心、关系沟通、人情礼仪、传统命理文化陪伴五项主发现入口；分类只是发现入口，不限制跨领域能力。
- 固定 `推荐角色`：
  1. `naval_ravikant` 纳瓦尔
  2. `richard_feynman` 理查德·费曼
  3. `nassim_taleb` 纳西姆·塔勒布
- 上述三项是思想/认知/人生观与精神启发方向的**编辑精选**；不是排名、热度、专业权威或个性化推荐。
- 真人型角色优先复用稳定人物头像，并显示轻量 `AI 模拟角色`；功能型角色使用稳定非真人身份图形，不生成虚构人脸。
- `OfficialSkillCatalog` / execution Manifest 是角色身份、能力、发布与执行资格的权威事实源。
- 旧 Room `Character` 只作为当前 Dialog/Orchestrator 的兼容执行模型，不重新升级成第二套 44 项权威 Catalog。

## Architecture

目标数据流：

```text
OfficialSkillCatalog（44，权威）
       +
SkillRolePresentationCatalog（仅发现分类 / 编辑精选）
       +
旧 Character 可复用视觉补充（仅同 ID 时）
       │
       ▼
SkillRoleCatalogUiState
       │
       ├─ 角色主页面 A/B
       ├─ 搜索 / 收藏 / 最近使用
       └─ 全屏角色详情
                │
                ▼
OfficialSkillConversationRoleAdapter
                │  按需解析并 upsert
                ▼
legacy Character（兼容执行行）
                │
                ▼
RoundtableViewModel participantIds
                │
                ▼
RoundtableOrchestrator / SkillLoader
```

关键原则：**不在 App 启动时把 44 项再次复制成另一套永久配置。** 角色页直接读 Catalog；只有当用户真正开始/加入对话时，才把目标官方 Skill 按需解析为兼容 `Character` 并写入旧表。

这样可以：

- 保留现有消息 `senderId`、participantIds 和 Orchestrator；
- 不新增 Room Schema；
- 不依赖异步 `onCreate` seeding；
- 不让 21～44 因 `skills_config.json` 缺失而无法加入对话；
- 未来迁出旧 Character 时，角色页不需要再次重写数据源。

## Task 6 — 打通 44 项到真实对话的按需兼容链路

**Files**

- Create: `app/src/main/java/com/elio/jianyu/skill/role/OfficialSkillConversationRoleAdapter.kt`
- Modify: `app/src/main/java/com/elio/jianyu/viewmodel/RoundtableViewModel.kt`
- Modify: `app/src/main/java/com/elio/jianyu/ui/App.kt`
- Add tests under `app/src/test/...` and/or `app/src/androidTest/...` following current ViewModel testability patterns.

**Adapter contract**

输入 `OfficialSkillDefinition + optional existing Character`，输出 legacy `Character` 兼容执行行：ID、name、tagline、assetPath/order/executable facts 来自官方 Catalog；同 ID 的稳定人物 avatar/voice 可复用；功能型缺头像时使用确定性非真人 fallback；不复制另一份 Prompt，`systemPrompt` 可继续由运行时从 assetPath 加载。

**Use actions**

- `createNewSessionWithSkillRole(skillId, title): Boolean`：验证官方 ID/执行资格 → ensure compat Character → 创建新会话 → 持久化唯一 participant → 发布 current session → success。
- `addSkillRoleToCurrentSessionAwait(skillId): Boolean`：捕获当前 session ID → 验证官方 role → ensure compat Character → 若 session 未切换则持久化 participantIds → success。
- 保留旧同步 wrapper 时只委托单一 suspend helper，避免两套业务逻辑。
- 只有 Boolean true 后 Route/App 才写 `OfficialSkillPreferences.recordSkillUsed()`。
- 任何失败不产生假的 recent-use。

**TDD**

- [x] 21～44 中至少选一个功能角色证明可生成兼容行且 assetPath 指向官方正式资产。
- [x] 旧 20 同 ID 视觉补充可保留，但官方 name/assetPath/order 覆盖旧事实。
- [x] unknown/non-executable ID 拒绝且不改 participantIds。
- [x] 新会话动作无 create-then-add race。
- [x] current session 切换竞态不把角色写入错误会话。
- [x] 成功后 recent use 写入，失败不写。
