## Goal

把已选定的 UI-02 A/B 双布局实现为【角色】一级页面，并以当前 **44 项 `OfficialSkillCatalog`** 为角色全集：

- `全部`：`推荐角色 + 最近使用 + 全部角色`；
- 具体分类：`分类说明 + 双列角色目录`；
- 44 项均可搜索、浏览、收藏、进入详情；
- 44 项均能真实执行“开始新对话 / 增加到当前会话”；
- 第 21～44 项不能只“看得到”，必须能成为 Dialog participant 并正常进入现有对话生成链；
- 当前固定编辑精选只显示 **`推荐角色`**，不得伪装成个性化 `为你推荐`。

## Frozen product decisions

- 当前 44 项全部作为可发现的 **Skill 角色**进入角色目录。
- 发现 Chip：`全部 / 思考方法 / 职业成长 / 研究学习 / 产品创造 / 沟通表达 / 办公事务 / 生活工具`。
- `生活工具` 包含：预算消费、习惯身心、关系沟通、人情礼仪、传统命理文化陪伴五项主发现入口；分类只是发现入口，不限制跨领域能力。
- 固定 `推荐角色`：
  1. `naval_ravikant` 纳瓦尔
  2. `richard_feynman` 理查德·费曼
  3. `nassim_taleb` 纳西姆·塔勒布
- 上述三项是思想/认知/人生观与精神启发方向的**编辑精选**；不是排名、热度、专业权威或个性化推荐。
- 真人型角色优先复用稳定人物头像，并显示轻量 `AI 模拟角色`；功能型角色使用稳定非真人身份图形，不生成虚构人脸。
- `OfficialSkillCatalog` / execution Manifest 是角色身份、能力、发布与执行资格的权威事实源。
- 旧 Room `Character` 只作为当前 Dialog/Orchestrator 的兼容执行模型，不重新升级成第二套 44 项权威 Catalog。

## Architecture

目标数据流：

```text
OfficialSkillCatalog（44，权威）
       +
SkillRolePresentationCatalog（仅发现分类 / 编辑精选）
       +
旧 Character 可复用视觉补充（仅同 ID 时）
       │
       ▼
SkillRoleCatalogUiState
       │
       ├─ 角色主页面 A/B
       ├─ 搜索 / 收藏 / 最近使用
       └─ 全屏角色详情
                │
                ▼
OfficialSkillConversationRoleAdapter
                │  按需解析并 upsert
                ▼
legacy Character（兼容执行行）
                │
                ▼
RoundtableViewModel participantIds
                │
                ▼
RoundtableOrchestrator / SkillLoader
```

关键原则：**不在 App 启动时把 44 项再次复制成另一套永久配置。** 角色页直接读 Catalog；只有当用户真正开始/加入对话时，才把目标官方 Skill 按需解析为兼容 `Character` 并写入旧表。

这样可以：

- 保留现有消息 `senderId`、participantIds 和 Orchestrator；
- 不新增 Room Schema；
- 不依赖异步 `onCreate` seeding；
- 不让 21～44 因 `skills_config.json` 缺失而无法加入对话；
- 未来迁出旧 Character 时，角色页不需要再次重写数据源。

## Tech stack / non-goals

技术栈沿用 Kotlin、Jetpack Compose、Material 3、Room、kotlinx.serialization、JUnit、Compose UI Test、JDK 17/Gradle Wrapper。

- 新增 Room 表或 Migration；
- 重写 Gemini transport、ExecutionRunCoordinator 或整套 RoundtableOrchestrator；

## Task 6 — 让 44 项按需进入旧对话兼容执行链

**Files**

- Create: `app/src/main/java/com/elio/jianyu/skill/role/OfficialSkillConversationRoleAdapter.kt`
- Create: `app/src/test/java/com/elio/jianyu/skill/role/OfficialSkillConversationRoleAdapterTest.kt`
- Modify: `app/src/main/java/com/elio/jianyu/viewmodel/RoundtableViewModel.kt`
- Modify/Add: `app/src/test/java/com/elio/jianyu/viewmodel/RoundtableConversationPolicyTest.kt`

**Adapter contract**

输入官方 Skill ID，输出一个可供旧 Orchestrator 使用的 `Character` 兼容对象：

- `id` = official skill ID
- `name` = `nameZh`
- `tagline` = official summary
- `skillAssetPath` = 当前 execution Manifest 生效后的正式 `assetPath`
- `order` = `defaultOrder`
- `isActive` = 当前可执行资格
- avatar/voice/vector：同 ID 旧 Character 有真实补充则保留；否则使用确定性功能角色 fallback / 默认 voice；不得覆盖官方身份和 assetPath
- `systemPrompt` 不成为第二事实源；实际执行继续通过 `SkillLoader` + 当前 official assetPath 加载

**Important: lazy compatibility, not bulk authority**

角色页浏览不写 Character。只有用户开始/加入对话时：

1. 从当前有效 Catalog 验证目标 ID；
2. 解析兼容 Character；
3. upsert Character；
4. 再修改会话 participantIds。

**Atomic ViewModel actions**

新增等价动作：

```text
startNewConversationWithOfficialRole(role)
addOfficialRoleToCurrentConversation(role)
```

`开始新对话` 必须在同一 coroutine 业务序列中完成：

```text
upsert role
→ create session
→ persist participantIds = [skillId]
→ load session
→ publish currentSession/currentParticipantIds
```

不能先发布空会话再异步加入角色。

`增加到当前会话`：

```text
capture currentSessionId
→ upsert role
→ recheck currentSessionId unchanged
→ persist distinct participantIds（保持既有上限）
→ publish state
```

失败时不写最近使用。

**TDD steps**

- [ ] 测试 21～44 中至少一个功能角色在旧表不存在时能被 adapter 解析。
- [ ] 测试旧 20 同 ID 的 avatar/voice 可复用，但 name/summary/assetPath/order 必须来自官方 Catalog。
- [ ] 测试未知/不可执行 ID 不得加入。
- [ ] 测试 start-new 顺序不出现空 participant 竞态。
- [ ] 测试 add-current 在会话切换竞态下不写错会话。
- [ ] 测试已有 participant 不重复、上限规则保持。

建议 Commit：`feat: bridge all official Skill roles into dialog sessions`

**Use intent**

```text

```

**Success semantics**

- `START_NEW...` 成功后切到【对话】并显示新会话 + 该角色。
- `ADD...` 成功后切到【对话】并保持当前会话 + 新角色。

- 查看详情、收藏、搜索、筛选不写最近使用。
- 失败时保留当前页面/会话并给用户可理解反馈，不伪装成功。

- [ ] 测试 intent 映射与未知 intent 拒绝/受控降级。
