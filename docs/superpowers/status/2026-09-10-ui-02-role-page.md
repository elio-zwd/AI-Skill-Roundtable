## 2026-09-12 Post-Merge Audit 修正

重新审查 `4bb47dd..871057b` 后，确认原 H-3“未发现半完成状态”的结论不充分，发现以下真实缺口：

1. `App.kt` 在进入 Skill 角色详情时调用 `ensureConversationReady()`；**仅浏览详情**即可静默创建/选择会话，使“浏览 != 使用动作”契约失真。
2. Start New / Add Current 在 session/participant mutation 已发生后，如果 roster settle 超时或失败，仅返回 `false`，原实现没有完整补偿，可能留下半完成状态。
3. 详情动作没有单次 in-flight 门禁；快速重复点击可并发提交；失败只记录日志，没有页面反馈。
4. 进一步 code review 发现：详情 Route coroutine 如果在 mutation 后被取消，`CancellationException` 会绕过普通失败路径；旧 `runCatching` 也可能错误吞取消。

以上均已在唯一修复分支 `codex/ui-postmerge-audit-fixes` 中处理：

- 浏览详情不再调用 `ensureConversationReady()`；Add Current 只由真实 `currentSessionId` 决定可用性。
- Start New / Add Current 增加失败补偿和测试 seam；失败恢复 session/participant mutation。
- 补偿使用 `NonCancellable`，取消时先补偿再继续抛出取消。
- session 恢复带 `expectedCurrentSessionId` 守卫，不覆盖用户后来切换的新会话。
- 详情动作增加短生命周期 in-flight 状态、禁止重复提交，并显示明确失败文案。
