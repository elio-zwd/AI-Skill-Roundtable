## 2. 使用规则

1. 用户界面、帮助文案和正式规格优先使用“面向用户的正式名称”。
2. 内部概念用于跨产品、设计和工程沟通，不得被视为已冻结的代码标识符。
3. 同一对象不得在不同 PR 中被拆成含义不同的近义词。
4. 历史旧称可以出现在迁移说明中，但必须标明“历史术语”或“当前工程术语”。
5. “现实支持”“思维拓展”“推进议题”是已冻结正式名称，不得以解释性文案替换。
6. 目标行为必须使用将来或目标语态，不能描述成当前 Android App 已经实现。
7. 用户不需要理解“Agent”“多智能体”“编排器”“Schema”等工程术语才能使用产品。
8. 当用户文案与工程精确性冲突时，用户界面采用通俗表达，工程文档通过术语映射补充精确定义。

## 3. 核心产品术语

| 面向用户的正式名称 | 内部概念 | 正式定义 | 不等于 |
|---|---|---|---|
| 问题 | `problem input` | 用户对现实任务、判断需求、认知疑问或成果需求的自然语言表达，是进入见域的入口。 | 议题、阶段、固定表单 |
| Skill | `skill capability` | 提供人物视角、专业顾问、任务助手或工作流能力的官方能力单元。 | 仅人物角色、单个 Prompt、第三方插件市场 |
| 议题 | `topic` | 围绕同一持续主线承载背景、资料、消息、阶段、判断、分歧、行动和成果的最高层业务容器。 | 一次提问、当前 `ChatSession` 的简单改名、消息轮次 |
| 阶段 | `stage` | 同一议题中围绕一个明确目标展开的推进节点。 | 响应批次、全部 Skill 的一次齐答、数据库版本 |
| 消息 | `message` | 用户、Skill 或系统在议题协作中产生的时序内容单元。 | 阶段、正式成果、资料本身 |
| 资料 | `material` | 为理解、核查和推进议题而引入的输入、证据、文件、链接、摘录或结构化信息。 | 已确认成果、任意聊天消息、缓存文件 |
| 成果 | `artifact` | 在议题中形成、经用户确认并保存的判断、行动方案、知识笔记或可交付内容。 | 未确认草稿、普通回复、导出动作本身 |
| 圆桌 | `roundtable collaboration` | 多个 Skill 围绕同一阶段目标协作的形式。 | 整个产品、多数投票、每次全部 Skill 发言 |
| 个人背景 | `personal context entry` | 用户主动保存、可见、可编辑、可选择并可跨议题复用的长期背景条目。 | 系统暗中记忆、自动收集的用户画像、全部历史聊天 |
| 议题简报 | `topic brief` | 对议题背景、当前目标、关键判断、分歧、行动和用户选定资料的可编辑压缩表达。 | 全部原始聊天、不可编辑系统摘要、正式成果 |
| 自由追问 | `follow-up` | 补充、质疑、澄清或深入当前阶段目标的自然语言输入。 | 创建新阶段、推进议题、自动触发工作流 |
| 推进议题 | `advance topic` | 用户通过三步确认，在原议题中建立新的明确阶段目标。 | 下一轮回答、重复所有 Skill、创建新议题 |
| 新议题 | `new topic` | 围绕新的独立主线建立持续容器。 | 原议题的新阶段、消息分支 |
| 关联新议题 | `linked topic` | 建立独立主线并保留与来源议题的显式关系。 | 自动复制原议题、阶段分叉、继续原议题 |
| 现实支持 | `practical support` | 处理生活、学习和工作中的具体事情，形成计划、沟通、研究、核查、决策、执行或交付。 | 永久模式、议题类型、“现实行动” |
| 思维拓展 | `perspective expansion` | 引入不同人物、领域、立场、反方意见和思维模型，发现盲区并拓展认知边界。 | 永久模式、议题类型、“思维与视角” |
| 单 Skill | `single-skill mode` | 当前阶段主要由一个 Skill 提供持续能力。 | 永久绑定、无法邀请其他 Skill |
| 多 Skill | `multi-skill mode` | 当前阶段由多个 Skill 构成参与阵容，可独立回应或显式协作。 | 每次全部发言、自动交叉讨论、投票系统 |
| 临时定向回应 | `directed response` | 在多 Skill 中点名某个 Skill，产生当前请求范围内的回答。 | 切换为单 Skill、退出多 Skill、新阶段 |
| 显式交叉讨论 | `explicit cross-discussion` | 用户选择参与者和焦点后触发的一轮 Skill 间讨论，并由系统整合。 | 默认多 Skill 独立回应、无限自动辩论 |
| 响应批次 | `response batch` | 围绕一次用户请求，由一个或多个 Skill 产生的一批回答。 | 阶段、议题、推进议题 |
| 阶段总结草稿 | `stage summary draft` | 系统根据当前阶段生成、等待用户编辑或确认的总结。 | 正式成果、系统替用户作出的最终结论 |
| 正式成果 | `confirmed artifact` | 用户明确确认后保存并进入议题成果及全局成果库的内容。 | 自动生成草稿、普通回复、临时复制文本 |
| 归档议题 | `archived topic` | 用户主动将暂不推进的议题转为归档状态，历史仍可查看和继续。 | 删除、自动结束、清空历史 |
| 已确认资料 | `confirmed material` | 用户确认可用于当前议题并可默认继承到后续阶段的资料。 | 系统临时检索结果、未经确认的推荐 |
| 当前 Skill 阵容 | `active skill set` | 当前阶段已由用户确认参与的 Skill 集合。 | 所有官方 Skill、历史参与者全集 |
| 共识 | `consensus` | 多个观点在给定条件下相互一致的部分。 | 多数票、绝对真理 |
| 分歧 | `disagreement` | 不同 Skill 在判断、假设、价值或建议上的差异。 | 系统错误、必须消除的冲突 |
| 适用条件 | `applicability conditions` | 某项判断或建议成立所依赖的前提、范围和约束。 | 免责声明占位、无条件结论 |
| 明确建议 | `recommendation` | 系统基于当前证据和条件给出的可理解建议及理由。 | 用户最终决定、保证结果 |
| 下一步 | `next action` | 当前阶段可以执行、验证或继续探索的具体行动。 | “下一轮”旧功能名、自动执行 |

## 4. 资料、成果与文件相关术语

| 正式名称 | 使用场景 | 约束 |
|---|---|---|
| 资料 | 用户带入或系统推荐的输入与依据 | 必须保留来源、议题和阶段关系 |
| 已确认资料 | 用户确认纳入议题的资料 | 后续阶段可以默认继承，但不表示复制原文副本 |
| 资料库 | 全局汇总和检索资料的入口 | 不切断资料与原议题、阶段的关系 |
| 草稿 | 尚未获得用户确认的生成内容 | 不得自动进入成果库或代表用户结论 |
| 阶段总结草稿 | 针对一个阶段的通用总结草稿 | 默认先生成，可编辑、放弃或转化 |
| 成果 | 用户确认保存的持久输出 | 必须可追溯到议题、阶段和来源 |
| 成果库 | 全局汇总和检索正式成果的入口 | 不表示成果脱离原议题 |
| 行动方案 | 一类成果 | 包含目标、步骤、阻碍、检查节点等 |
| 决策记录 | 一类成果 | 区分事实、条件、分歧、建议和用户决定 |
| 知识笔记 | 一类成果 | 用于沉淀结构化理解和可复用知识 |
| 交付稿 | 一类成果 | 面向发送、提交、发布或继续编辑的内容 |
| 音频成果 | 成果的一种输出形式 | 保留与源消息或源成果的关系，不作为最高层产品对象 |
| 导出文件 | 跨设备或离线保存的加密数据载体 | 导出动作和文件本身不自动等于业务成果 |
| 恢复快照 | 设备绑定、用于本地恢复的受保护副本 | 不等同于跨设备备份，不默认包含在加密导出中 |

在正式文档中，不能把“资料”“成果”“文件”“备份”“快照”混为同一对象。

## 5. 阶段推进术语

### 5.1 唯一正式入口

正式入口名称只能使用：**推进议题**。

允许的辅助说明：

- “为这个议题建立下一阶段目标”；
- “从更多视角继续思考”；
- “把当前判断转成行动方案”；
- “确认后将在原议题中创建新阶段”。

不得作为正式入口名称：

- 下一轮；
- 再来一轮；
- 轮次推进；
- 开始新回合；
- 继续脑暴；
- 自动推进。

“下一轮”“回合”“第 N 轮”仅可描述历史功能或一次响应批次。

### 5.2 正式推进方向

| 正式名称 | 可用通俗说明 | 不得替换为 |
|---|---|---|
| 思维拓展 | 拓展新视角、检查盲区、深入关键问题 | 思维与视角、认知模式、观点模式 |
| 现实支持 | 形成行动方案、明确下一步、完成具体事情 | 现实行动、执行模式、任务模式 |

两类方向不是永久标签、互斥模式或两条独立议题线。

### 5.3 三步确认名称

1. **选择推进方向**；
2. **选择具体措施或自定义目标**；
3. **确认下一阶段摘要**。

第三步至少应使用以下一致术语：

- 下一阶段目标；
- 方向和措施；
- 默认继承内容；
- Skill 阵容；
- 重点资料；
- 预期输出形式。

在最终确认前，只能称为“推进设置”“确认摘要”或“待确认内容”，不得称为“新阶段”。

## 6. Skill 与协作术语

### 6.1 Skill 的正式分类

Skill 的四类正式分类由 PR08-C 细化，但上位名称固定为：

- 人物视角；
- 专业顾问；
- 任务助手；
- 工作流能力。

“角色”“智囊”“专家”“Agent”可以在特定解释文案中出现，但不能替代 Skill 作为统一能力载体名称。

### 6.2 多 Skill 协作动作

| 正式动作 | 行为 | 不会自动发生的变化 |
|---|---|---|
| 独立回应 | 多个 Skill 各自给出回答 | 不自动互相引用，不形成交叉讨论 |
| 临时定向回应 | 用户点名一个 Skill 回答 | 不退出多 Skill，不切换长期模式，不创建阶段 |
| 邀请 Skill | 用户确认将新 Skill 加入当前阵容 | 不删除历史，不默认发送全部原始聊天 |
| 移除 Skill | 用户将 Skill 从当前阵容移除 | 不删除该 Skill 的历史回答、资料或成果 |
| 显式交叉讨论 | 用户选择参与者和焦点后讨论一轮 | 不无限循环，不自动投票 |
| 整合 | 系统整理共识、分歧、条件、建议和下一步 | 不替用户作最终决定 |

“圆桌”描述多 Skill 协作形式；单 Skill 场景不需要被包装成圆桌。

## 7. 个人背景术语

| 正式名称 | 定义 | 规则 |
|---|---|---|
| 个人背景 | 可跨议题复用的长期背景条目集合 | 用户可见、可编辑、可选择 |
| 背景条目 | 一条独立长期信息 | 只有用户主动加入并确认后保存 |
| 推荐背景 | 系统认为与当前议题相关的候选条目 | 默认不勾选，用户确认后带入 |
| 停用 | 暂时不用于新议题 | 不删除条目和历史引用 |
| 归档背景 | 从常用列表移出但保留 | 不等于删除 |
| 普通删除 | 删除当前背景条目 | 不改写历史议题 |
| 彻底清除 | 按用户确认的影响范围移除或替换历史引用 | 必须展示影响范围并二次确认 |
| 匿名占位 | 清除后保留结构关系的中性标记 | 不泄露原文和敏感类别 |

不得使用“系统记住了你”“自动建立用户画像”等暗示未经确认长期保存的文案。

## 8. 本地数据与安全术语

| 正式名称 | 内部概念 | 定义与边界 |
|---|---|---|
| 本地保存 | `local-first storage` | V1 数据主要保存在当前设备，不表示绝对不会联网调用模型 |
| 应用锁 | `app lock` | 用户可选的进入应用保护，支持生物识别或应用 PIN |
| 应用 PIN | `app PIN` | 应用锁凭据之一，不等同于备份密码 |
| 设备安全密钥 | `device-bound key` | 保护本地库和恢复快照的设备绑定密钥，不等同于应用锁凭据 |
| 备份密码 | `backup password` | 加密导出文件的独立密码，不等同于应用 PIN或设备密钥 |
| 密保问题 | `password hint/recovery aid` | 只能辅助记忆或验证流程，不能在忘记密码后重置或解密备份 |
| 加密导出 | `encrypted export` | 生成使用独立备份密码保护的跨设备数据文件 |
| 导入预览 | `import preview` | 正式写入前展示新增、重复、冲突、跳过和替换范围 |
| 合并 | `merge import` | 按去重和用户冲突选择将备份内容加入当前库 |
| 替换 | `replace import` | 用备份内容替换当前库，执行前必须创建并验证恢复快照 |
| 隔离校验 | `isolated validation` | 在不修改当前库的区域完成解密、结构和完整性检查 |
| 原子写入 | `atomic write` | 正式更新全有或全无，失败不得留下半完成状态 |
| 恢复快照 | `recovery snapshot` | 操作前或用户手动创建、受设备安全密钥保护的本地恢复副本 |
| 回退前快照 | `pre-rollback snapshot` | 每次执行回退前创建并验证的当前状态保护副本 |
| 损坏快照 | `invalid snapshot` | 验证失败、不可用于恢复但默认保留的快照 |
| 本地操作记录 | `local operation log` | 记录导入、替换、回退和快照操作摘要，不含正文、密码或敏感内容 |

禁止使用“绝对安全”“永不丢失”“密保可以找回备份密码”等承诺。

## 9. 高风险表达契约

### 9.1 正式表达

- “提供一般信息和分析框架”；
- “请核对来源、时效和适用条件”；
- “以下内容存在不确定性”；
- “重要决定前建议由具备资质的专业人员复核”；
- “紧急或人身安全风险请优先寻求现实帮助”；
- “系统不会自动替你执行决定”。

### 9.2 禁止表达

- “这是医学诊断”；
- “这是正式法律意见”；
- “保证收益”或“保证结果”；
- “AI 已替你完成专业审查”；
- “用户最终决定，因此无需风险提示”；
- 未说明限制时将人物型 Skill 包装成本人真实意见。

### 9.3 特殊 Skill 名称

| 历史或候选名称 | 正式处理 | 约束 |
|---|---|---|
| Windows 文档生产力助手 | 名称可由 PR08-C 进一步细化 | 只能承诺 Android 真实可用的内容组织、规划、检查和成果生成，不伪装桌面自动化已执行 |
| 规避 AIGC 检测类 | 原创表达与写作自然化助手 | 不帮助绕过检测、隐瞒不允许的 AI 使用、伪造经历/数据/引用/身份或承诺不可检测 |

## 10. 历史与当前工程术语迁移

| 历史或当前用语 | 目标正式术语 | 使用规则 |
|---|---|---|
| 下一轮 | 推进议题，或响应批次 | 若表达产品阶段推进，必须改为“推进议题”；若仅指模型再次回答，应明确写“下一响应批次” |
| 轮次推进 | 阶段推进 | “轮次”不能作为最高层产品对象 |
| 第 N 轮 / `roundIndex` | 第 N 个响应批次 / 响应批次索引 | 当前工程事实，不得直接映射为阶段 |
| 会话 / `ChatSession` | 当前工程会话；目标为议题 | 不能仅通过改名声称已实现议题模型 |
| 角色 / 智囊 / `Character` | Skill，必要时说明“人物视角 Skill” | 当前 `Character` 只覆盖人物型能力基线 |
| 圆桌会议 | 圆桌或多 Skill 协作 | 圆桌不是产品最高层容器 |
| 脑暴交锋 | 按实际行为写独立回应、交叉讨论或响应批次 | 避免把所有协作都描述成对抗或辩论 |
| 材料 / 资源 | 资料 | 除非特指 Android Resource、文件资源或计算资源，否则产品层统一写“资料” |
| 输出 | 消息、草稿或成果 | 必须说明是否经过用户确认并持久保存 |
| 总结 | 阶段总结草稿或正式成果 | 必须区分确认状态 |
| 现实行动 | 现实支持 | 仅可作为历史旧称说明 |
| 思维与视角 | 思维拓展 | 仅可作为历史旧称说明 |
| 拓展新视角 | 思维拓展的解释性文案 | 不替换正式方向名称 |
| 形成行动方案 | 现实支持的解释性文案或成果类型 | 不替换正式方向名称 |
| 自动邀请 Skill | 推荐 Skill | 加入必须由用户确认 |
| 自动归档 | 归档提示 | 系统不能自动归档或删除议题 |
| 自动记忆用户 | 推荐或保存个人背景 | 长期保存和带入必须由用户确认 |
| 分支议题 | 关联新议题 | 一个议题本身保持单一主线，不自动分叉 |

## 13. PR08-B～F 使用约束

### PR08-B：信息架构与核心交互

- 页面与流程必须使用本文正式用户术语。
- “推进议题”三步流程在最终确认前不能显示已经创建的新阶段。
- 必须区分消息、草稿、资料和正式成果的状态。
- 取消、失败和恢复文案不得暗示历史已被覆盖。

### PR08-C：Skill 分类与推荐

- 统一使用 Skill 作为能力载体上位词。
- 四类 Skill、标签、来源、许可、风险和时效不得改变本文核心对象含义。
- 人物名气不能被文案等同于专业可靠性。
- 推荐只提供候选和理由，不能写成自动加入。

### PR08-D：品牌与视觉

- 视觉标签可以附加图标和通俗说明，但不得改名“现实支持”“思维拓展”“推进议题”。
- 不能通过两个完全割裂的视觉系统暗示两类价值是两套产品。
- 圆桌、阶段、资料和成果必须有不同视觉语义。

### PR08-E：技术影响与迁移

- 内部概念名仅用于讨论，不是已批准的 Kotlin 或 Room 名称。
- 必须区分响应批次与阶段，禁止把 `roundIndex` 直接迁移为阶段。
- 必须评估会话、消息、人物角色和音频现状与目标对象之间的缺口。
- 数据安全术语对应用户可见行为，具体算法和 Schema 由技术评估提出。

### PR08-F：最终整合

PR08-F 必须协调：

1. PR08-B 是否始终将“资料”作为用户正式术语，避免与“材料”“资源”产生不同对象；
2. PR08-B/D 是否明确区分消息、草稿、正式成果和导出文件；
3. PR08-B/E 是否将“推进议题”与内部响应批次彻底分离；
4. PR08-C 是否用 Skill 统一承载人物视角、专业顾问、任务助手和工作流能力；
5. PR08-D 是否保持现实支持、思维拓展为同一产品内可双向切换的价值方向；
6. PR08-E 是否把内部概念误当作已冻结类名、表名或接口名；
7. 所有文档是否明确目标设计尚未在当前 Android App 中实现。

如并行 PR 发现真实产品契约冲突，应在各自 PR 描述中提出变更提案，由 PR08-F 统一处理，不得直接改写第 1～62 题已确认结论。
