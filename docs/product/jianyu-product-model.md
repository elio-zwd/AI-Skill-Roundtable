## 2. 产品定义与冻结原则

> 见域是一款面向个人的多智能体思考与行动工作台。用户围绕持续议题，调用人物视角、专业顾问、任务助手和工作流能力，通过自由追问与分阶段推进，沉淀判断、行动方案和知识成果。

冻结原则：

1. **问题是入口**：用户先表达问题，不必先理解 Agent、Skill、工作流或多智能体。
2. **Skill 是能力载体**：人物视角、专业顾问、任务助手和工作流能力统一以 Skill 承载。
3. **议题是持续容器**：背景、资料、消息、阶段、判断、分歧、行动和成果持续归属于议题。
4. **阶段是推进节点**：每个阶段围绕一个明确目标；自由追问继续当前阶段，“推进议题”创建新的明确阶段。
5. **圆桌是协作形式**：圆桌只表示多 Skill 协作，不等于整个产品，也不以投票裁决真理。
6. **成果由用户确认**：系统可以生成草稿，只有用户确认后才成为正式成果。
7. **用户拥有最终控制权**：Skill 加入、阶段推进、背景带入、正式保存、归档、冲突处理和高风险决定均由用户确认。
8. **目标与现状分离**：当前工程仍是会话、消息、人物角色和轮次调度基线；PR08 只定义目标规格。

## 3. 核心对象关系

```text
用户表达问题
    ↓
系统可推荐方向、模式与 Skill，用户确认
    ↓
议题（持续容器）
    ├── 个人背景引用（可见、可选）
    ├── 资料（输入与证据）
    ├── 阶段 1（明确目标）
    │   ├── 单 Skill 或多 Skill
    │   ├── 消息与响应批次
    │   ├── 可选圆桌 / 定向回应 / 交叉讨论
    │   └── 阶段总结草稿 → 用户确认 → 正式成果
    ├── 阶段 2、3……（由“推进议题”确认创建）
    └── 归档 / 继续 / 关联新议题
```

约束：

- 一个议题保持一条主线，可以连续包含多个阶段。
- 新阶段属于原议题，不覆盖旧阶段，不复制互相冲突的历史副本。
- 需要独立主线时，由用户显式创建关联新议题或全新议题。
- “轮次”只表示一次模型或成员响应批次，不能替代议题或阶段。

## 4. 核心对象定义

### 4.1 问题

**定义**：用户对现实任务、判断需求、认知疑问或成果需求的自然语言表达，是进入见域的入口。

**规则**：

- 问题可以直接输入，不强制先选现实支持、思维拓展、单 Skill 或多 Skill。
- 系统可以根据问题推荐方向、使用模式和 Skill，并说明理由。
- 推荐不会自动开始；用户确认或调整后，才建立议题及初始阶段。
- 问题不是长期容器；其持续上下文由议题承载。

### 4.2 Skill

**定义**：为议题提供特定视角、专业能力、任务能力或工作流能力的官方能力单元。

**类型**：

1. 人物视角；
2. 专业顾问；
3. 任务助手；
4. 工作流能力。

**规则**：

- V1 只提供官方内置 Skill，不支持用户创建、第三方导入或公开市场。
- Skill 可以服务现实支持、思维拓展或两者，并可拥有多个领域、场景、风险和输入输出标签。
- 系统只推荐候选及理由，必须由用户确认加入。
- Skill 的加入、移除或替换不删除历史消息、资料和成果。
- 中途加入的 Skill 默认接收可编辑议题简报和用户选定资料，不默认接收全部原始聊天。
- 人物型 Skill 必须说明是 AI 生成视角，不代表本人；高风险 Skill 必须披露来源、限制、能力边界和信息时效。

### 4.3 议题

**定义**：围绕同一持续主线保存背景、资料、协作过程、阶段历史、判断、分歧、行动和成果的最高层业务容器。

**必须承载**：

- 议题标题、背景和约束；
- 用户确认带入的个人背景；
- 参与过的 Skill 及变化历史；
- 消息与协作过程；
- 已确认资料及来源；
- 一个或多个阶段及其目标；
- 判断、分歧、行动项；
- 已保存成果及来源关系。

**生命周期**：

```text
创建 → 活跃推进 → 用户归档 → 继续原议题 / 创建关联新议题 / 保持归档
```

**规则**：

- 系统可以建议归档，但不能自动归档或删除。
- 归档不是删除，历史仍可查看。
- 基于归档继续时展示旧简报，并要求用户补充“现在有什么变化”。
- 原归档简报保持不变；新增变化和新简报单独记录。

### 4.4 阶段

**定义**：同一议题中围绕一个明确目标展开的推进节点。

**规则**：

- 初始阶段在用户确认开始议题时建立。
- 自由追问补充、质疑、澄清或深入当前阶段，不创建新阶段。
- “推进议题”用于建立新的阶段目标；打开、返回或取消流程均不创建阶段。
- 只有三步确认的最后一步完成后，才创建新阶段。
- 新阶段默认继承议题背景、已确认资料、已保存成果、当前 Skill 阵容、已形成判断、主要分歧和当前行动项。
- 用户可以在确认前调整目标、Skill、资料和输出形式。
- 阶段保留目标、来源、继承关系、消息、资料、判断、分歧、行动和成果的可追溯关系。
- 阶段不是数据库版本、消息轮次或所有 Skill 的一次齐答。

### 4.5 消息

**定义**：议题协作过程中由用户、Skill 或系统产生的时序内容单元。

**消息可以表达**：

- 用户问题、自由追问和补充；
- Skill 的独立回答或定向回答；
- 交叉讨论内容；
- 系统状态、推荐理由、失败、停止和恢复提示；
- 草稿内容及用户修改记录。

**规则**：

- 消息归属于议题，并在发生时关联当前阶段。
- 一次响应批次可以包含多条消息；响应批次不是阶段。
- Pending、流式、成功、失败、停止、重试等属于消息或生成过程状态，不改变产品对象层级。
- 消息正文不会因为 Skill 移除、背景普通删除或新阶段创建而被静默改写。

### 4.6 资料

**定义**：用户或系统为理解、核查和推进议题而引入的输入、证据、文件、链接、摘录或结构化信息。

**规则**：

- 资料采用“议题内管理 + 全局资料库汇总”。
- 每项资料保留来源、所属议题、关联阶段和使用关系。
- 系统可以推荐资料，但只有用户确认后才成为“已确认资料”并默认继承到后续阶段。
- 关联新议题时带入可编辑议题简报和用户选择的资料，不默认复制全部原始聊天。
- 资料与成果不同：资料主要作为输入和依据，成果是用户确认保存的输出。

### 4.7 成果

**定义**：在议题中形成、经用户确认并保存的判断、行动方案、知识笔记或可交付内容。

**成果类型至少包括**：

- 通用阶段总结；
- 行动方案；
- 决策记录；
- 知识笔记；
- 交付稿；
- 音频等派生输出形式。

**规则**：

- 系统先生成阶段总结草稿，用户可以编辑。
- 未经用户确认的内容仍是草稿，不是正式成果。
- 默认先生成通用总结，再按用户选择转为其他成果类型。
- 成果采用“议题内管理 + 全局成果库汇总”。
- 每项成果保留原议题、阶段、Skill、资料和源内容关系。
- 新阶段继承成果的可用关系，不复制成多个互相冲突的独立副本。

### 4.8 圆桌

**定义**：多个 Skill 围绕同一阶段目标协作的形式。

**默认协作**：

- 多 Skill 默认分别独立回应；
- 初始多 Skill 用于建立不同视角；
- 后续回答者可按相关性或用户点名选择；
- 圆桌不要求每次都让全部 Skill 回答。

**显式交叉讨论**：

- 必须由用户主动触发；
- 用户选择参与者和讨论焦点；
- 进行一轮交叉讨论后由系统整合；
- 不自动演化成无限讨论。

**结果结构**：

- 共识；
- 分歧；
- 适用条件；
- 明确建议；
- 下一步。

系统可以给出推荐与依据，但不得通过多数投票包装为真理，用户保留最终决定权。

### 4.9 个人背景

**定义**：用户主动保存、可跨议题复用的长期背景条目。

**规则**：

- 每条背景可见、可编辑、可选择，并可独立管理。
- 系统可以推荐相关背景，但默认不勾选。
- 只有用户主动加入并确认后，长期信息才保存或带入议题。
- 支持编辑、停用、归档和删除。
- 普通删除不改写历史议题。
- 彻底清除前展示影响范围并二次确认。
- 部分引用默认支持精确移除或替换，也允许删除整份相关内容。
- 清除后的历史位置使用不泄露原文和敏感类别的匿名占位。

## 5. 两类核心价值与双向跨界

### 5.1 现实支持

用于处理生活、学习和工作中的具体事情，形成计划、沟通、研究、核查、决策、执行和可交付成果。

### 5.2 思维拓展

用于引入不同人物、领域、立场、反方意见和思维模型，重新理解问题、发现盲区并拓展认知边界。

### 5.3 共同规则

- 用户可以跳过、单独选择或组合。
- 两类不是永久模式、用户标签或议题类型。
- 同一议题可以从思维拓展进入现实支持，也可以从现实支持回到思维拓展。
- 切换方向不自动创建新议题；只有用户确认“推进议题”后才创建新阶段。
- “生活与工作”“思维与视角”“现实行动”不是正式分类名称。
- “拓展新视角”“形成行动方案”可以作为解释性文案，不能替代正式方向名称。

## 6. 单 Skill、多 Skill 与协作动作

### 6.1 单 Skill

适合明确问题、垂直任务和持续咨询。单 Skill 可以邀请其他 Skill，用户确认后升级为多 Skill。

### 6.2 多 Skill

适合复杂议题、重大决策、长期成长和跨领域协作。多 Skill 是参与阵容，不意味着所有 Skill 每次必须共同发言。

### 6.3 临时定向回应

- 用户在多 Skill 中点名某个 Skill，只产生一次或当前请求范围内的定向回答。
- 临时定向回应不自动退出多 Skill，也不创建新阶段。
- 需要长期一对一深聊时，用户必须明确切换为单 Skill。

### 6.4 显式交叉讨论

- 用户明确触发并选择参与者与焦点。
- 默认多 Skill 独立回答不能被称为交叉讨论。
- 交叉讨论结束后由系统整合，不以投票裁决。

## 7. 自由追问与推进议题

| 行为 | 目的 | 是否创建新阶段 |
|---|---|---|
| 自由追问 | 补充、质疑、澄清或深入当前阶段目标 | 否 |
| 推进议题 | 建立新的明确阶段目标 | 仅最终确认后 |
| 新议题 | 建立独立主线 | 创建新的议题 |

“推进议题”入口始终可用；阶段较成熟时系统可以增强提示并说明理由，但不能要求用户先完成总结、保存成果或等待系统许可。

三步确认：

1. 选择推进方向：思维拓展或现实支持；
2. 选择具体措施或填写自定义目标；
3. 确认下一阶段摘要，包括目标、方向、措施、继承内容、Skill、重点资料和预期输出。

预设措施：

| 思维拓展 | 现实支持 |
|---|---|
| 引入反方意见 | 明确下一步 |
| 查找遗漏视角 | 形成执行计划 |
| 检查关键假设 | 分析执行阻碍 |
| 比较不同立场 | 生成成果交付 |
| 深入某个问题 | 设置检查节点 |
| 自定义目标 | 自定义目标 |

普通自然语言输入不得被系统擅自解释为阶段推进。

## 8. 阶段总结与成果确认

```text
阶段过程
  → 系统生成通用阶段总结草稿
  → 用户查看、编辑、补充或放弃
  → 用户明确确认
  → 保存为正式成果
  → 可进一步转为行动方案、决策记录、知识笔记或交付稿
```

边界：

- 阶段结束不是自动条件，用户可以持续自由追问。
- 生成草稿不等于阶段被强制完成。
- 未确认草稿不得进入正式成果库或被描述为用户结论。
- 系统建议与用户决定必须可区分。
- 高风险结论必须保留条件、不确定性、信息时效和复核提醒。

## 9. 归档、继续与关联新议题

对相似或后续问题，用户可以选择：

1. **继续原议题**：主线未改变，在原议题当前阶段继续，或通过推进议题创建新阶段；
2. **创建关联新议题**：需要独立主线，但保留来源关系；
3. **创建全新议题**：不继承原议题关系。

关联新议题：

- 带入可编辑议题简报；
- Skill 阵容可调整；
- 资料由用户选择；
- 不默认复制全部原始聊天；
- 原议题与新议题保留关联关系，但各自独立推进。

基于归档继续：

- 展示归档时的旧简报；
- 要求用户补充“现在有什么变化”；
- 原简报不可被后续内容覆盖；
- 新变化和新简报单独保存。

## 10. 本地保存、导入导出与恢复边界

V1 目标：

- 本地保存，不做账号和自动云同步；
- 支持手动加密导入导出；
- 应用锁可选，支持生物识别或应用 PIN；
- 本地库由设备安全密钥保护，独立于应用锁；
- 导出文件始终加密，使用独立备份密码；
- 密保问题只能辅助记忆或验证流程，不能在忘记备份密码后重置密码或解密；
- 修改备份密码需要原密码，并生成新备份，不覆盖唯一旧备份；
- 新备份自动校验，可选隔离验证导入。

导入、快照与回退必须满足：

- 相同数据去重，差异版本由用户选择当前、备份或两者；
- 不静默覆盖冲突数据；
- 非空库导入先分类汇总，再查看逐项差异；
- 替换当前库前创建并验证恢复快照；
- 导入、替换和回退先隔离校验，正式写入采用原子操作；
- 任一步失败不得修改当前库，并说明失败阶段、数据是否受影响和下一步；
- 回退前创建并验证“回退前快照”；
- 快照由设备安全密钥保护，创建后和恢复前验证；
- 损坏快照保留并标记不可用，由用户决定删除；
- 快照保留到用户主动删除；容量不足只提醒，不自动清理；
- 支持手动快照和备注；
- 本地操作记录不含正文、密码、应用锁凭据或敏感内容；
- 加密导出默认只包含当前库，不包含设备绑定恢复快照。

本节冻结用户行为和安全目标，不冻结加密算法、数据表、事务实现、文件后缀、压缩方式、容量阈值或后台框架。

## 11. 高风险原则

医疗、法律、金融等高风险问题采用分级响应，不完全禁止。

- 一般风险：可提供分析、建议和行动方案，并说明关键假设和适用条件。
- 较高风险：只提供一般信息、分析框架和可核查依据；说明时效、不确定性和适用条件；重要决定前提示专业人员复核。
- 紧急或重大不可逆风险：优先提示风险和现实帮助，不自动执行决定，不提供绕过安全、法律或专业审查的方案。
- 不作诊断、正式法律意见、收益保证或专业执照意见。
- 高风险 Skill 必须披露来源、限制、能力边界和信息时效。
- 用户保留最终决定权，但系统不得用“最终决定权”弱化必要的安全提示。

特殊 Skill：

- “Windows 文档生产力助手”只能提供 Android 真实可用的内容组织、工作流规划、检查清单或成果生成能力，不得伪装桌面自动化已执行。
- 原“规避 AIGC 检测类”统一转化为“原创表达与写作自然化助手”，不得帮助绕过检测、隐瞒不允许的 AI 使用、伪造经历/数据/引用/身份、承诺无法检测或提供对抗技巧。

## 14. 产品边界与非目标

### 14.1 V1 产品边界

- 面向个人，不以组织账号、多租户或团队权限为前提。
- 本地优先，不做账号和自动云同步。
- 只提供官方内置 Skill。
- 问题、议题、阶段、资料、成果和个人背景由用户控制。
- 圆桌、多 Skill 与工作流是可选协作能力，不是使用产品的前置知识。

### 14.2 PR08-A 非目标

- 不设计页面布局、路由、动效、状态矩阵或像素级文案。
- 不冻结 Skill Schema、候选清单最终数量或推荐算法。
- 不决定 Room Entity、DAO、Migration、Kotlin 类型、接口名或数据库表。
- 不决定加密算法、备份格式、快照阈值、事务或后台框架。
- 不修改生产代码、测试、Room、Gradle、资源、Manifest、CI、仓库设置、官网、DNS 或服务器。
- 不实施 App 名、applicationId、namespace、包路径或仓库重命名。
- 不迁移旧包数据；当前 App 尚未正式发布，后续按全新应用身份迁移。
- 不把本文目标行为写成当前已实现。

## 15. 给 PR08-B～F 的输入与协调点

### PR08-B

必须把本模型转为问题优先首页、推荐确认、议题工作区、阶段时间线、自由追问、推进议题三步流程、资料/成果/归档/恢复状态。不得改变对象含义。

必须将 Skill 四类型、两类主价值、多标签、官方内置范围、来源许可、人物声明和高风险边界具体化。不得把现实支持或思维拓展固化为永久 Skill 限制。

### PR08-D

必须使用本文正式术语设计视觉承载，不得将圆桌设计成整个产品，也不得将两类价值拆成两套产品。

### PR08-E

必须以“当前对象不等同于目标对象”为前提评估迁移，尤其禁止把 `Message.roundIndex` 直接当作阶段。PR08-F 只冻结产品对象和行为边界；具体 Schema、类型、事务和加密方案由 PR09 在失败测试与安全评审后决定。

### PR08-F

必须统一以下跨 PR 协调点：

- “资料”作为正式用户术语，其他文档不得与“材料”“资源”混用而产生不同对象；
- “成果”是确认后的持久输出，“草稿”“消息回复”“导出文件”不得默认等同成果；

- PR08-F 已完成跨规格收敛；后续发现真实产品契约冲突时，必须以最终规格索引为入口提出变更提案，不得由 PR09 实现分支静默改写。
