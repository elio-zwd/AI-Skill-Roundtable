## 1. 产品身份

```text
产品 / App：见域
口号：看见更多观点，打开认知边界
目标仓库：jianyu-workbench
目标官网：jianyu.my-elio.online
目标 applicationId：com.elio.jianyu
旧 App：不保留
旧包数据：不迁移
```

见域是一款面向个人的多智能体思考与行动工作台。用户围绕持续议题，调用人物视角、专业顾问、任务助手和工作流能力，通过自由追问与分阶段推进，沉淀判断、行动方案和知识成果。

## 2. 目标用户与优先场景

### 2.1 目标用户

优先级：

1. 个人深度思考者；
2. 职场与学习用户；
3. 管理者和决策者；
4. 研究与内容创作者。

### 2.2 核心场景

- 日常思考与决策；
- 学习研究与知识整理；
- 团队讨论与方案评审；
- 内容、文档与沟通成果生成；
- 长期个人成长和复杂项目推进。

### 2.3 核心价值

- **现实支持**：处理具体生活、学习和工作问题，形成下一步、计划、沟通文本和可编辑成果。
- **思维拓展**：引入不同人物、专业、立场和反方，检查假设、盲区和不确定性。

两类价值属于同一产品：可跳过、单选或组合，也可在同一议题中双向切换，不形成两套产品或两条议题主线。

## 3. 正式产品对象

| 对象 | 正式定义 | 关键边界 |
|---|---|---|
| 问题 | 用户进入见域时表达的疑问、目标或任务 | 是入口，不等于持久容器 |
| Skill | 提供人物视角、专业分析、任务输出或工作流的能力载体 | 不等同于模型、聊天角色或整个产品 |
| 议题 | 围绕一个持续问题保存阶段、消息、资料、成果和背景使用记录的容器 | 一个议题保持单一主线 |
| 阶段 | 议题中具有明确目标的推进节点 | 不等于响应批次或 `roundIndex` |
| 消息 | 用户和 Skill 在阶段中的交互记录 | 不自动成为成果 |
| 响应批次 | 一次用户指令后模型或成员的回答批次 | 只用于执行与展示，不代表阶段 |
| 资料 | 用户确认带入的输入、依据和来源 | 与成果严格区分 |
| 阶段总结草稿 | 对当前阶段判断、分歧、行动或知识的可编辑草稿 | 持久保存，但未确认前不是成果 |
| 成果 | 用户确认保存的判断、行动方案、知识笔记或可交付内容 | 可以关联阶段、资料、Skill 和音频 |
| 圆桌 | 多 Skill 协作形式 | 不代表整个产品，不以投票裁决真理 |
| 个人背景 | 可复用的长期用户事实、偏好和约束 | 每个议题由用户显式选择是否带入 |
| 执行运行 | 一次实际模型调用或工作流执行 | 目标技术模型，不能继续复用消息主键代替 |

## 4. V1 产品范围

### 4.1 纳入 V1

- 问题优先首页；
- 仅保存议题、不立即运行；
- 单 Skill 和多 Skill；
- Skill 搜索、分类、筛选、详情、收藏与最近使用；
- 推荐理由和用户确认；
- 保存官方 Skill 组合、顺序与可选默认职责；
- 自由追问；
- 临时点名某个 Skill；
- 显式交叉讨论；
- 推进议题三步流程；
- 阶段时间线；
- 资料与成果；
- 阶段总结草稿；
- 归档、恢复、关联新议题；
- 回收站与彻底清除；
- 停止、重试、部分成功和进程恢复；
- 44 项官方 Skill 的分批完成；
- 加密导出、设备绑定快照、隔离导入与回退的目标行为。

### 4.2 V1 不纳入

- 用户创建或编辑 Skill 正文；
- 第三方 Skill 导入；
- 公开 Skill 市场；
- 用户公开发布 Skill；
- Windows Office、COM、VBA、宏或桌面文件系统控制；
- 自动替用户完成现实审批、签署或提交；
- 旧 App 或旧包数据迁移；
- 未经用户确认自动加入 Skill、调用模型或保存长期背景。

## 5. 首页与议题创建

### 5.1 首页结构

首页以问题输入为首要任务，不要求用户先理解模式、Skill 或“多智能体”。

用户可以：

1. 输入问题；
2. 可选现实支持、思维拓展或两者组合；
3. 选择“获取建议”进入 Skill 推荐确认；
4. 或选择“保存议题”，只保存草稿而不运行模型。

### 5.2 仅保存议题

“保存议题”是 V1 次级操作：

- 创建议题草稿；
- 不推荐或加入 Skill；
- 不调用模型；
- 不创建执行运行；
- 不自动带入资料或个人背景；
- 可从议题列表继续完善并开始运行。

议题草稿在列表中应明确显示“尚未开始”，不得伪装为已经生成结果。

## 6. Skill 发现、推荐与确认

### 6.1 四类 Skill

- 人物视角；
- 专业顾问；
- 任务助手；
- 工作流能力。

### 6.2 推荐原则

推荐采用：问题优先、全量可发现、理由可解释、风险可见、用户确认、阵容去重和观点多样。

每个候选至少显示：

- 匹配问题；
- 职责；
- 所需资料；
- 预期输出；
- 风险与时效；
- 联网要求；
- 人物模拟状态；
- 当前发布或开发状态。

用户确认前：

- 不创建执行运行；
- 不自动加入 Skill；
- 不自动带入资料或个人背景；
- 不把其他 Skill 输出交给成果构建或表达类 Skill。

### 6.3 人物 Skill

现有 20 项人物 Skill：

- 均可搜索和浏览；
- 在所有场景中按能力匹配正常参与自动推荐；
- 不因争议、政治、金融或其他风险标签降低排名；
- 风险标签只影响理由、披露、输出边界、时效核验和专业转介；
- 统一显示：

> 这是基于公开资料生成的 AI 模拟视角，不代表本人，也不保证复现其当前或完整观点。

人物知名度、财富、职位、粉丝量和点击量不得替代专业可靠性。

### 6.4 官方 Skill 组合

V1 允许用户保存：

- 官方 Skill 组合名称；
- Skill 成员；
- 成员顺序；
- 可选默认职责。

默认职责属于组合层的成员分工，不修改官方 Skill 正文、系统边界或安全规则。V1 不允许保存自定义 Skill 正文、第三方 Skill 或第三方执行脚本。

## 7. 单 Skill、多 Skill 与协作

### 7.1 并列模式

单 Skill 与多 Skill 是并列模式：

- 单 Skill 可在后续邀请其他 Skill；
- 多 Skill 可临时点名一个 Skill 回应；
- 中途新增 Skill 只接收用户可编辑的议题简报，不默认接收全部原始聊天；
- 增删 Skill 不删除既有回答、资料或成果；
- 模式变化不自动创建新议题或阶段。

### 7.2 默认独立回应

多 Skill 默认独立回应，避免成员互相复制和过早收敛。

### 7.3 临时点名

用户可以在多 Skill 议题中临时点名一个 Skill：

- 只影响当前指令；
- 完成后恢复默认阵容行为；
- 不改变长期成员关系。

### 7.4 显式交叉讨论

交叉讨论必须由用户显式触发，并选择参与者和焦点：

- 默认只对当前指令生效；
- 完成后恢复各 Skill 独立回应；
- 不自动把所有历史资料和个人背景发送给所有参与者；
- 不由投票决定真理；
- 输出需保留共识、分歧、适用条件、明确建议和下一步。

## 8. 自由追问与推进议题

### 8.1 自由追问

自由追问继续当前阶段：

- 可追问任何当前内容；
- 不创建新阶段；
- 不要求全部 Skill 重复回应；
- 可以临时点名或显式触发交叉讨论。

### 8.2 推进议题

“推进议题”是唯一正式阶段推进入口，“下一轮”只作为历史术语。

入口始终可用，阶段较成熟时可以增强提示，但不得强迫用户推进。

### 8.3 三步流程

1. **选择方向**：现实支持、思维拓展，或两者组合；
2. **选择措施或自定义目标**；
3. **确认下一阶段摘要**：目标、Skill、资料、背景和预期输出。

两类方向使用两个可独立选择的方向卡片；同时选择仍只创建一个新阶段。

只有第三步最终确认后才创建新阶段。

### 8.4 无成果直接推进

用户可以不生成或保存正式成果，直接推进阶段。

系统可以保存必要的阶段上下文和确认摘要，但不得将其自动标记为正式成果。

### 8.5 撤销未运行阶段

新阶段创建后、首次执行运行开始前，可以撤销：

- 不使用倒计时；
- 删除该空阶段及未提交运行设置；
- 返回上一阶段；
- 不影响上一阶段的消息、资料、成果和历史。

一旦开始执行，改用停止、归档或再次推进，不再显示“撤销阶段”。

## 9. 资料、草稿与成果

### 9.1 导航

全局使用一个一级入口“资料与成果”，页内提供：

- 资料 Tab；
- 成果 Tab。

两者仍是不同对象，可按议题、阶段、Skill、来源和时间筛选，并支持深链直接打开指定对象。

### 9.2 阶段总结草稿

草稿跨 Activity 与进程重建持久保存，不自动过期，直到：

- 用户确认保存为成果；
- 用户主动放弃；
- 所属议题被彻底清除。

系统默认先生成通用阶段总结草稿；用户再决定是否转为行动方案、决策记录、知识笔记或其他交付稿。

### 9.3 成果确认

只有用户明确确认保存，草稿才成为正式成果。

正式成果可以是：

- 判断或决策记录；
- 行动方案；
- 知识笔记；
- 沟通文本；
- 文档结构、表格或其他可交付内容；
- 音频等关联资产。

导出文件是成果的外部表示，不是新的成果类型。

## 10. 归档、删除与恢复

### 10.1 归档

归档保留议题的阶段、消息、资料和成果。归档后可以：

- 恢复并继续原议题；
- 基于该议题创建关联新议题。

议题只由用户主动归档。系统可以提示，但不得自动归档或删除。

恢复归档议题继续时，系统展示旧简报并要求用户补充“现在有什么变化”；旧简报保持不变，新变化与新简报另行记录。

遇到相似问题时，用户可以选择继续原议题、创建带可编辑简报和可调整 Skill 的关联新议题，或创建不继承上下文的全新议题。关联新议题不复制全部原始聊天。

### 10.2 运行中归档

运行期间触发归档时必须让用户明确选择：

1. 等待当前生成完成，完成后归档；
2. 停止当前生成并归档。

不得静默停止，也不得在后台仍运行时仅把页面显示为已归档。

### 10.3 回收站

普通删除进入回收站：

- 不自动过期；
- 可以恢复；
- 容量不足时只提醒；
- 用户可主动彻底清除。

彻底清除前必须明确说明不可恢复范围。

## 11. 个人背景

个人背景以可见、可编辑、可选择的独立条目保存到背景库，但每个新议题都需要用户显式选择是否带入。系统可以推荐相关条目，但默认不勾选；长期信息只有在用户主动加入并确认后才保存。

系统必须展示本次实际使用的背景，不得：

- 默认把全部背景带入所有议题；
- 把一次问题自动升级为长期背景；
- 在用户不知情时发送敏感背景。

背景条目支持编辑、停用、归档和删除。普通删除不改写历史议题；“彻底清除”必须先展示影响范围并二次确认。历史内容仅引用部分背景时，默认精确移除或替换该部分，也允许用户删除整份内容；清除后的历史引用使用不泄露原文和敏感类别的匿名占位。

## 12. 两个特殊 Skill

### 12.1 办公文档助手

内部 ID：`office-document-productivity`。

Android V1 允许生成：

- Word 正文、结构和大纲；
- PPT 逐页大纲和演讲要点；
- Excel 字段、公式思路和数据整理逻辑；
- 会议纪要、周报月报、项目计划；
- 通知、申请、汇报材料；
- 文本、Markdown、表格或 CSV。

不得宣称控制 Windows Office、COM、VBA、宏、PowerShell、桌面文件或复杂格式保真。

### 12.2 去AI化助手

内部 ID：`original-expression-naturalizer`。

定位：现实沟通文案任务助手。根据用户提供的真实事实、关系背景和行动目标，减少模板感、机械感和生硬表达，形成符合用户本人语气与场景的可用文本。

固定边界说明：

> 让真实内容更像你本人表达，不用于规避检测或伪造事实。

该固定边界必须与名称同时出现在 Skill 目录卡片或就近说明、详情页、推荐确认、首次调用确认和成果导出说明中，不得只藏在详情页。

允许：

- 请假、申请、说明、道歉、拒绝、协商和催办；
- 求职邮件、自我介绍、申请理由和工作汇报；
- 调整正式、口语、礼貌、直接或委婉程度；
- 将已确认的行动建议转化为用户可直接使用的现实文本。

禁止：

- 绕过 AI 检测、学术诚信检查、平台审核或组织规则；
- 承诺“不可检测”或检测结果；
- 伪造事实、经历、数据、引用或身份；
- 删除必须保留的 AI 使用、来源或诚信声明；
- 整理或统一多个 Skill 的观点；
- 掩盖圆桌分歧。

正式实现必须从零原创设计，并通过原创性、诚信与质量验收。

## 13. 44 项 Skill 的 V1 分批

- 44 项全部属于 V1 阶段目标；
- V1.0 不要求一次性上线全部项目；
- V1.0 / V1.1 按许可清晰度、移动端可行性、安全与来源治理、内容质量、实现完成度和测试证据划分；
- 不按四类 Skill 机械切批；
- 未通过门禁的候选只能显示为开发中、待核验或暂缓，不得伪装成可执行能力；
- 人物风险标签不作为降低推荐排名或推迟实现的单独依据。

## 14. 状态、错误与恢复

必须覆盖：

- 空状态；
- 加载、搜索、思考和流式输出；
- 成功、部分成功和全部失败；
- 用户停止；
- 无 API Key、离线、限流和服务错误；
- 资料读取或授权失败；
- 推荐取消与修改；
- 推进议题取消、误触、提交中和恢复；
- Activity / 进程重建；
- 归档、回收站、恢复和彻底清除；
- 窄屏、字体放大、明暗主题、TalkBack 和减少动效。

页面级错误不得吞掉已经成功的单项结果；失败 Skill 支持原位重试，已成功成员不得重复消耗。

## 15. 数据与安全目标

### 15.1 本地保存与应用锁

V1 以本地保存和手动导入导出为边界，不提供账号体系或自动云同步。

应用锁为可选能力，可使用生物识别或应用 PIN；本地库由设备安全密钥保护，且数据库保护密钥独立于应用锁凭据。

### 15.2 新应用沙箱

```text
applicationId：com.elio.jianyu
namespace：优先同步为 com.elio.jianyu
新 App：全新应用沙箱和全新初始数据库
旧包 com.elio.skillroundtable：不做跨应用数据 Migration
```

PR08-F 不冻结数据库文件名、表名、字段、Schema 版本或 Kotlin 类型。

### 15.3 加密导出

- 导出文件始终加密，并使用独立备份密码；
- 修改备份密码必须输入原密码；密保问题只能提供辅助提示，不能在忘记密码后重置密码或解密旧备份；
- 修改密码时生成新备份，不覆盖唯一旧备份；
- 新备份创建后自动校验，并允许用户选择在隔离空间验证导入。

### 15.4 快照与导入

必须区分：

- 可移植加密导出；
- 设备绑定恢复快照；
- 临时隔离导入区。

目标行为：

- 向非空数据库导入前先展示按类别汇总、可逐项展开的差异预览，并由用户选择合并或替换；
- 相同数据自动去重；
- 冲突数据由用户选择保留当前、备份或两者；
- 替换前创建并验证恢复快照；
- 导入先隔离校验；
- 正式写入采用可回退的原子切换；
- 失败不得修改当前库；
- 显示失败阶段和可读错误；
- 恢复快照保留到用户主动删除；损坏快照保留并标记不可用，由用户决定是否删除；
- 快照由设备安全密钥保护，显示单项大小和总占用；容量不足只提醒，不自动删除；
- 回退前创建“回退前快照”；
- 快照记录名称、来源、时间、数据量、大小和可选备注；
- 快照不包含备份密码或应用锁凭据；
- 创建后立即验证，查看或恢复前再次验证；
- 支持手动快照和备注；
- 本地操作摘要不得包含正文、密码或敏感内容；
- 加密导出默认不包含设备绑定恢复快照。

精确 KDF、AEAD、目录结构、文件切换和 WorkManager 方案由 PR09 设计与验证。
