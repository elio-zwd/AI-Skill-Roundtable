### 已确认用户决定

- A/B 描述的是同一个“角色”一级页面的两种分类状态，不是两个一级页面。
- 顶部分类 Chip 始终存在。“全部”选中时，主体采用 A 原版的推荐总览结构：推荐、最近使用、全部角色。
- 具体分类选中时，主体采用 B 的结构：分类说明卡与双列角色目录。
- 切换分类不改变一级导航，不提升任何角色的地位，也不改变当前会话的参与关系。
- 2026-09-10 用户确认：角色分类使用独立角色展示事实源；顶部统一为“收藏 + 筛选”；真人型角色卡保留轻量 `AI 模拟角色`。
- UI-02 当前只是固定可推荐角色集合，因此推荐区标题固定使用 **`推荐角色`**，不得写成个性化 **`为你推荐`**；`defaultOrder`、固定配置或 `recommendable=true` 都不能被表述为个性化依据。

### 2026-09-10 角色数量复核

重新核查当前 `main` 后确认：

- `OfficialSkillCatalog` 当前固定为 **44 项**；
- `official_skill_execution_manifest_v2.json` 已给 1～44 项提供正式执行资产；
- 旧 `skills_config.json` / Room `Character` 主要仍是早期 20 项对话阵容兼容层，不能继续作为【角色】页全集；
- 当前 `OfficialSkillCatalogRoute` 已能浏览完整官方 Catalog，但 `OfficialSkillUseRequest` 尚未把第 21～44 项真正接入 Dialog participant 链。

因此原 20 项分类 Plan 被撤回为施工依据。角色页后续必须以当前有效 `OfficialSkillCatalog` 为全集事实源。

### 当前建议、待用户审查

44 项对账草稿建议：

1. 44 项全部作为可发现的 Skill 角色进入【角色】目录；`WORKFLOW_CAPABILITY` 不自动等同于后台工具。
2. 最大程度保留已选 B 图的原五类，并新增两类，形成：`全部 / 思考方法 / 职业成长 / 研究学习 / 产品创造 / 沟通表达 / 办公事务 / 生活支持`。
3. 固定 `推荐角色` 不再取 `defaultOrder` 前三名，而使用显式编辑精选；初始建议为 `调研与事实核查助手 / 产品与竞品分析助手 / 理查德·费曼`。
4. 真人型角色使用稳定人物头像并标记 `AI 模拟角色`；功能型角色使用稳定的非真人身份图形，不为凑“人物感”生成虚构人脸。

这些建议在用户审查前不得写入生产 assets，也不得据此开始 Android 实现。

### 统一与排除

- 两种状态必须统一页面标题、顶部操作、搜索框、分类 Chip、底部四项导航和滚动行为。A、B 图片中互不一致的顶部结构不能原样各实现一套。
- 图片中的角色姓名、头像、收藏状态、推荐顺序、标签和分类数量均为样例，实施时读取真实角色资源与用户状态。
- 真人型角色必须显示“AI 模拟角色”提示，不能让图片中的示例标记遗漏成为实现依据。
- 固定角色推荐集合可以使用显式编辑精选顺序，但不能把它描述为算法匹配、排名或针对用户的个性化推荐。
- 状态栏、挖孔、底部系统手势条由 Android 系统负责，不能在应用内绘制。
- A v2、C 以及浏览器出图中的其他主页面版本没有被本次决定选中。

### 用户决定与产品约束

- 主页面采用“资料汇总卡 + 成果汇总卡 + 最近使用的资料 + 最近保存的成果”的总览结构。
- 两张汇总卡分别进入完整资料列表和完整成果列表；两个对象保持清晰区分。
- 右上角新增入口用于新增资料。成果只能由用户对对话内容明确执行“保存为成果”后产生，不能通过该入口直接创建正式成果。
- 底部提示“只有你明确保存的内容才会成为成果”属于需保留的产品语义，最终文案可在规格审查时微调。

### 统一与排除

- 图片中的数量、文件名、日期、会话次数、来源会话和摘要均为样例，实施时使用真实数据与空状态。
- 搜索范围、排序和查看全部后的列表形态需要在规格中明确，不能仅凭图标推断已存在能力。
- 状态栏和底部系统手势条由 Android 系统负责，不在应用内绘制。
- A、C 以及浏览器出图中的其他资料主页面版本没有被本次决定选中。
