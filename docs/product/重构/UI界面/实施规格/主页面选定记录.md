### 用户决定

- 这两张图描述的是同一个“角色”一级页面的两种分类状态，不是两个一级页面。
- 顶部分类 Chip 始终存在。“全部”选中时，主体采用 A 原版的推荐总览结构：推荐、最近使用、全部角色。
- “思考方式”等具体分类选中时，主体采用 B 的结构：分类说明卡与双列角色目录。
- 切换分类不改变一级导航，不提升任何角色的地位，也不改变当前会话的参与关系。

### 统一与排除

- 两种状态必须统一页面标题、顶部操作、搜索框、分类 Chip、底部四项导航和滚动行为。A、B 图片中互不一致的顶部结构不能原样各实现一套。
- 图片中的角色姓名、头像、收藏状态、推荐顺序、标签和分类数量均为样例，实施时读取真实角色资源与用户状态。
- 真实人物型角色必须显示“AI 模拟角色”提示，不能让图片中的示例标记遗漏成为实现依据。
- 状态栏、挖孔、底部系统手势条由 Android 系统负责，不能在应用内绘制。
- A v2、C 以及浏览器出图中的其他主页面版本没有被本次决定选中。

### 规格 AI 必须解决

1. 统一两张图的顶部栏与分类 Chip 位置，明确固定区和滚动区。
2. 明确“全部”内容中的推荐、最近使用、全部角色是否分段懒加载，以及无推荐、无最近记录时的状态。
3. 明确具体分类的分类说明来源、排序、筛选、收藏和进入详情行为。
4. 核查现有 Skill 元数据是否支持分类；缺少真实字段时列为实现依赖，不凭图片硬编码临时分类。

### 用户决定与产品约束

- 主页面采用“资料汇总卡 + 成果汇总卡 + 最近使用的资料 + 最近保存的成果”的总览结构。
- 两张汇总卡分别进入完整资料列表和完整成果列表；两个对象保持清晰区分。
- 右上角新增入口用于新增资料。成果只能由用户对对话内容明确执行“保存为成果”后产生，不能通过该入口直接创建正式成果。
- 底部提示“只有你明确保存的内容才会成为成果”属于需保留的产品语义，最终文案可在规格审查时微调。

### 统一与排除

- 图片中的数量、文件名、日期、会话次数、来源会话和摘要均为样例，实施时使用真实数据与空状态。
- 搜索范围、排序和查看全部后的列表形态需要在规格中明确，不能仅凭图标推断已存在能力。
- 状态栏和底部系统手势条由 Android 系统负责，不在应用内绘制。
- A、C 以及浏览器出图中的其他资料主页面版本没有被本次决定选中。
