### 用户决定

- 两张图描述同一个“角色”一级页面的两种分类状态，不是两个一级页面。
- 顶部分类 Chip 始终存在；`全部` 使用 A 的推荐总览；具体分类使用 B 的分类说明 + 双列角色目录。
- 切换分类不改变一级导航，不提升任何角色地位，也不改变当前会话参与关系。
- 顶部统一为 `收藏 + 筛选`。
- 真人型角色卡保留轻量 `AI 模拟角色`，完整声明进入详情/首次使用。
- 固定推荐集合区块只允许写 **`推荐角色`**，不得写个性化 **`为你推荐`**。
- 重新核查后，【角色】页全集以当前有效 **OfficialSkillCatalog 44 项**为准，旧 20 项 Character 只作为兼容执行/视觉补充，不再决定全集。
- 当前 44 项全部作为可发现 Skill 角色进入目录。
- 主发现分类采用：`全部 / 思考方法 / 职业成长 / 研究学习 / 产品创造 / 沟通表达 / 办公事务 / 生活工具`。
- 固定精神/思想型编辑精选采用：**纳瓦尔 / 理查德·费曼 / 纳西姆·塔勒布**。
- 功能型角色使用稳定非真人身份图形，不为了人物感生成虚构人脸。

### 统一与排除

- A/B 两种状态统一页面标题、顶部操作、搜索、分类 Chip、底部四项导航和滚动行为。
- 图片中的角色姓名、头像、收藏状态、推荐顺序、标签和分类数量均为视觉样例；生产数据读取真实事实源。
- `defaultOrder` 可以用于稳定目录顺序，但不能解释成推荐分数或个性化。
- `推荐角色` 使用显式编辑精选顺序，不使用 Catalog 前三项冒充推荐算法。
- 角色浏览不批量写旧 Character；只有真正开始/加入对话时才按需建立兼容执行行。
- 状态栏、挖孔、底部系统手势条由 Android 系统负责，不在 App 内绘制。
- A v2、C 以及其他未选主页面版本不在本次实现范围。

### 已解决的规格问题

1. A/B 顶部栏、分类、固定/滚动区已经统一。
2. 推荐、最近使用、全部角色与分类网格的状态边界已经明确。
3. 角色分类不从 Skill tags 临时推导；使用独立 presentation 映射。
4. 固定推荐不伪装个性化。
5. 角色全集从错误的 20 项 Character 修正为 44 项 OfficialSkillCatalog。
6. `生活支持` 已按用户决定改为 `生活工具`。
7. UI-02 完成条件增加：第 21～44 项必须能真实完成“开始新对话 / 增加到当前会话”并成为 participant。

### 用户决定与产品约束

- 主页面采用“资料汇总卡 + 成果汇总卡 + 最近使用的资料 + 最近保存的成果”的总览结构。
- 两张汇总卡分别进入完整资料列表和完整成果列表；两个对象保持清晰区分。
- 右上角新增入口用于新增资料。成果只能由用户对对话内容明确执行“保存为成果”后产生，不能通过该入口直接创建正式成果。
- 底部提示“只有你明确保存的内容才会成为成果”属于需保留的产品语义，最终文案可在规格审查时微调。

### 统一与排除

- 图片中的数量、文件名、日期、会话次数、来源会话和摘要均为样例，实施时使用真实数据与空状态。
- 搜索范围、排序和查看全部后的列表形态需要在规格中明确，不能仅凭图标推断已存在能力。
- 状态栏和底部系统手势条由 Android 系统负责，不在应用内绘制。
- A、C 以及浏览器出图中的其他资料主页面版本没有被本次决定选中。
