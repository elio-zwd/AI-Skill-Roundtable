## 2. 页面定位

【角色】是一级页面，用于发现、理解、收藏和选择可以参与对话的 **Skill 角色**。

本页不是内部 Skill 能力后台、Agent 市场、排行榜或多智能体编排控制台。角色之间视觉与产品地位平级。

当前有效 `OfficialSkillCatalog` 的 **44 项全部作为可发现 Skill 角色进入本页**。`WORKFLOW_CAPABILITY` 只表示能力组织方式，不自动等于隐藏工具。未来真正没有独立对话身份的纯工具应通过明确字段排除，而不是按主类型推断。

角色身份、名称、summary、能力、发布与执行资格以当前有效 OfficialSkillCatalog / execution Manifest 为事实源；旧 `skills_config.json` / Room `Character` 不再决定角色全集。

## 3. 统一页面骨架

```text
系统状态栏 / Insets
┌─────────────────────────────┐
│ Skill 角色                   │  固定标题区
│ 和不同的思考方式对话   收藏 筛选 │
├─────────────────────────────┤
│ 搜索框                       │
│ 横向分类 Chip                │  以下为一个纵向滚动容器
│ 分类弱提示                   │
│                             │
│ if 全部                      │
│   推荐角色                    │
│   Hero + 2 次级推荐           │
│   最近使用                    │
│   全部角色（单列）            │
│ else                         │
│   分类说明卡                  │
│   双列角色目录                │
├─────────────────────────────┤
│ 对话 / 角色 / 资料 / 我的     │  共享底部导航
└─────────────────────────────┘
系统手势区 / Insets
```

固定规则：

- 标题区位于系统状态栏安全区下方。
- 搜索、Chip、提示与主体共用一个纵向滚动容器，避免嵌套纵向滚动。
- Chip 行可独立横向滚动。
- 切换分类后主体回到内容顶部；搜索词保留。
- 底部导航由共享 App shell 提供，UI-02 不创建私有 Bottom Navigation。

## 4. 分类

Chip 固定为：

`全部 / 思考方法 / 职业成长 / 研究学习 / 产品创造 / 沟通表达 / 办公事务 / 生活工具`

分类只是发现入口。每个角色配置一个 `primaryDiscoveryCategory`，详情与搜索仍使用 OfficialSkillCatalog 多维标签表现跨领域能力。

分类说明建议：

| 分类 | 说明 |
|---|---|
| 思考方法 | 检查假设、比较框架、识别风险与盲区 |
| 职业成长 | 求职、职业选择、职场协作与考试路径 |
| 研究学习 | 学习理解、技术研究与事实核查 |
| 产品创造 | 产品、创业、经营、增长与竞品判断 |
| 沟通表达 | 内容、传播、表达、谈判与现实沟通文案 |
| 办公事务 | 会议、文档、合同、人事、交接与申报材料 |
| 生活工具 | 消费、自我管理、关系、礼仪与文化类日常辅助 |

44 项一对一分类映射以 `2026-09-10-ui-02-role-catalog-decisions.md` 为准。

## 5. `全部` 状态

### 5.1 推荐角色

区块标题固定为 **`推荐角色`**。

当前没有真实用户个性化排序依据，禁止使用 `为你推荐`，禁止用 `defaultOrder`、点击量、人物名气、风险等级或 `recommendable=true` 冒充个性化/可靠性排序。

固定精神/思想型编辑精选：

1. Hero：纳瓦尔 `naval_ravikant`
2. 次级：理查德·费曼 `richard_feynman`
3. 次级：纳西姆·塔勒布 `nassim_taleb`

三项分别强调人生选择与自主、求真与理解、不确定性与反脆弱。实现使用显式 `featuredOrder=1..3`。

Hero：左侧头像/人物视觉约 36%～40%，右侧角色名、定位/推荐理由、最多 3 个弱标签和 `查看角色`。不得展示排名、百分比、热度或评分。

### 5.2 最近使用

- 仅由真实使用记录产生；打开详情不计入最近使用。
- 主页面最多突出 2 个最近使用角色。
- 无记录时隐藏整个区块，不伪造占位角色。

### 5.3 全部角色

- 必须覆盖当前 OfficialSkillCatalog 44 项。
- 使用单列角色行，Catalog `defaultOrder` 只作为稳定目录顺序，不表示排名。
- 每行：稳定头像/身份图形、姓名、最多两行说明、收藏、Chevron。
- 整行进入详情；收藏为独立至少 48dp 热区，不连带触发详情。

## 6. 具体分类状态

- Chip 下显示分类说明卡。
- 主体使用双列角色卡；目标 412dp 级逻辑宽度维持双列。
- 当大字体/窄屏不足以安全显示内容时允许单列降级。
- 搜索词与当前分类取交集。
- 无结果显示明确空状态，不静默切回 `全部`。

## 7. 搜索、收藏、最近

### 搜索

搜索至少覆盖官方名称、别名、summary、领域/场景/输出标签，并与当前发现分类组合过滤。

### 收藏

- 继续使用真实 OfficialSkillPreferences 收藏持久化。
- 收藏不改变角色可靠性或官方排序。

### 最近使用

只有真实完成“开始新对话”或“增加到当前会话”等使用动作后才记录。失败、打开详情、收藏、筛选、搜索都不写最近使用。

## 8. 头像与角色视觉

### 真人/人物模拟角色

- 优先复用仓库稳定人物头像。
- 列表/卡片使用轻量 `AI 模拟角色` 标签。
- 详情/首次使用显示完整 `personDisclaimer`。
- 不把生成候选图裁剪成生产头像。

### 功能型角色

- 使用稳定非真人身份图形；不为人物感生成虚构人脸。
- 可采用分类弱色 + 名称缩写/稳定图形。
- 同一个 Skill ID 的身份图形必须跨页面稳定，不随机变化。

## 9. 全屏角色详情

点击任何角色卡进入全屏二级详情。返回时恢复原分类、搜索和滚动位置。

详情至少展示：

- 名称、角色定位/summary；
- 适合的问题/场景；
- 思考方式或工作方式；
- 输入、输出与边界；
- 真人角色完整 AI 模拟/非本人声明。

底部固定动作：

- `开始新对话`
- `增加到当前会话`

当前没有有效会话时，增加到当前会话禁用并说明原因。Screen 只发动作，不直接写数据库。

## 10. 44 项真实进入对话的完成条件

UI-02 不能只完成目录换皮。当前旧 Dialog 仍依赖 Room `Character` / participantIds / RoundtableOrchestrator，因此第 21～44 项必须通过按需兼容桥接进入对话。

目标链路：

```text
OfficialSkillCatalog（44，权威）
→ 用户开始/增加角色
→ conversation role compatibility adapter
→ 按需 upsert legacy Character
→ participantIds
→ 现有 RoundtableOrchestrator / SkillLoader
```

要求：

- 浏览角色页不批量写 Character。
- 同 ID 旧 Character 只能提供 avatar/voice/vector 等补充；官方名称、summary、assetPath、order、执行资格不得被旧数据覆盖。
- `开始新对话` 必须原子序列完成兼容角色写入、会话创建、participantIds 持久化，再发布当前会话，避免空会话竞态。
- `增加到当前会话` 必须防止会话切换竞态。
- 成功后才写最近使用；失败不得伪装为已加入。

## 11. 视觉参数与可访问性

沿用共享视觉基线：近白冷灰紫背景、白色 Surface、蓝色交互/选中、弱描边、大圆角、低阴影。

起始估计：

- 页面左右 16～20dp；
- 区块间距 20～24dp；
- 搜索高 52～56dp；
- Chip 高约 36～40dp；
- 标题 24～28sp；
- 卡片正文约 15～17sp；
- 所有交互热区至少 48dp。

这些 dp/sp 不是从 PNG 像素机械换算的真值。最终以 Xiaomi 14 Ultra 1440×3200 运行截图对照 A/B 选定图校准。

## 12. 状态

必须覆盖：Catalog loading/error、无推荐、无最近、搜索无结果、分类无结果、长名称、大字体、窄屏、不可执行角色动作失败。

Catalog 加载失败时显示安全错误态，不退回旧 20 项冒充完整目录。

## 13. 验收要点

- 角色总数以 OfficialSkillCatalog 为准，当前为 44。
- 7 类主发现映射合计 44，无遗漏、无重复。
- 页面文案使用 `生活工具`，不残留旧 `生活支持`。
- 推荐区为纳瓦尔 / 费曼 / 塔勒布，且标题只有 `推荐角色`。
- 第 21～44 项可真实 start-new / add-current，并能成为 Dialog participant。
- 真人模拟声明、功能型非真人稳定视觉正确。
- 多角色平级；增加角色不自动触发交叉讨论。
- A/B 页面结构与选定图片保持一致的层级、密度、圆角、留白和视觉语言。
- 只有实际测试/截图证据存在后才可宣布实现完成。
