### 1.1 采纳与排除

已确认采纳：

- `全部`：A 原版的信息层级——推荐、最近使用、全部角色。
- 具体分类：B 原版的信息层级——分类说明、双列角色目录。
- 两种状态都保留分类 Chip，不把 A、B 做成两个页面或两套顶部栏。
- 一级底部导航固定为 `对话 / 角色 / 资料 / 我的`，当前 `角色` 选中。
- Skill 角色采用人物化呈现，角色之间视觉平级。
- UI-02 当前推荐区来自固定的可推荐角色集合，因此区块标题固定为 `推荐角色`；只有未来存在真实用户上下文排序依据时，才能另行改为 `为你推荐`。

明确排除：

- A v2、C 和其他未选主页面候选。
- 排行榜、评分、热度、下载量、市场/商店心智。
- 主角色/副角色、队长、皇冠、默认正反方。
- 在主页面直接“自动加入会话”或点击角色即自动执行。
- 将生成图中的示例姓名、推荐顺序、收藏状态、头像、标签数量硬编码成生产数据。
- 用 `defaultOrder`、固定顺序或 `recommendable=true` 冒充“为你推荐”的个性化依据。

### 1.2 尺寸事实与估计边界

选定 PNG 的仓库路径、哈希和实际文件尺寸由选图记录确认。本文不把图片像素直接换算为 Compose dp；下文 dp/sp 使用共享视觉基线与目标 412dp 级逻辑宽度给出**实施起始估计**，最终以 Xiaomi 14 Ultra 1440 × 3200 真机/模拟器运行截图对比为准。

## 2. 页面职责与入口

### 2.1 页面职责

【角色】是一级页面，负责：

1. 让用户发现可作为对话参与者的 **Skill 角色**；
2. 快速理解不同角色最稳定的思考方式和擅长领域；
3. 通过推荐、最近使用、分类和搜索降低查找成本；
4. 查看角色详情、收藏角色；
5. 从详情页明确选择“开始新对话”或“增加到当前会话”。

本页不是：

- 内部 Skill 能力目录；
- Agent 市场；
- 多智能体编排控制台；
- 模型/Prompt/执行门禁后台；
- 当前会话参与角色管理面板。

纯工具或工作流能力如果不作为独立对话主体存在，不应为了填满目录而伪装成人物角色。

### 2.2 进入与退出

- 从底部一级导航点击 `角色` 进入本页。
- 页面默认分类为 `全部`。
- 点击角色卡、推荐 Hero 或 `查看角色` 进入对应 **Skill 角色详情全屏页**。
- 从详情页顶部返回或系统返回时，恢复角色页原分类、搜索词和滚动位置。
- 一级页面系统返回遵循 App 顶层导航既有 Android 语义，不自行制造二级返回栈。
- 主页面本身不直接开始模型调用，不直接改变当前会话参与关系。

## 3. 布局与视觉参数

### 3.1 统一页面骨架

采用以下单一骨架，不为 A/B 分别创建两套页面：

```text
系统状态栏 / Insets（系统绘制）
┌─────────────────────────────┐
│ 页面标题区：Skill 角色       │  固定
│ 副标题 + 收藏 / 筛选         │
├─────────────────────────────┤
│ 搜索框                       │  以下作为同一个纵向滚动容器
│ 横向分类 Chip                │
│ 分类弱提示                   │
│                             │
│ if 全部                      │
│   推荐角色                    │
│   Hero + 次级推荐             │
│   最近使用                    │
│   全部角色（单列）            │
│ else                         │
│   分类说明卡                  │
│   双列角色目录                │
│                             │
├─────────────────────────────┤
│ 对话 / 角色 / 资料 / 我的     │  固定
└─────────────────────────────┘
系统手势区 / Insets（系统绘制）
```

固定规则：

- 页面标题区固定在系统状态栏安全区下方。
- 底部一级导航固定在系统导航 Insets 上方。
- 搜索、分类 Chip、分类提示和主体内容使用一个纵向滚动容器；不要把 A 的列表、B 的网格再套进独立纵向滚动导致手势冲突。
- 分类 Chip 行自身允许水平滚动。
- 切换分类后主体滚动回该页面内容顶部；搜索词保留，便于用户对不同分类比较同一关键词。

### 3.3 `全部` 状态——A 推荐总览

#### 推荐角色

- 区块标题固定为 `推荐角色`。UI-02 当前只展示固定的可推荐角色集合，没有用户相关排序依据，因此不得写 `为你推荐`。
- 固定集合可以按稳定目录顺序展示；`defaultOrder` 只表示稳定展示顺序，不表达算法匹配度、热度或个性化。
- 第一条推荐使用横向 Hero 卡：左侧人物半身肖像约占卡宽 36%～40%，右侧为角色名、角色定位/推荐理由、最多 3 个弱标签和 `查看角色` 描边按钮。
- Hero 背景为极浅蓝紫/角色弱色，1dp 弱描边，20～24dp 大圆角，阴影 0～2dp。
- Hero 建议高度约 180～220dp；在目标首屏中不得超过可用内容高度约 28%。
- Hero 后可展示最多 2 张次级推荐卡；两张横排时等宽，卡间距约 12dp。卡片不展示排名、百分比、热度或算法分数。
- 推荐不足 3 个时不保留空卡位；没有可推荐角色时隐藏整个推荐区块，不用伪造角色填充。
- 未来若新增基于收藏、最近使用、用户当前上下文等真实信号的个性化角色页推荐策略，应单独设计、测试并审查后，才允许将标题改为 `为你推荐`。

#### 最近使用

- 区块标题：`最近使用`；右侧 `查看全部` 仅在存在超过主页面展示数量的记录时显示。
- 主页面最多突出 2 个最近真正进入使用流程的角色；查看详情不计入最近使用。
- 紧凑卡包含头像、姓名、一行能力说明、最近使用时间；不显示“增加”按钮。
- 无最近使用时整个区块隐藏，不显示占位空卡；完整空状态由后续“最近使用”页面规格负责。

#### 全部角色

- 区块标题：`全部角色`。
- 使用单列角色行，按稳定角色目录顺序排列。
- 每行：圆形/轻圆角人物头像、姓名、最多两行说明、收藏星标、Chevron。
- 行高以内容自适应，建议最小 80～96dp；整行可点击进入详情，收藏图标为独立 48dp 热区，点击收藏不应同时触发详情。

### 3.4 具体分类状态——B 分类目录

分类 Chip：

- `全部`
- `思考方法`
- `职业成长`
- `研究学习`
- `产品创造`
- `沟通表达`

选中态使用交互蓝 + 极浅蓝底，未选使用白/近白底 + 弱描边。Chip 只表示发现分类，不表示角色等级、阵营或当前会话身份。

Chip 下保留弱提示：`按角色最稳定的思考方式分类`。

#### 分类说明卡

以 `思考方法` 为例：

- 标题：`思考方法`
- 说明：`适合检查假设、梳理结构和发现盲区`
- 右侧只使用极淡线性节点/关系装饰；不能使用抢视觉焦点的人物 Hero。
- 卡高建议 104～128dp；20～24dp 圆角；1dp 弱描边；背景使用该分类的极浅弱色。
- 其他分类的说明必须来自稳定的分类元数据/文案表，不从单个 Skill 标签现场拼接成一句不稳定描述。

#### 双列角色目录

- 目标宽度约 412dp 时保持两列等宽；页面左右边距 16～20dp，列间距建议 12dp。
- 单卡高宽比约 `H:W = 1.15～1.25:1`，以图片选定布局为基准微调。
- 上半部为人物半身头像/肖像与角色弱色背景；下半部为姓名、一行定位、最多 2 个小标签。
- 右上收藏星标独立可点击；整卡其余区域进入详情。
- 所有卡等宽、同一网格规则，不因推荐程度、真人身份或使用次数放大某个角色。
- 目标 412dp 宽度下角色名与一行定位必须可读；姓名最多 2 行，定位最多 2 行，标签超出则减少数量而不是挤压字体。
- 较窄设备或放大字体导致双列无法满足可读性/48dp 热区时，允许响应式降为单列；这属于 Android 可访问性适配，不改变目标设备的双列基准。

### 3.5 颜色、字体、圆角与图标

直接复用共享视觉 Token，不在角色页面建立第二套私有调色板：

- 页面背景：约 `#FCFBFE`。
- Surface：`#FFFFFF`。
- 主文字：约 `#111116`。
- 次文字：约 `#747B90`。
- 普通边框：约 `#ECECF4`。
- 交互蓝：`#0D60FD`～`#176DFF`。
- 品牌紫：`#5B3EF5`～`#6A45FF`。
- 角色弱色：浅薰衣草、浅薄荷、浅蓝等，仅作身份识别，不表达等级。
- 区块标题：18～20sp SemiBold；卡标题 16～18sp SemiBold；正文 15～17sp；元数据 12～14sp。
- 图标统一圆角端点线性风格；禁止 Emoji、3D 图标和多套线宽混用。

### 4.2 真实人物型角色

- 主页面允许在真实人物型角色卡上显示一次小号 `AI 模拟角色` 身份标记；它是身份标签，不是完整免责声明。
- 完整说明放在角色详情/首次使用：`AI 模拟角色，基于可获得资料构建，不代表本人，也不保证复现本人当前或完整观点。`
- 不在每个卡片重复长免责声明，不把角色写成真人本人在线。

### 4.3 头像与角色展示资源

生产角色卡必须拥有稳定的角色展示资源，不从生成图裁头像，也不从姓名首字临时替代后宣称视觉完成。

| 资源 | 当前核查 | 目标规则 |
|---|---|---|
| 真实人物头像 | `app/src/main/assets/avatars/` 已存在一批真人头像资源，例如 `steve_jobs.jpg` | 通过稳定角色 ID 映射；列表/详情/对话保持同一人物外貌 |
| 规划教练/系统思考者头像 | 对话 `PreviewMock` 使用 `R.drawable.avatar_planner` / `avatar_thinker` | Preview Mock 不能作为正式目录事实源；若作为正式角色需进入角色展示元数据 |

| 收藏图标、Chevron、筛选、搜索 | 可使用统一 Material/项目线性图标体系 | 统一视觉尺寸与 contentDescription |

## 5. 交互契约

| 控件 | 前置状态 | 用户动作 | 状态/数据变化 | 成功目的地 | 取消/失败/返回 |
|---|---|---|---|---|---|
| 分类 Chip | 页面已加载 | 点击 `全部` 或具体分类 | 更新当前发现分类；保留搜索词；滚动回主体顶部 | 同一角色页面切换布局 | 无网络副作用；无匹配角色显示空状态 |
| 搜索框 | 页面已加载 | 输入关键词 | 对当前角色目录做本地搜索；不修改收藏/最近 | 留在当前页并缩小结果 | 清空恢复分类默认内容 |
| 收藏星标 | 角色可收藏 | 点击 | 持久化收藏状态 | 原地更新星标 | 保存失败保持原状态并给轻量错误提示 |
| 顶部收藏入口 | 页面已加载 | 点击 | 不修改数据 | 进入收藏角色视图/页面 | 返回恢复主页面分类与滚动位置 |
| 顶部筛选入口 | 页面已加载 | 点击 | 仅打开筛选 UI | 后续筛选 Bottom Sheet/页面 | 取消不改变既有筛选；UI-03 细化 |
| Hero `查看角色` | 有推荐角色 | 点击 | 不自动使用角色 | 角色详情全屏页 | 返回恢复原滚动位置 |
| 普通角色卡 | 有角色数据 | 点击非收藏区域 | 不改变最近使用、不自动加入会话 | 角色详情全屏页 | 返回恢复原位置 |
| `查看全部` 最近使用 | 最近记录超过主页面展示上限 | 点击 | 不修改数据 | 最近使用角色视图/页面 | 返回恢复主页面 |

### 5.1 搜索与分类组合

- 搜索词非空时，搜索条件与当前分类做交集，不默默取消用户选中的分类。
- `全部` + 搜索：推荐与最近区暂时收起，主体显示匹配角色的单列结果，避免同一角色重复出现三次。
- 具体分类 + 搜索：保留分类说明的简化标题行，双列目录只显示匹配角色。
- 无结果时保留搜索词和分类 Chip，让用户知道当前约束，并提供 `清除筛选`/清空搜索入口。

### 5.2 收藏与最近使用

- 收藏是长期用户状态，现有 `OfficialSkillPreferences.favoriteIds` / `setFavorite()` 可作为持久化能力基础。
- 最近使用只在角色真正进入使用流程后记录；查看角色详情不能写入最近，现有 `OfficialSkillPreferences` 已明确该边界。
- 主页面不显示“在线”“正在使用”之类虚假状态。

### 5.3 进入详情与使用角色

本页点击角色只进入详情，不直接执行。

目标链路：

```text
角色主页面
  → Skill 角色详情全屏页
      → 开始新对话
      → 增加到当前会话（存在可用当前会话时）
```

- `开始新对话` 创建独立会话，由该角色参与。
- `增加到当前会话` 必须明确指定真实当前会话；没有可用会话时禁用，不得静默新建。
- 增加角色不会改变其他角色地位，不自动触发交叉讨论。
- 收藏角色只是收藏，不等价于使用、加入会话或设为默认角色。

### 7.1 关键架构结论

当前 `OfficialSkillCatalog` 是**能力目录事实源**，而本页面需要的是**用户侧 Skill 角色目录**。ADR-009 已明确二者不等价，因此不建议简单给每个 `OfficialSkillDefinition` 强塞一张人物头像后就称为角色。

实现前应先核查 `skills_config.json` 等既有配置是否已经包含可复用的角色化展示事实；若没有，增加一个最小的角色展示投影/manifest，以稳定 Skill ID 为键，只包含真正可作为对话参与者的角色，并承载：

- 用户侧角色名称；
- 头像资源；
- 一句话角色定位；
- 发现分类；
- 最多若干展示标签；
- 角色弱色 Token/语义；
- 真人身份标记/声明来源。

该映射层不得复制 Skill 的执行协议、风险规则和全部能力字段；执行能力仍以官方 Skill catalog 为事实源。

## 8. 验收用例

### 8.1 功能与状态

1. **全部状态**：进入【角色】 → `全部` 默认选中 → `推荐角色`、最近、全部角色按可用数据依次显示；没有数据的可选区块不留空壳。
2. **分类切换**：点击 `思考方法` → 同页切换为分类说明 + 双列目录 → 底部仍为【角色】选中 → 不创建新导航页面。
3. **连续切换**：`全部 → 思考方法 → 职业成长 → 全部` → 无主从/排名标识，列表无重复状态污染。
4. **搜索 + 分类**：输入关键词并选具体分类 → 结果取交集 → 无结果时保留查询和分类上下文，可清除恢复。
5. **收藏**：点击卡片星标 → 不进入详情 → 收藏状态持久化；重进页面仍存在。
6. **详情不计最近**：只打开角色详情再返回 → 最近使用不新增该角色。
7. **真正使用后记最近**：从详情完成开始新对话/增加会话 → 再回角色页时最近使用更新。
8. **详情返回位置**：在列表较深位置打开角色再返回 → 恢复原分类、查询和滚动位置。
9. **真人身份**：真实人物型卡有轻量 `AI 模拟角色` 身份标记；详情提供完整声明；不写成真人在线。
10. **无会话增加**：详情中没有可用当前会话 → `增加到当前会话` 明确禁用，不静默创建会话。
11. **推荐文案真实性**：UI-02 使用固定可推荐集合时，页面只显示 `推荐角色`，不得出现 `为你推荐`；固定顺序不展示任何个性化暗示。

### 8.2 视觉截图基线

固定验收环境：

- Xiaomi 14 Ultra 基准；
- 1440 × 3200；
- Android 竖屏；
- 浅色模式；
- 默认 fontScale；
- 系统状态栏/手势条由系统绘制。

至少保存两张主基准截图：

1. `全部`：有 3 个以上可推荐角色、2 个最近使用、至少 4 个全部角色；用于对比选定 A。
2. `思考方法`：分类说明 + 至少 6 个角色的双列目录；用于对比选定 B。

视觉比较优先级：

1. 顶部固定区、主体滚动区、底部导航和安全区是否正确；
2. A 的 Hero 占比、推荐/最近/全部角色层级是否接近选定图；
3. B 的双列卡比例、人物图占比、文字可读性是否接近选定图；
4. 卡片圆角、描边、颜色、图标、弱阴影；
5. 头像一致性和真实人物身份标记。

另补：至少一款较窄 Android 屏幕 + 放大字体检查，确认双列不能维持时可安全降单列，无截断关键操作。

## 9. 已确认决定与变更记录

### D1｜角色分类事实源【已确认】

为用户侧角色展示增加 `primaryDiscoveryCategory`（每个角色一个主发现分类），放在独立角色展示映射中；Skill catalog 的 `primaryType`、`primaryValue` 和 tags 继续服务能力与推荐，不拿它们临时拼 UI 分类。

原因：符合“Skill ≠ Skill 角色”的产品模型，也避免 UI 用姓名/标签启发式分类后随着文案变化漂移。

### D2｜推荐区生产语义【已确认】

UI-02 当前只有**固定的可推荐角色集合**，没有用户相关排序依据，因此：

- 区块标题固定为 **`推荐角色`**；
- 可以使用稳定顺序展示，但不得把 `defaultOrder`、收藏状态或固定配置描述成个性化匹配；
- 不显示算法分数、热度、排名或“更适合你”等未经事实支持的暗示；
- 只有未来新增并验证真实的用户上下文推荐策略后，才允许另行改为 **`为你推荐`**。

### D3｜统一顶部动作【已确认】

统一为右侧 `收藏` + `筛选`。

- 搜索由常驻搜索框承担，顶部不再重复搜索图标。
- 收藏是角色页高频个人动作。
- 筛选已有真实能力基础，并可在 UI-03 继续升级为 Bottom Sheet。
- `更多` 没有当前必须常驻的主页面动作，暂不显示。

### D4｜真实人物卡片身份标记【已确认】

主页面真人卡片保留一处小号 `AI 模拟角色`；完整免责声明只放详情/首次使用。这样既保持人物感，也不在列表重复长免责声明。

### D5｜像素级参数【已确认实施原则】

本文的 dp/sp 为实现起始估计，不作为“从 841 × 1870 图片机械换算”的硬编码值。运行后必须用选定 PNG 做截图差异校准，再冻结最终主题/组件尺寸。
