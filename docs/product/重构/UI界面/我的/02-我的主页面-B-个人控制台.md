> 目的：验证以“个人背景”作为页面第一内容，是否更符合【我的】名称。

## 1. 必须继承

遵循[共享视觉基线](../共享/jianyu-shared-visual-baseline.md)。底部导航完整显示“对话 / 角色 / 资料 / 我的”，当前【我的】蓝色选中。

## 2. 顶部栏

- 标题：`我的`
- 右侧：设置线性图标
- 顶部不单独显示账号入口、登录状态或昵称；用户头像只在下方「个人背景」卡中出现。

## 3. 个人背景 Hero

首屏顶部是一张浅薰衣草到白色的大圆角卡：

- 左侧为圆形**对话头像**：复用【对话】中用户消息气泡右侧的同一张头像；
- 头像右下叠放小型紫色编辑 / 切换图标，点击后进入头像选择，不直接表示账号登录；
- 头像必须保持低调，不使用会员、在线或社交状态徽章；
- 标题：`个人背景`
- 说明：`让 Skill 角色在你允许时理解目标、时间和约束`
- 状态：`已保存 4 项`
- 主入口：`查看与编辑`

卡片底部横向显示三个摘要 Chip：

- `职业目标`
- `可用时间`
- `表达偏好`

## 4. 快捷控制

两列四张等尺寸卡：

1. `模型与 API Key`
   - `Gemini · 2 个可用 Key`
2. `数据与隐私`
   - `导出、删除与权限`
3. `备份与恢复`
   - `尚未创建备份`
4. `遥测与诊断`
   - `已关闭`

每张卡有低饱和图标、大标题、一行状态和 Chevron。卡片同权，不做红黄绿 Dashboard 指标。

## 5. 应用偏好

底部一张白色圆角分组卡：

- `设置`
- `关于见域`

每行为列表形式。

## 6. 视觉重点

- Hero 强调的是用户主动维护的背景；头像用于建立与【对话】的一致识别，不表达账号身份；
- 个人背景卡使用紫色弱氛围，与角色人物卡不同；
- 快捷卡状态只描述候选界面数据，不能写成安全承诺；
- 不展示个人背景正文，避免主页面泄露敏感内容。

## 7. 用户主要比较点

- 是否比方案 A 更像“我的”；
- Hero 是否占用太多空间；
- 对话头像与切换入口是否清楚但不过度账号化；
- 四张快捷卡是否容易扫视；
- 无账号体系时是否仍自然。
