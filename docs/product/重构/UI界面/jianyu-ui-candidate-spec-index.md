# 见域三个主页面 UI 候选规格索引

> 文档状态：出图候选包，待用户看图选择
>
> 目标：为【角色】【资料】【我的】三个一级页面生成多套候选界面及关键子页面图片。用户选择方向后，再由后续 AI 基于选定图片编写最终页面描述规格和 UI 代码。
>
> 当前文件不代表设计定稿，不覆盖现有产品规范。

浏览器逐张出图时统一遵循：[浏览器图片 AI 生成工作流](./BROWSER-IMAGE-GENERATION-WORKFLOW.md)。

下载后的分类、选图、规格转写、代码实现与截图验收，统一从[UI 重构交接计划](./UI-RECONSTRUCTION-HANDOFF.md)进入。

## 1. 统一工作流

```text
候选描述文档
→ 图片生成 AI 为每份文档生成对应 Android 界面图
→ 用户比较并选择主页面方向、组件和子页面
→ 描述整理 AI 依据选定图片编写最终 UI 规格
→ 开发 AI 依据最终规格实现 Jetpack Compose UI
→ 对照选定图片进行截图回归和迭代
```

图片生成 AI 在处理任意候选文档前，应同时读取：

1. [共享视觉基线](./共享/jianyu-shared-visual-baseline.md)；
2. [图片输出规则](./共享/jianyu-image-generation-output-rules.md)；
3. [对话页已选定规格](./对话/jianyu-dialog-final-ui-spec.md)；
4. 当前准备出图的单份候选文档。

## 2. 一级导航统一要求

本候选包使用新的四项一级导航：

```text
对话 / 角色 / 资料 / 我的
```

这与旧对话参考图中的“对话 / 资料 / 成果 / 我的”不同。新候选图必须以本文件为准：

- 【成果】合并到【资料】页面内部；
- 新增【角色】一级页面；
- 当前页面对应的底部导航项使用蓝色选中态；
- 其余视觉语言继续匹配已选定【对话】页面。

## 6. 用户审图记录建议

用户可在每份候选文档末尾记录：

```text
图片文件：
生成模型：
是否保留：保留 / 淘汰 / 待比较
喜欢的部分：
不喜欢的部分：
需要与其他方案组合的部分：
最终决定：
```

主页面、子页面和组件可以混合选择，不要求整套采用同一个候选方向。但混合后必须由后续描述整理 AI 统一：

- 顶部栏；
- 卡片语言；
- Tab 与筛选控件；
- 底部导航；
- 页面间返回链；
- 颜色、圆角与间距。
