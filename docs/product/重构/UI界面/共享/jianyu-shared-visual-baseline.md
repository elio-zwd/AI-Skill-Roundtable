# 见域 UI 候选图共享视觉基线

> 文档状态：三个主页面候选图的共同约束
>
> 视觉事实来源：【对话】页已选定主图及 6 张展开态参考图。
>
> 本文只统一视觉语言，不替用户选择【角色】【资料】【我的】页面的具体信息架构。

## 1. 目标设备与画布

- 产品：见域
- 平台：Android
- 设备基准：Xiaomi 14 Ultra
- 方向：竖屏
- 设计画布：1440 × 3200 px
- 图片语言：简体中文
- 当前只设计浅色模式

图片顶部应呈现 Android / Xiaomi 风格系统状态栏与中央单圆挖孔，但 App 实现时挖孔和系统手势条由系统绘制。禁止出现 iPhone Dynamic Island、iOS 状态栏或 iOS Home Indicator。

## 2. 与对话页必须一致的整体气质

关键词：

```text
轻量、柔和、人物化、低对比、近白、冷紫灰、宽松留白、Android、可阅读
```

候选图必须像同一款 App 的其他页面，而不是重新设计另一套产品：

- 主背景为极浅冷紫灰，接近 `#FCFBFE`；
- 顶部栏、底部导航、Sheet 和主要卡片为白色或近白；
- 卡片使用 1dp 极淡描边和大圆角；
- 阴影只负责轻微抬升，不使用厚重悬浮阴影；
- 页面留白中等偏宽松，信息密度不能像企业后台控制台；
- 使用蓝色表达当前选中和主要执行动作；
- 使用紫色表达品牌动作、创建、编辑和描边 CTA；
- 成功状态可使用克制的绿色；
- 危险操作只在图标与文字上使用红色，不大面积铺红底。

## 3. 共享颜色起始值

| 语义 | 建议色值 | 用途 |
|---|---|---|
| 页面背景 | `#FCFBFE` | 主背景 |
| 表面 | `#FFFFFF` | 卡片、顶部栏、Sheet |
| 主文字 | `#111116` | 标题、正文 |
| 次文字 | `#747B90` | 时间、说明、元数据 |
| 弱文字 | `#A1A7B7` | 占位、禁用 |
| 交互蓝 | `#0D60FD`～`#176DFF` | 选中、确认、主要 CTA |
| 品牌紫 | `#5B3EF5`～`#6A45FF` | 新增、编辑、描边 CTA |
| 成功绿 | `#18B96C`～`#1AC477` | 已启用、已保存 |
| 普通边框 | `#ECECF4` | 搜索框、普通卡片 |
| 浅薰衣草 | `#F7F5FE` | 角色、轻提示 |
| 浅薄荷 | `#F0FAF6` | 成功、角色弱识别 |
| 浅蓝 | `#EEF5FF` | 选中项、信息提示 |
| 危险红 | `#FF3B30` | 删除、清空 |
| 遮罩 | 黑色 30%～45% | Modal Sheet / Dialog |

图片生成 AI 可以做轻微视觉校正，但不能把页面改成高饱和霓虹、深色赛博、玻璃拟态或 3D 拟物风格。

## 4. 共享形状与间距

- 基础网格：4dp；
- 页面左右边距：16～20dp；
- 区块间距：20～24dp；
- 卡片内边距：16～20dp；
- 小 Chip 圆角：14～18dp；
- 搜索框、普通按钮：16～20dp；
- 大卡片：20～24dp；
- Bottom Sheet 顶部：24～28dp；
- 点击热区最小：48dp × 48dp；
- 卡片阴影：0～2dp；
- Popover 阴影：6～12dp，但透明度低。

页面不能拥挤堆满功能，也不能为了“高级感”留下大面积无信息空白。

## 5. 共享文字与图标

字体使用 Android 中文 Sans / Xiaomi 系统字体气质，不使用 iOS SF Pro 作为视觉基准。

建议层级：

- 页面标题：24～28sp，Bold；
- 区块标题：18～20sp，SemiBold；
- 卡片标题：16～18sp，SemiBold；
- 正文：15～17sp，Regular；
- 元数据：12～14sp，Regular；
- 底部导航：12～14sp。

图标统一为圆角端点的线性图标：

- 默认灰蓝；
- 选中蓝；
- 创建与编辑紫；
- 成功绿；
- 删除红；
- 不混用 Emoji、3D 图标、彩色贴纸和多套不同线宽的图标包。

## 6. 共享顶部栏

三个主页面统一采用接近纯白的顶部栏：

- 位于系统状态栏安全区下方；
- 左侧以页面标题为主，不使用对话页 Hamburger；
- 标题下可有一句弱灰说明，但不超过一行；
- 右侧最多保留两个主要图标动作，例如搜索、筛选、新增；
- 不使用传统高饱和有色 Toolbar；
- 顶部栏与内容之间不使用粗分割线。

二级页面使用左上返回箭头、居中或左对齐标题、右侧必要动作。系统返回与顶部返回必须指向同一上级。

## 7. 新底部一级导航

所有新候选图统一显示：

1. 对话：聊天气泡图标；
2. 角色：人物头像轮廓加小星光，或双人轮廓图标；
3. 资料：文件夹图标；
4. 我的：单人轮廓图标。

视觉规则：

- 四等分；
- 图标在上、文字在下；
- 当前项蓝色、可使用实心或略高强调；
- 其余项灰蓝线性；
- 【角色】图标必须与【我的】明显区分；
- 白色背景，顶部极淡分割线；
- App 导航内容高度约 64～72dp，另加系统导航 Insets。

## 8. 人物与角色视觉

出现 Skill 角色时必须沿用对话页规则：

- 使用写实或半写实人物化头像，不使用模型 Logo；
- 同一角色在列表、卡片和详情中保持同一张脸、服装和气质；
- 角色可有极弱薰衣草、薄荷、浅蓝等个性色；
- 角色色只用于识别，不表达等级、阵营、正方或反方；
- 真实人物型角色在详情或首次使用处显示“AI 模拟角色，不代表本人”的弱提示；
- 不在每个列表卡和每条消息中反复展示免责声明。

## 9. Drawer、Sheet、Popover 与 Dialog

沿用对话页的交互形态：

- 大型选择与编辑：白色 Modal Bottom Sheet，顶部大圆角、Handle、必要时 Scrim；
- 输入辅助选择：轻模态 Bottom Sheet，可减少 Scrim；
- 少量锚定菜单：白色 Popover，无 Scrim；
- 高风险确认：居中 Dialog 或专用确认 Sheet，危险动作红色文字；
- 所有 Sheet 和 Dialog 都必须保留清晰关闭、取消和返回路径。

## 10. 图片中禁止出现

- iOS 专属系统视觉；
- 主 Skill、副 Skill、队长、皇冠；
- 默认正方、反方；
- Run ID、Interaction ID、响应批次、编排器状态；
- API Key 完整明文；
- “绝对安全”“永不丢失”等承诺；
- 把普通 AI 回复自动标成正式成果；
- 把真实人物型角色表述为真人本人在线；
- 与对话页完全不同的暗色、霓虹、强玻璃或企业后台风格。
