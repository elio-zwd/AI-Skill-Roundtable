# 见域 UI 候选图片生成与交付规则

> 用途：约束图片生成 AI 的输出，减少无法比较、文字乱码和跨方案混搭。

## 1. 一份文档对应的输出

- 主页面候选文档：生成 1 张完整页面图；
- 二级页面文档：生成 1 张完整二级页面图；
- Bottom Sheet / Dialog 文档：生成 1 张带真实背景上下文的展开态图；
- 组件板文档：生成 1 张 1440 × 3200 的组件样式板；
- 状态组文档：生成 3～4 张同布局不同状态的页面图，或生成一张明确分栏的状态对比板；
- 不在一张主页面图中混合 A、B、C 三种互斥方案。

## 2. 画布与系统环境

- 1440 × 3200 px；
- Android 竖屏；
- Xiaomi 14 Ultra 中央单圆挖孔；
- 简体中文；
- 浅色模式；
- 底部为 Android 手势导航区，不模拟 iOS。

## 3. 中文文字要求

- 必须尽量准确呈现文档给出的标题、按钮和示例内容；
- 不生成无法辨认的伪中文；
- 文本超长时使用真实省略号或合理换行；
- 不擅自把“Skill 角色”缩成“智能体”“Agent”或“机器人”；
- 不把“资料”和“成果”混成同一对象名称。

## 4. 图片一致性要求

- 共享视觉基线优先于模型默认审美；
- 同一批图片中的顶部栏、底部导航、圆角、蓝紫强调色保持一致；
- 同一 Skill 角色复用同一人物外貌；
- 同一文件、成果、设置项在不同图片中使用一致名称；
- 若文档没有要求人物，不要额外加入装饰性真人照片；
- 若文档要求底部导航，必须显示新的“对话 / 角色 / 资料 / 我的”。

## 5. 交付命名

建议按文档文件名输出，例如：

```text
01-角色主页面-A-推荐优先.png
04-Skill角色详情全屏页.png
08-保存为成果-BottomSheet.png
```

同一文档有多个状态时追加：

```text
-empty
-content
-selected
-error
```

## 6. 不确定内容处理

候选文档中标注“待用户选择”的内容，图片生成 AI应：

- 只实现当前候选文件指定的那一种方向；
- 不把其他候选方向混进来；
- 不自行宣布它是最终方案；
- 可在文件名或图片外部说明中标注候选编号，但不要把“A 方案”等工程字样画进 App UI。

## 7. 图片生成后需要记录

在对应文档末尾或独立审图记录中填写：

```text
图片路径：
生成日期：
是否保留：
保留元素：
需要修改：
最终是否入选：
```
