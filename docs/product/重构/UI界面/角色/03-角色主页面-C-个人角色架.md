# 【角色】主页面候选 C｜个人角色架

> 图片类型：完整一级页面候选图
>
> 输出：1 张 1440 × 3200 Android 竖屏图片
>
> 目的：判断“先服务已使用角色，再发现新角色”是否更符合长期使用。

## 1. 必须继承

遵循[共享视觉基线](../共享/jianyu-shared-visual-baseline.md)。底部导航为“对话 / 角色 / 资料 / 我的”，【角色】蓝色选中。

## 2. 页面状态

- 收藏：研究员、系统思考者；
- 最近使用：规划教练、系统思考者、产品顾问；
- 角色总数：6；
- 不存在角色等级或默认主角色。

## 3. 页面布局

### 顶部栏

- 标题：`Skill 角色`
- 副标题：`你常用的思考伙伴`
- 右侧搜索图标

### 我的角色架

首屏顶部是一张白色大圆角容器，标题：`我的角色架`

内部横向排列 3 个圆形人物头像：

- 研究员；
- 系统思考者；
- 规划教练。

每个头像下显示姓名。收藏角色头像右上角有小紫色星标；最近使用角色不加等级徽章。

容器底部两个等宽弱按钮：

- `查看收藏`
- `管理最近使用`

### 最近使用

使用单列宽卡，每行包含：

- 左侧大圆形头像；
- 姓名；
- 最近一次使用场景，例如 `昨天 · 目标拆解`；
- 一行能力说明；
- 右侧蓝色轻按钮：`开始对话`。

显示规划教练、系统思考者、产品顾问三行。

### 发现新角色

标题：`发现新角色`

横向两张推荐卡：

- 苏格拉底；
- 史蒂夫·乔布斯。

卡片仅有“查看”入口，不直接自动开始对话。

底部文字入口：`浏览全部角色  →`

## 4. 视觉重点

- “我的角色架”有轻微个人化，但不能做成社交好友列表；
- 头像和姓名是第一识别信息；
- “开始对话”蓝色轻按钮要比人物信息弱；
- 新角色发现区域在首屏下半部，明显但不压过常用角色；
- 保留宽松留白和淡紫、薄荷角色色。

## 5. 不要生成

- 好友在线列表、私信红点、粉丝数；
- 养成、等级、经验值；
- “我的团队”“队长”；
- 强行给收藏角色更大头像形成权力关系。

## 6. 用户主要比较点

- 对新用户而言是否显得内容不足；
- 对老用户而言是否比推荐优先更高效；
- “我的角色架”是否会被误解为主从团队；
- 角色发现入口是否太弱。
