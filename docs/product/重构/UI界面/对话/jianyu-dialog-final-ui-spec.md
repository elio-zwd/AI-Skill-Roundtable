> 文档用途：供后续 Android / Jetpack Compose UI 开发 AI 直接实现当前已选定的视觉方案。  
> 视觉主参考：`ChatGPT Image 2026年8月27日 09_04_44.png`。  
> 展开状态参考：其余 6 张 `09_22_51 / 09_22_52 / 09_22_53` 图片。  
> 本文只拆解现有设计，不重新设计、不增加新的一级页面、不改变 Skill 角色的产品语义。

## 1. 页面定位

### 1.1 产品与页面

- 产品名称：**见域**
- 当前页面：**对话**
- 页面级别：Top 1 核心页面 / 应用首要核心体验
- 目标设备：**Xiaomi 14 Ultra**
- 平台：**Android**
- 方向：**竖屏**
- 设计基准画布：**1440 × 3200 px**
- 界面语言：**简体中文**

### 1.2 核心体验定义

本页面不是“多工具调用控制台”，而是一个具有 IM / 群聊感的多角色 AI 对话界面。

用户面对的是一个或多个**平级的 Skill 角色**。每个 Skill 角色以人物化方式出现，具有自己的：

- 姓名
- 人物化头像
- 稳定人格感
- 稳定思维方式
- 稳定表达方式
- 擅长领域

页面不出现模型 Logo、模型名称、Agent 编排关系、主从关系或“正方 / 反方”标签。

多个 Skill 角色默认独立形成判断。只有用户主动触发**交叉讨论**时，才显式进入角色间互相参考观点的讨论状态。

### 1.3 角色关系约束

所有 Skill 角色在产品语义上完全平级。

视觉中允许存在：

- 当前活跃角色强调
- 当前回复角色强调
- 最近互动角色强调
- 角色自身专属的弱色彩识别

但这些视觉差异**不得解释成角色等级、领导关系、主助手 / 副助手关系**。

## 3. Xiaomi 14 Ultra 适配基准

### 3.1 安全区

必须按 Xiaomi 14 Ultra 的 Android 系统 Insets 实际获取：

- `statusBars`
- `navigationBars`
- `ime`
- `displayCutout`

不要硬编码状态栏高度，也不要将图片中的黑色圆形挖孔当作 App 自绘元素。

### 3.2 中央挖孔

截图顶部中央存在 Xiaomi 14 Ultra 风格的**单圆形前摄挖孔**。

开发要求：

- App 不绘制黑色圆点。
- 顶部内容避开 `displayCutout`。
- 标题区域仍保持视觉居中于 App 内容区域，不要为了挖孔把整行内容异常下移。
- 禁止使用 iOS Dynamic Island 视觉。

### 3.3 Android 手势导航区

截图底部存在系统灰色手势导航条。

它属于 Android 系统导航区域，不是 App 的 iOS Home Indicator。

开发要求：

- 不在 Compose 中自行绘制该灰色条。
- Bottom Navigation 必须使用 `navigationBarsPadding()` 或等效 Insets 处理。
- 页面背景延伸到系统导航区，视觉保持白色 / 近白色连续表面。

### 3.4 dp / sp 使用原则

1440 × 3200 px 只用于还原：

- 视觉比例
- 区域占比
- 对齐关系
- 密度
- 元素相对尺寸

**禁止直接使用 `px = dp`。**

Compose 最终实现应：

1. 先按本文给出的相对比例搭建；
2. 使用 Android `dp` / `sp`；
3. 在 Xiaomi 14 Ultra 真机或等尺寸模拟环境中校准；
4. 以截图视觉匹配为最终判断，而不是机械按像素换算。

## 4. 整体视觉语言

### 4.1 设计风格

整体是**轻量化、人物化、柔和低对比的 AI 多角色聊天界面**。

它借用了 Material 3 的部分结构习惯：

- Bottom Sheet
- Navigation Bar
- Drawer
- 圆角卡片
- Snackbar / Chip 式状态
- 线性图标

但并不是 Material 3 默认皮肤，而是明显存在一套自定义视觉语言：

- Skill 角色使用真人感 / 人像感头像而非模型 Logo。
- 不同 Skill 角色使用极弱的个性色背景。
- 角色卡、消息卡、Sheet 都使用较大的圆角。
- 边框很淡，阴影非常轻。
- 主色同时使用**亮蓝**与**紫色**，而不是单一 Material Primary。
- 角色识别增加**浅薰衣草紫**和**浅薄荷绿**。
- 页面整体接近白色，但不是完全纯白平铺；背景存在很弱的冷紫灰倾向。

### 4.2 明暗模式

当前截图只定义**浅色模式**。

未定义：

- 深色模式
- 自动深浅切换后的角色色如何变化
- OLED 黑背景方案

因此当前实现应优先忠实完成 Light Theme。

### 4.3 背景

主体页面背景目测接近：

- `#FCFBFE`
- `#FBFAFD`
- 或极浅冷紫灰

顶部导航与底部导航接近纯白。

聊天内容区域在白底上带有极轻的冷紫雾感，不应做明显纹理。

### 4.4 强调色

视觉中有两组主要强调色：

**交互蓝**
- 用于发送按钮、底部导航选中态、联网搜索图标、用户消息状态。
- 目测范围：`#0D60FD` ～ `#176DFF`

**品牌 / 操作紫**
- 用于新建会话、编辑图标、部分描边按钮、角色详情主 CTA。
- 目测范围：`#563AF5` ～ `#6B45FF`
- 角色详情主 CTA 是紫色系水平渐变，而不是纯单色。

### 4.5 角色辅助色

**规划教练**
- 弱薰衣草紫 / 冷紫白
- 卡片背景：约 `#F7F5FE`
- 边框：约 `#E7E1FB`

**系统思考者**
- 弱薄荷绿 / 青绿色白
- 卡片背景：约 `#F0FAF6`
- 边框：约 `#CDEDE2`
- 装饰小星光与详情页图标使用绿色系

这些色彩用于**识别角色**，不是阵营颜色。

### 4.6 文字颜色层级

建议按截图建立 4 级：

1. **Primary**
   - 近黑：`#111116` ～ `#17171B`
   - 用于标题、角色名、正文、菜单主文案。
2. **Secondary**
   - 蓝灰：`#72798E` ～ `#7F8599`
   - 用于时间、简介、辅助说明、未选中导航标签。
3. **Tertiary**
   - 更浅灰蓝：`#A0A6B6` 左右
   - 用于弱提示、禁用状态。
4. **Destructive**
   - 红：约 `#FF3B30`
   - 只用于“删除会话”。

### 4.7 卡片

卡片共同特征：

- 白色或极浅色填充
- 细描边
- 大圆角
- 阴影非常弱
- 内边距宽松
- 不使用厚重投影
- 不使用高对比玻璃拟态

### 4.8 毛玻璃

主截图没有明确可验证的强毛玻璃效果。

部分浮层因为下面有 Scrim，会呈现“浮在页面上”的感觉，但主要依赖：

- 半透明黑色遮罩
- 白色 Sheet
- 轻阴影

不要擅自加入明显 Background Blur。

### 4.9 渐变

明确出现的渐变：

- Skill 角色详情的“让 TA 回答这次问题”按钮：蓝紫 / 紫色横向渐变。
- 用户消息气泡可能存在极弱的浅蓝渐变。
- 角色卡可能有极弱的角色色渐变。

这些渐变都应保持低对比，不做高饱和霓虹。

### 4.10 留白与视觉密度

整体属于**中等偏宽松密度**：

- 卡片之间有明显呼吸空间。
- 消息正文行距较舒展。
- 大组件之间通常有 16–24dp 级视觉间距。
- 小型元数据不拥挤。
- 底部操作栏通过细分割线和等分布局保持清爽。

## 5. 页面整体布局

### 5.1 主页面纵向区域

按 1440 × 3200 基准，主体截图可近似划分为：

| 区域 | 估算 Y 范围 | 说明 |
|---|---:|---|
| Android 状态栏 | `0–120` | 系统区域 |
| 顶部导航主行 | `120–310` | 菜单、标题、副标题、右侧操作 |
| Skill 角色区域 | `310–595` | 两个角色卡 + 增加入口 |
| 对话滚动区域 | `595–2650` | 用户消息 + Skill 消息 |
| 联网搜索状态 Chip | `2645–2730` | 位于输入区上方 |
| 输入区 | `2745–2945` | 固定底部编辑器 |
| Bottom Navigation + 系统底部安全区 | `2960–3200` | 一级导航 + Android 手势区 |

以上均为目测范围，实际应以组件视觉匹配为准。

### 5.2 横向边距

主页面通常使用两档水平边距：

- 页面级外边距：约基准 `40–55 px`
- 消息正文卡片因为要给头像留位，左侧内容起点约基准 `225 px`

换成 Compose 后建议先以：

- 页面级 `16–20dp`
- 头像与消息组合区域 `48–56dp` 头像槽位 + `12–16dp` 间距

作为起始实现范围，再在 Xiaomi 14 Ultra 校准。

### 5.3 页面层级

视觉层级从高到低：

1. 系统状态栏
2. 顶部导航
3. Skill 角色条
4. 对话内容
5. 联网搜索状态
6. 输入区
7. 底部一级导航

展开时使用 Overlay：

- Drawer
- Bottom Sheet
- Popover Menu
- Scrim

## 6. 系统状态栏

### 组件：Android 系统状态栏

**用途**  
展示系统时间、网络、信号、电池、中央挖孔。

**位置**  
屏幕顶部，完全由 Android 系统管理。

**背景**  
白色 / 与 App 顶部表面连续。

**颜色**
- 状态图标：黑色
- 电池数字：黑色
- 无品牌色状态栏背景

**中央挖孔**
- 黑色圆形
- 位于屏幕横向中心
- App 内容不得与其重叠

**与 App 顶部内容关系**
- App 顶部导航从系统状态栏安全区下方开始。
- 视觉上没有传统有色 Toolbar 分割。

**开发备注**
- 使用 Edge-to-Edge 可以，但内容必须消费系统 Insets。
- 不绘制自定义状态栏图标。
- 不模拟 iPhone 状态栏。

## 7. 顶部导航栏

### 7.1 顶部导航整体

**用途**  
显示会话身份及会话级操作。

**布局方式**
- 横向布局
- 左：会话列表入口

**背景**

**图标**
- 三条水平线 Hamburger
- 黑色

**位置**

**视觉尺寸**
- 图形本体约 `48–56 px` 基准

**交互**
- 点击打开左侧**会话记录 Drawer**

### 7.3 会话标题

**文案**
- `如何把一个复杂目标拆成可执行计划？`

**位置**
- 左起约基准 `225–230 px`

### 7.5 右侧紫色编辑 / 新建图标

- 紫色描边
- 不带圆形背景

**位置**

**交互意图**

但主体截图本身没有文字标签，因此**具体语义需要产品最终确认**。

### 7.6 更多菜单按钮

**图标**

- 黑色

**位置**

## 10. Skill 角色人格化表达

当前视觉通过以下方式明确传达“用户在和不同的人格化 AI Skill 角色交流”。

### 10.1 人物化头像优先

Skill 角色使用：

- 写实 / 半写实真人感肖像
- 稳定的人脸特征
- 稳定服装与气质
- 角色列表、角色卡、消息头像、详情页保持同一人物

不使用：

- ChatGPT Logo
- Gemini Logo
- 模型厂商 Logo
- 抽象机器人图标作为主要身份

### 10.2 姓名优先于模型信息

主页面只显示：

- 规划教练
- 系统思考者

不展示模型名。

用户首先识别的是“谁在说话”，而不是“哪个模型在输出”。

### 10.3 角色简介

角色卡使用一句稳定能力概括：

- 规划教练：偏目标拆解与行动
- 系统思考者：偏结构、依赖与风险

角色详情进一步拆为：

- 擅长
- 思维特点
- 表达特点

这三项共同形成稳定角色人格，而不是一次性 Prompt 标签。

### 10.4 消息署名

每次 Skill 回复都明确显示：

- 头像
- 姓名
- 时间

视觉接近 IM 群聊成员发言。

### 10.5 弱角色色

每个角色可拥有极弱的识别色：

- 规划教练：薰衣草紫
- 系统思考者：薄荷绿

角色色用于：

- 角色卡背景
- 卡片边框
- 头像外围
- 小型装饰

不使用高饱和大面积填充，因此不会变成“游戏阵营”。

### 10.6 语言人格

截图中的两条回复内容本身形成不同思维路径：

- 规划教练优先拆行动步骤与里程碑
- 系统思考者先补关键约束、反馈闭环与风险

开发层需要保留角色署名与消息独立性，不能把多角色回复合并成一个匿名“大模型答案”。

- 小 Chip：`14–18dp`

## 19. Android / Jetpack Compose 实现注意事项

### 19.1 推荐页面结构

在不改变视觉的前提下，Compose 可按以下层级组织：

```text
Root Box / Scaffold
├── Main Content
│   ├── Top Navigation
│   ├── Skill Role Strip
│   └── Conversation LazyColumn
├── Search Status Chip
├── Composer
├── Bottom Navigation
└── Overlay Layer
    ├── Conversation Drawer
    ├── Bottom Sheets
    └── More Popover
```

这只是实现层级建议，不改变产品结构。

### 19.2 Insets

必须处理：

- `statusBarsPadding()`
- `navigationBarsPadding()`
- `imePadding()`
- `WindowInsets.displayCutout`

不要将 1440 × 3200 像素值硬编码成 Compose 尺寸。

### 19.3 对话列表

建议使用 `LazyColumn`：

- Key 使用稳定 message id
- 不因为流式回复造成整个列表跳动
- 底部增加足够 Content Padding，避免最后一条消息被 Composer 遮挡

### 19.4 消息富文本

至少支持截图已出现的：

- 普通段落
- Bold
- 无序列表
- 编号文本
- 换行

不要将 Markdown 原始符号直接展示给用户。

### 19.5 多角色组件复用

建议建立统一 `SkillRoleVisualIdentity`：

- avatar
- displayName
- shortDescription
- accentColor
- tintBackground
- tintBorder
- optionalDecoration

但该结构只服务视觉识别，不编码“主 / 副 / 正 / 反”。

### 19.6 Sheet

根据截图至少存在 3 类：

1. **Modal Bottom Sheet**
   - 增加 Skill 角色
   - Skill 角色详情
   - `+` 功能
2. **轻模态 / Composer 联动 Sheet**
   - 本次回复角色
3. **非 Sheet 浮层**
   - 会话更多 Popover

不要把所有二级入口统一做成同一种 Sheet。

### 19.7 Drawer

会话记录应从左侧进入：

- 宽约屏幕 65%
- 右侧有 Scrim
- 不替换整个 Activity
- 当前会话列表状态保持

### 19.8 动画

截图是静态图，没有定义动画时长和曲线。

可以使用 Android / Material 的基础进入退出动画作为工程默认，但：

- 不增加夸张弹簧
- 不做角色卡 3D 翻转
- 不做游戏式发光

最终动画规范待补充。

### 19.9 可点击区域

所有视觉上较小的图标必须扩大触控热区：

- Hamburger
- 编辑 / 新建
- 三点
- 关闭
- `@`
- 消息操作
- Sheet Chevron

建议最小 `48dp × 48dp`。

### 19.10 无障碍

在不改变视觉前提下：

- 图标按钮提供 `contentDescription`
- 头像提供角色名语义
- 不能只用颜色表示“已加入 / 已开启”
- 选中本次回复角色同时保留 Check
- 删除操作应有确认机制；确认界面截图未定义

### 19.11 状态管理

UI 状态至少区分：

- 当前会话
- 当前 Skill 角色列表
- 本次回复角色
- 联网搜索开关

**待确认**
- 更多菜单最终是否改为“保存为成果”
- 还是保留“保存 / 整理成果”作为会话级动作

### 21.4 真实人物 Skill 角色的 AI 模拟声明未在当前列表展示

### 21.6 顶部紫色方框笔图标语义

图标视觉类似“新建 / 编辑”。

Drawer 中已有明确的“新建会话”。

- 新建会话
- 编辑当前会话
- 其他会话动作

开发阶段应使用可替换事件，不要把功能语义写死进图标组件。

### 21.7 本次回复角色的范围

截图定义了三个选项：

- 规划教练
- 系统思考者
- 多个角色分别回答

待确认：

- 当会话加入 3 个及以上 Skill 角色时，“多个角色分别回答”是否默认全部角色
- 是否可以多选部分角色
- 是否仍只允许“单角色 / 全部角色”两种模式

当前截图无法判断。

### 21.8 角色详情 CTA 的“这次问题”

截图文案：
- `让 TA 回答这次问题`

待确认“这次问题”是：

- 输入框当前未发送草稿
- 最近一次用户消息
- 当前选中的某条消息
- 打开详情前的上下文问题

### 21.9 顶部 Skill 角色条的扩展方式

- 2 个角色卡
- 1 个增加入口

### 21.10 独立回复与交叉讨论

主体截图中两个角色依次给出观点，但这不等于已经进入“交叉讨论”。
