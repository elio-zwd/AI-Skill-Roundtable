# 使用右侧浏览器图片 AI 生成见域 UI 全套候选图

> 文档状态：全部候选图已生成；用户已下载，文件名分类完成，逐图对应与选型待核对
>
> 适用范围：`docs/product/重构/UI界面/` 下【角色】【资料】【我的】三个系列
>
> 执行方式：由 Codex 控制用户已经登录的右侧浏览器，在 ChatGPT 中逐张生成；用户在全部完成后手动下载

## 1. 目标与边界

2026-09-07 更新：用户已下载 58 个文件，含重复下载及参考图。已仅按文件名分类，见[下载图片分类记录](./候选图片/下载图片分类记录.md)。第 8 节保留生成阶段的队列快照，尚未逐项核对本地图片，因此“已生成待下载”不再代表当前整体下载进度，也不能直接批量改为“已下载”。后续按[UI 重构交接计划](./UI-RECONSTRUCTION-HANDOFF.md)进行选图、规格和实现。

本文规定如何把见域现有页面描述文档交给浏览器图片 AI，生成完整的 Android UI 候选图。

本流程只负责：

- 按“大类”新建并维护独立的图片生成对话；本轮已有的功能系列（角色、资料、我的）各自作为一个大类；
- 按固定顺序上传视觉参考和当前页面描述；
- 一次只请求一张图片；
- 等当前图片生成完成后再请求下一张；
- 在本文记录生成状态和对应对话地址；
- 全部生成完成后通知用户手动下载。

本流程不负责：

- 自动下载浏览器中的图片；
- 把候选图片直接宣布为最终设计；
- 修改 Android UI 代码；
- 根据生成图片反向修改产品定义；
- 在用户审图前自动进行大规模风格迭代。

## 2. 对话划分规则

严格执行“一个大类一个对话”。大类边界优先级如下：

1. 用户或队列明确标注的优先级大类（例如 `P0`、`P1`）优先；从一个优先级切换到另一个优先级时，必须新建 ChatGPT 对话，不能沿用上一类的对话上下文。
2. 没有优先级标注时，按功能系列划分；本轮【角色】【资料】【我的】分别是三个大类，各自使用一个对话。
3. 同一大类内部的页面、组件、选项和状态继续复用该大类对话；不得为了单个子页面另开对话，也不得把不同大类混在一起。

本轮功能系列对话安排：

| 顺序 | 浏览器对话 | 包含范围 | 预计新生成 |
|---|---|---|---:|
| 1 | `见域 UI 出图｜角色系列` | 角色主页面、详情、搜索、Sheet、组件和状态 | 14 张 |
| 2 | `见域 UI 出图｜资料系列` | 资料与成果主页面、详情、编辑、Sheet、组件和状态 | 18 张 |
| 3 | `见域 UI 出图｜我的系列` | 我的主页面、设置类子页面、Sheet、Dialog 和组件 | 18 张 |

三个系列合计需要 51 张视觉稿。其中[我的主页面 B](./我的/参考图片/02-我的主页面-B-个人控制台-选定.png)已经由用户认可，作为固定参考图，不在浏览器中重复生成，因此本轮浏览器队列为 **50 张**。

执行约束：

- 完成一个大类后，必须使用 ChatGPT 的“新建对话”进入下一个大类；本轮即完成【角色】后进入【资料】，完成【资料】后进入【我的】；
- 若后续队列出现 `P0`、`P1` 等新的大类标记，必须在切换标记前新建对话，即使两个标记属于同一个功能系列；
- “新建对话”指新的 ChatGPT 会话，不要求打开新的浏览器窗口或标签页；
- 不得在同一对话中混合两个大类的描述文档；
- 不得并行发送多个出图请求；
- 若单个系列的对话因上下文或页面故障无法继续，不得自行拆分系列，先停止并向用户说明。

## 3. 固定视觉输入

### 3.1 每个系列首次发送的固定附件

新建系列对话后，第一次出图需要同时上传：

1. [共享视觉基线](./共享/jianyu-shared-visual-baseline.md)；
2. [图片输出规则](./共享/jianyu-image-generation-output-rules.md)；
3. [对话页最终 UI 规格](./对话/jianyu-dialog-final-ui-spec.md)；
4. [对话页面主参考图](./对话/ChatGPT%20Image%202026年8月27日%2009_04_44.png)；
5. [已认可的我的主页面 B](./我的/参考图片/02-我的主页面-B-个人控制台-选定.png)；
6. 当前系列的 `00-界面出图索引.md`；
7. 当前准备生成的第一份页面描述文档。

三个系列索引分别是：

- [角色界面出图索引](./角色/00-角色界面出图索引.md)；
- [资料界面出图索引](./资料/00-资料界面出图索引.md)；
- [我的界面出图索引](./我的/00-我的界面出图索引.md)。

浏览器图片 AI 无法通过本机路径自行读取文件，因此必须上传真实附件，不能只把 `D:\...` 路径写入消息。

### 3.2 系列内后续图片的输入

同一系列的第二张及后续图片只新增上传：

- 当前要生成的单份页面描述文档。

共享基线、输出规则、对话参考图和我的参考图沿用该对话开场附件，不重复上传。若浏览器 AI 明确表示无法继续读取早期附件，停止执行并向用户说明，不擅自改变系列划分。

### 3.3 参考图职责

- 【对话】主参考图：锁定见域的人物化气质、蓝紫色、卡片、图标和 Android 页面外壳；
- 已认可【我的】主页面 B：锁定四项新导航、页面密度、标题、Hero 和设置卡片语言；
- 同一系列此前生成的图片：只帮助保持角色外貌和局部组件一致，不代表此前方案已经被选中；
- 当前页面描述：决定本次图片的业务结构、文案、状态和禁止项，优先级高于参考图中的业务内容。

【角色】A 的现有 v2 图片只是本流程的验证样图，不自动视为最终选定方向。【我的】B 是目前唯一正式认可的主页面视觉参考。

## 4. 浏览器自动化执行规则

### 4.1 允许操作的范围

Codex 只操作用户已经打开并登录的右侧 ChatGPT 浏览器页面。用户已经授权本流程上传以下内容到该页面：

- 本目录中的 UI 描述 Markdown；
- 共享视觉规范 Markdown；
- 见域 UI 参考图片。

不得上传仓库中的代码、密钥、配置、日志、个人资料或与 UI 出图无关的文件。

### 4.2 每张图片的浏览器动作

1. 确认当前浏览器对话属于正确系列；
2. 确认上一张图片已经完成生成，不再显示生成中或停止按钮；
3. 上传当前页面描述文档；
4. 在输入框发送本流程规定的提示词；
5. 等待图片生成完成；
6. 核对回复中确实存在一张完整图片，而不是纯文字解释；
7. 在第 8 节队列表中把该项更新为 `已生成待下载`；
8. 再进入下一项。

不得因为页面响应慢而重复发送相同请求。若发送结果不确定，先重新读取当前对话，确认是否已经出现请求或生成任务。

### 4.3 无需确认与必须停止的情况

在用户本次授权范围内，上传上述 UI 文档和参考图、发送出图提示、建立新的系列对话均无需逐张再次确认。

出现以下情况必须停止，保留已经完成的结果并通知用户：

- 登录失效或要求重新认证；
- CAPTCHA、人机验证或安全拦截；
- 图片额度、频率限制或模型不可用；
- 页面要求升级、购买或确认付费；
- 附件上传失败且重试一次仍失败；
- 当前请求是否已经发送无法判断；
- ChatGPT 返回安全拒绝，需要改变产品内容；
- 对话上下文过长，无法继续读取开场附件。

不得读取或操作用户其他 ChatGPT 对话，不查看密码、Cookie、浏览历史或浏览器存储。

## 5. 系列第一张图片的统一提示词

每个新系列的第一条消息在上传第 3.1 节全部附件后发送：

```text
请根据我上传的共享视觉基线、图片输出规则、对话页规格、两张视觉参考图、当前系列索引和当前页面描述，生成当前描述对应的一张完整 Android UI 图片。

输入职责：
1. 共享视觉基线定义见域已经确定的颜色、字体、圆角、卡片、图标、Android 系统区域和人物化气质，必须继承。
2. 图片输出规则定义尺寸、中文、文件范围和禁止混搭要求，必须遵守。
3. 对话页规格与对话参考图用于保持同一产品感，但不要复制对话页的聊天业务结构。
4. 已认可的“我的”页面用于锁定四项新底部导航和整体页面密度。
5. 当前系列索引用于理解本系列边界。
6. 当前页面描述决定本次唯一页面的业务结构、文案、状态和禁止项，优先级最高。

输出要求：
- 本次只生成当前页面描述对应的一张独立图片。
- 画布目标为 1440 × 3200，Xiaomi 14 Ultra 比例，Android 竖屏，浅色模式。
- 使用简体中文，标题、按钮、标签和关键状态必须尽量准确、清晰、可读。
- 保持高保真、可实现的原生 Android 产品界面，不生成线框图、概念艺术、营销海报或手机展示模型。
- 底部一级导航统一为“对话 / 角色 / 资料 / 我的”，并正确高亮当前页面；二级页面按描述决定是否显示底部导航。
- 资料和成果必须保持对象区别；Skill 角色必须人物化、平级，不生成主角色、队长、正方或反方。
- 不生成 iPhone 灵动岛、iOS 状态栏或 iOS Home Indicator。
- 不把多个候选、状态或页面拼进一张图；状态组或页面组也按我当前指定的单个子项逐张生成。
- 不增加描述文档之外的核心功能。
- 如果输入冲突：业务结构以当前页面描述为准，视觉风格以共享视觉基线和两张参考图为准。

请直接生成图片，不要先解释设计思路，也不要在图片外增加方案说明。
```

## 6. 系列内后续图片的统一提示词

上传当前页面描述后发送：

```text
继续生成本系列的下一张图片。请读取本对话开场的共享视觉基线、输出规则和参考图，并以本次新上传的页面描述作为业务结构与文案的唯一依据。

要求：
- 本次只生成这一份描述对应的一张独立 Android UI 图片。
- 延续本系列已经建立的颜色、圆角、字体、图标、间距、人物头像和页面外壳。
- 目标画布为 1440 × 3200，Xiaomi 14 Ultra 比例，Android 竖屏，简体中文，浅色模式。
- 关键中文尽量准确可读。
- 当前描述的结构、状态和禁止项优先，不混入同系列其他 A/B/C 候选。
- 不生成设备外框、说明板、对比拼图、营销海报或 iOS 专属元素。
- 直接生成图片，不需要解释。
```

## 7. 页面组、状态组和 Dialog 组的逐张提示

同一 Markdown 要求多张图片时，每一次都重新上传同一份描述文档，并在第 6 节提示词末尾追加：

```text
本次只生成：【在这里填写当前子页面或状态的准确名称】。
不要同时生成该文档中的其他状态；未指定部分保持与本系列既有视觉一致。
```

例如：

```text
本次只生成：【状态二｜收藏为空】。
不要同时生成正常内容、搜索无结果或加载失败状态。
```

Bottom Sheet 和 Dialog 必须放在描述指定的真实页面背景上，并显示遮罩；不得只输出一张脱离页面上下文的白色浮层组件。

## 9. 单张图片验收

每张图片生成后只做快速验收，不在批量阶段反复打磨：

1. 回复中确实包含一张图片；
2. 只出现当前要求的一个页面、状态、Sheet 或 Dialog；
3. 整体仍像同一款见域 App；
4. 是 Android 竖屏，不是 iPhone 或桌面页面；
5. 四项底部导航为“对话 / 角色 / 资料 / 我的”，且仅在描述要求时出现；
6. 当前一级页面高亮正确；
7. 关键中文标题、按钮和状态基本可读；
8. 页面主体、组件顺序和打开状态符合当前描述；
9. Skill 角色保持人物化和平级，没有 Agent 市场、排行榜或主从标识；
10. 资料、成果、个人背景之间没有混淆；
11. 没有完整 API Key、内部错误堆栈或绝对安全承诺；
12. 没有设备外框、设计说明、标注线或多图拼接。

以下轻微问题不阻塞继续生成，只在状态中记为 `需重做`，待用户集中审图后处理：

- 次要中文错字；
- 人物头像与另一页存在轻微差异；
- 间距、圆角或弱色存在小幅偏差；
- 非核心说明文字换行不理想。

以下问题允许立即原地重试一次：

- 没有生成图片，只输出文字；
- 生成了桌面页、iPhone 页、海报或手机外壳；
- 把多个页面或多个状态拼在一张图里；
- 当前页面类型完全错误；
- 图片明显截断，无法看见主要内容。

立即重试时只指出一个失败主题，并重申其余结构不变。重试一次仍失败则标记 `需重做`，继续队列，不进行无限修图。

## 10. 批量阶段的迭代规则

本轮目标是先得到完整候选集，因此：

- 不因为个人审美自动要求第二版；
- 不在 A 图生成后替用户选择 A/B/C；
- 不因后一张更漂亮而回头自动重做前面的所有图片；
- 不覆盖浏览器中已经生成的结果；
- 修订必须使用新版本号 `v2`、`v3`；
- 用户完成第一轮集中审图后，再按“一次只修改一个主题”定向迭代。

定向修改示例：

```text
保持页面结构、文案、颜色、圆角和所有其他区域不变，只把“规划教练”和“系统思考者”的头像改为与对话参考图完全一致。
```

## 11. 用户手动下载规则

全部生成完成后，Codex只汇报：

- 三个系列各生成了多少张；
- 每个系列的 ChatGPT 对话地址；
- 哪些图片标记为 `需重做`；
- 哪些图片已经存在、不需要下载。

用户随后进入三个对话逐张下载。建议保存目录：

```text
docs/product/重构/UI界面/
├─ 角色/浏览器出图/
├─ 资料/浏览器出图/
└─ 我的/浏览器出图/
```

下载时采用第 8 节给出的文件名。浏览器自动附加 `(1)`、`(2)` 等后缀时，下载完成后再按建议名称整理。不得覆盖旧版；同一页面的新版本递增 `v2`、`v3`。

## 12. 中断、恢复与防重复

中断后恢复时：

1. 先读取本文第 8 节状态；
2. 打开对应系列已经记录的 ChatGPT 对话；
3. 检查对话最后一条请求和最后一张图片；
4. 若最后一项已经完成但文档未更新，先补记为 `已生成待下载`；
5. 从第一项 `待生成` 继续；
6. 不重新生成 `已生成待下载`、`已下载`或`跳过-已有选定图`的项目。

若无法判断上一条请求是否成功，不发送重复请求，先停下来向用户说明当前对话和队列位置。

## 13. 全部完成的判定

只有满足以下条件，才可以报告“浏览器出图完成”：

- 【角色】14 项均为 `已生成待下载`、`已下载`或经用户确认的`需重做`；
- 【资料】18 项均为上述完成状态；
- 【我的】18 个待生成项均为上述完成状态，主页面 B 保持`跳过-已有选定图`；
- 三个对话地址已经记录；
- 浏览器中没有仍在生成的图片；
- 没有重复发送或混入其他系列；
- 用户已被明确告知下一步是手动下载和集中审图。

完成生成不代表图片已经下载，也不代表设计已经定稿。
